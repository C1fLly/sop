# 3-03 机器级配置和工具清单

2026-11-19。没调用 AI、没花钱，没开虚拟机，没动这台电脑的环境（本机只读地跑了一遍检查命令）。

## 做了什么

- **`machine/tools.toml`：基础工具的唯一清单**（设计书 4.4）。12 样：git、curl、uv、bubblewrap、uidmap、dbus-user-session、nvm、Node、pnpm、gh、免管理员 Docker、wt。每样写：一句大白话说干什么的、最低版本、装在哪（`~/tools/…` 或「系统软件包」）、检查命令、谁来装（`apt:软件包` 或 `script:安装脚本`）、要不要管理员密码、哪一步装（M0、M2、M5）、要先装好哪几样。
- **`machine/catalog.py`：读清单**。清单写错了读的时候就报，说清是第几项哪个字段：少字段、类型不对、多出不认识的字段、名字重复、版本写法不对、步骤不对、apt 装的却说不要管理员密码或位置不写「系统软件包」、工具包自己装的不在 `~/tools` 下、安装脚本路径跑出 `machine/`、要先装的那样排在后面。另有比版本（按数比，`1.9.99` 小于 `1.10`；系统软件包版本前面的「1:」跳过）和跑检查命令（不改任何东西；超时连它带起的子进程一起结束）。
- **`machine/config.py`：`~/tools/sop/config/` 下三份登记的读写**（3.2、4.3、4.4、4.5）：
  - `network.json` 网络设置：代理（三项）、三种软件源、从哪来（探测到的或小白填的）。只认这几项，代理和网址的写法不对直接报错、一个字都不写；另给安装脚本拼代理的环境变量（大小写两套）。
  - `tools.json` 工具实际位置：在哪、版本、是不是规定位置那一份、另有几份在哪（占多大、在不在系统盘，给 3-06 的「另有一份不在规定位置」用）。AI 工具也记在这里（种类 `ai`），可以带「最近一次做过真实演练的版本」（10.1）。
  - `system.json` 系统组件版本：内核、bubblewrap、免管理员 Docker 那条系统规则、往终端塞按键的开关四样；另给一个「和登记比，哪几样变了」的函数，给 3-07 用。
  - 规矩：目录只有用户自己能进、文件只有用户自己能读（代理里可能带账号密码）；读改写先上锁；先写临时文件再换名，写一半断了不留坏文件；文件坏了明说是哪个文件，不当成空的接着用。
- **`sop machine` 入口**：在 `kernel/cli.py` 里排在「找项目」之前，所以不在项目里也能用。现在只有 `sop machine tools`（大白话列出清单）；`doctor`、`setup`、`migrate`、`clean` 如实说还没做、在哪个任务做。
- `kernel/paths.py` 加 `tools_dir()`：平常是 `~/tools`（工具包根目录的上一层），自测用 `SOP_TOOLS_DIR` 换掉。
- README 的目录表补了 `machine/` 一行，阶段那句改成第三段。

## 结果

- 新加单元测试 `tests/unit/test_machine_config.py` 15 项，全部通过。含：真清单能读、每样的规矩都对；一份好样例、十种坏样例都报得出；版本比较；检查命令「没装、装了版本不够、够了、超时」四种；三份登记的读写、坏写法不落盘、文件权限 0700/0600、没有临时文件残留、文件坏了报出文件名；4 个进程同时各登记 15 样，60 样一样不丢；`sop machine` 在不是项目的目录里能用、只看不写登记。
- 全部自测：做之前单元测试 39 项、流程沙箱 22 个剧本、总检查 62 个样例全过；做之后单元测试 54 项（多了这 15 项）、其余一样，全部通过。
- 本机只读跑了一遍清单的检查命令（`SOP_HOME` 指到 `/tmp` 下一个不存在的目录，跑完确认没建出任何文件）：git 2.53.0、curl 8.18.0、bubblewrap 0.11.1、uidmap、dbus-user-session、wt 1.3.1 在且版本够；uv、nvm、Node、pnpm、gh、Docker 不在 `~/tools` 下（这台电脑按用户的要求还没用 SOP 初始化，用户自己的 uv、Docker 在别处），和实际相符。

- 安装脚本一个都没写：清单里写的 `install/uv.sh`、`nvm.sh`、`node.sh`、`pnpm.sh`、`gh.sh` 由 3-08 写，`docker-rootless.sh` 由 3-09 写，`wt.sh` 由 3-22 写。现在这些文件不存在，测试只查路径写法。
- 版本下限是按第一段、第二段实际用过的版本定的（git 2.42 是 wt 脚本里要求的；uv 0.13、Node 24、pnpm 12、Docker 29、gh 2.60、wt 1.3），3-08、3-09、3-22 真装时再核对。pnpm 定 12 是因为 W36 只在 12 上试过 `pnpm_config_` 开头的变量。
- 「环境迁移中停掉的容器的记录」（4.3 列在 `config/` 下）不在这次的三份里，3-31 写迁移时加。
- 网络设置里「GitHub、AI 服务、软件源连不连得上」的检查是体检的事（3-06、3-13）。
- 体检、安装本身（3-04 到 3-06、3-12）。

## 和设计书的出入（留给 3-48 并入）

- **gh 装在哪，设计书 4.3 的表里没写。** 照「SOP 用到的一切都装在 `tools` 目录下」，清单里定成 `~/tools/gh`（官方发布的压缩包，不用管理员密码，在 M2 装）。3-08 写安装脚本时核实。
- 三份登记的文件名定成 `network.json`（设计书原有）、`tools.json`、`system.json`。
- 多了一条命令 `sop machine tools`（列出基础工具），8.5 的命令表里没有。
- 清单多了三个字段：`what`（一句大白话）、`step`（哪一步装）、`needs`（先装哪几样），4.4 只列了六个字段。

## 自己出的错

- 第一次本机只读核对时，uidmap 的版本显示成「1」：系统软件包的版本是「1:4.x」这种带前缀的写法，取版本号时取到了前缀。改成跳过前缀，补了一条测试。不影响结论（这两样只要装了就行，不看版本）。
- 检查命令超时那条，起初直接用 `subprocess.run` 的超时；命令自己再带起子进程时，管道一直不关、会白等。改成整组结束，测试里专门造了一个「后台还挂着一个子进程」的情况。
