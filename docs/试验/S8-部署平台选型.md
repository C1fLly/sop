# 试验 S8：部署平台选型

**用户看过结果后的决定（2026-11-17）**：Java 那套后端可以改用 PostgreSQL，所以纸面首选是 Render；部署相关流程的开发暂缓，注册和实测也跟着往后放。

状态：纸面比较已完成（2026-11-17）。按用户的要求，**只读官方文档，没有注册账号，没有绑付款方式，没有登录，没有调用任何平台的接口，没有部署任何东西**。实测等用户回来定。没做的部分列在末尾。

没有调用需要付费的 AI 工具，没有花钱。

## 要验证什么

设计书第 19 节：在候选的海外托管平台里选一家，核实 11.5 列出的各项：

1. 是否同时提供托管的 MySQL 和 PostgreSQL。
2. 能否用脚本完成部署和回退。
3. 备份和告警由谁做。
4. 付款方式。
5. 费用。

候选是 Railway、Render、Fly.io。

## 怎么做的

- 三家的官方文档都提供纯文字版本（网址后面加 `.md`）。把相关页面下载下来逐页读，共 160 多个文件。引文是逐字原文。
- 少数页面（状态页、个别指南）只经网页摘要工具读到，下面标了「经摘要」。
- 读完后我又从下载的原文里抽查了 20 来条关键引文（付款方式、有没有托管 MySQL、备份、告警、回退、价格），都对得上。
- 凡是没读到官方原文的，下面都写「没核实」。

## 结果

### 第 1 项：托管的数据库

「托管」有程度之分，三家差别很大：

| | PostgreSQL | MySQL |
|---|---|---|
| Railway | 有。平台提供并维护一份模板，负责开通和打安全补丁。**备份、按时间点恢复、高可用都要用户自己去打开**，默认不开 | 有，和 PostgreSQL 同样的方式 |
| Render | 有，全托管。付费的数据库默认持续备份 | **没有。** 只能自己跑一个 MySQL 容器加一块磁盘，运维全是自己的事 |
| Fly.io | 有，全托管（它叫 Managed Postgres），自带备份和高可用。旧的那一种已经停止维护 | **没有。** 只能自己跑 |

依据（原文）：

- Railway：「Railway maintains its PostgreSQL, MySQL, Redis and MongoDB templates: it provisions them and ships security patches for their images.」责任表里写着：备份和按时间点恢复是「User turns them on」，高可用是「User turns it on」。它还说：「alerting on them is yours to set up, and Railway does not publish an uptime SLA today.」
- Render：「Render offers managed Postgres databases」；别的数据库是「You can also run your own custom database instance (MariaDB, MongoDB, etc.) backed by a persistent disk.」对自己跑的 MySQL，官方明说磁盘快照不宜用来恢复数据库：「Relying on a disk snapshot to restore a database is not recommended. Restoring a disk snapshot will likely result in corrupted or lost database data.」
- Fly.io：「Fly.io's Managed Postgres is our fully-managed database service」；旧的一种：「Fly Postgres (unmanaged) is no longer maintained」；MySQL：「If you just want to run a quick, self-managed MySQL instance on Fly.io, here's how to do it.」

**结论：没有一家同时提供「全托管」的 MySQL 和 PostgreSQL。** 只有 Railway 两样都有，但它是半托管：备份和高可用要自己开，告警自己配。

### 第 2 项：用脚本部署和回退

| | 用脚本部署 | 令牌能限定到多小 | 用脚本回退 | 回退带不带配置 |
|---|---|---|---|---|
| Railway | 能。命令行工具加项目令牌 | 一个项目里的一个环境 | 命令行工具没有回退命令；接口文档里有回退操作。官方两处说法有出入 | 带。镜像和变量一起回退 |
| Render | 能。命令行工具加密钥；官方给了在 GitHub 上自动部署的例子 | 整个工作区，限不到单个环境 | 能，调接口。命令行工具没有回退命令 | 带。环境变量、启动命令一起回退；磁盘不回退 |
| Fly.io | 能。命令行工具；官方给了在 GitHub 上自动部署的做法 | 单个应用 | 能，用命令行重新部署旧镜像 | **不带。** 只回退镜像，配置和密钥还是现在的 |

依据（原文）：

- Railway：「For automated deployments, use a Project Token instead of interactive login. Project tokens are scoped to a specific environment and can only perform deployment-related actions.」回退：「Both the Docker image and custom variables are restored during the rollback process.」但另一页说：「The dashboard is the only place to roll back to an arbitrary older deployment.」而接口文档里又有回退操作，并注明只能回退到标着可回退的那些版本。项目令牌能不能调用这个操作，没核实。回退有时间窗口：免费 24 小时、Hobby 套餐 72 小时、Pro 套餐 120 小时，过期只能重新构建。
- Render：「The Render CLI can authenticate using an API key instead of `render login`.」回退：「To trigger a rollback via the Render API, use the Roll back deploy endpoint.」能回退的版本数：Hobby 套餐保留 5 个，Pro 套餐 15 个。
- Fly.io：「There's no special `rollback` command because you don't need one.」「Rollbacks don't undo config changes.」「Right now, Fly doesn't promise to store app images forever.」

**结论：三家都能用脚本部署。回退 Render 和 Fly.io 有写明的脚本做法；Railway 的说法有出入，要实测。**

### 第 3 项：备份和告警由谁做

备份：

| | 自动备份 | 保留多久 | 能否恢复成一个新实例（恢复演练要用） |
|---|---|---|---|
| Railway | 用户自己开，默认不开。「Backups are a newer feature that is still under development.」 | 每日的留 6 天，每周的留 27 天；按时间点恢复：PostgreSQL 约 4 周，MySQL 7 天 | 按时间点恢复可以，恢复成一个新的服务，原来的不动 |
| Render | 付费的 PostgreSQL 默认就有，平台做 | Hobby 套餐 3 天，Pro 套餐 7 天 | 可以，恢复成新实例。文档正文只写了网页操作；接口目录里有对应条目，细节没核实 |
| Fly.io | 托管的 PostgreSQL 默认就有，平台做 | 10 天 | 可以，有命令行命令 |

告警：

| | 自带的告警 | 发到哪 | 服务挂了会不会自己重启 |
|---|---|---|---|
| Railway | 部署失败、服务崩溃；用量和费用上限 | 邮件，另可发到一个网址（Slack、Discord 可接） | 崩溃后自动重启最多 10 次。**但健康检查只在部署时做，上线后不再查**：「Railway does not monitor the healthcheck endpoint after the deployment has gone live.」 |
| Render | 构建或部署失败、定时任务失败、服务不健康、磁盘超过 80% | 邮件、Slack | **会。持续查健康，不健康满 60 秒自动重启**：「If an instance fails consecutive health checks for 60 seconds, Render automatically restarts the instance.」 |
| Fly.io | **没有。**「Fly.io doesn't include built-in alerting on metrics」「We don't support billing alerts (yet)」 | — | 进程退出会按策略重启；健康检查不通过不会重启 |

**结论：备份 Render 和 Fly.io 是平台默认做，Railway 要用户自己开。告警 Render 最全，Fly.io 没有。**

### 第 4 项：付款方式

| | 官方写明接受的 | 要不要先绑卡 | 免费或试用 |
|---|---|---|---|
| Railway | **只收信用卡**，不能预付：「Railway only accepts credit cards for plan subscriptions.」「Railway requires the use of a post-paid card.」 | 试用不用 | 一次性 5 美元、30 天。完整试用还是受限试用，取决于 GitHub 账号能不能通过它的自动验证，官方不受理人工申请 |
| Render | **信用卡和借记卡都收**：「We accept all major credit and debit cards.」经 Stripe 处理。绑卡时扣 1 美元验证，随后退回 | 免费的服务不用 | 有免费的服务；免费的数据库 30 天过期、没有备份，不能当预发用 |
| Fly.io | 信用卡；**没有信用卡可以预购额度**，最低 25 美元。预付卡不能存为默认卡，但可以用来买额度 | 多数功能要 | 1 美元、7 天，试用的机器跑 5 分钟自动停 |

**对中国大陆发行的卡（银联、国内的双币卡），以及对大陆用户的限制：三家的官方文档都没有说明。** 读到的定价、计费、试用页面里没有出现 China、UnionPay、Alipay，也没有按国家的限制。PayPal 三家都没提。Railway 和 Render 的服务条款正文没读到（页面只返回了标题），**没核实**。

**结论：纸面上 Render 的说法最宽（明写收借记卡），Fly.io 有不用信用卡的路（预购额度），Railway 最窄。用户手里的卡到底能不能用，纸面上定不了，只有注册后绑卡才知道。**

### 第 5 项：费用

口径：一个后端加一个数据库，预发和生产各一套，一直开着，不算流量。**都是估算，不是报价。**

| | 每月大约 | 怎么算的 |
|---|---|---|
| Render，Node 加 PostgreSQL | 27 美元 | 后端最小的一档 7 美元 × 2；数据库最小的一档 6 美元加 1GB 存储 0.3 美元，× 2。套餐本身 0 美元 |
| Render，Java 加 PostgreSQL | 63 美元 | Java 在 512MB 内存里多半不够，后端换 2GB 的一档 25 美元 × 2，数据库同上。「Java 多半不够」是我的判断，没有实测 |
| Railway | 30 到 50 美元 | 按用量算：内存每 GB 每月 10 美元，处理器每核每月 20 美元，存储每 GB 0.15 美元。用量是我假设的。官方自己说给不出准数：「We are unable to give exact quotes or estimates」 |
| Fly.io | 84 到 90 美元 | 大头是托管的 PostgreSQL，最小的一档每月 38 美元 × 2；后端最小的一档 3.69 美元 × 2。新加坡机房的计算价格要再乘 1.27 |

前端（Vue）在 Render 上可以作为静态网站免费托管。

## 结论

1. **设计书 11.5 假定的「一家平台同时提供托管的 MySQL 和 PostgreSQL」，纸面上不成立。** 全托管的 MySQL 三家都没有；Railway 有半托管的。
2. **所以选哪家，取决于一个要由用户定的问题：Java 那套后端一定要用 MySQL 吗？** 设计书 11.5 里 MySQL 只是候选，不是用户定下的。
   - **如果 Java 那套可以改用 PostgreSQL：纸面首选 Render。** 理由：数据库的备份和恢复由平台默认做，不用记得去开；服务不健康会自己重启，告警发邮件，开箱就有；费用固定且最低；收借记卡；部署有官方的自动化例子，回退有写明的接口并且带着配置一起回退。
     - Render 的短板：回退要调接口，不是一条命令；密钥是整个工作区通用的，限不到「只能动预发」；最便宜的套餐只能恢复到 3 天内；往网址发告警要 Pro 套餐（每月另加 25 美元）。
   - **如果 MySQL 一定要托管：只能选 Railway。** 要接受：备份、高可用要自己开，告警自己配；上线后不查健康；只收信用卡；回退的脚本做法要实测；费用随用量浮动。
   - Fly.io 两种情况下都不占优：贵三倍左右，没有自带的告警和定时任务，回退不带配置。它唯一的强项是恢复演练全程命令行、没有信用卡也能付款。
3. **付款这一项纸面上定不了。** 三家都没有写对大陆的卡怎么样。
4. **「部署、回退、备份并恢复到新实例、告警送达」这几样设计书 7.7 的 R3 要实际演练的东西，Render 在纸面上都有对应的做法**，其中「用接口触发按时间点恢复」的细节没核实。

设计书没有改成「选定 Render」：选哪家要等用户回答上面那个问题，并且实测过付款才算数。11.5 里记下了纸面结论。

## 纸面上定不了、要注册后实测才知道的

1. 用户手里的卡能不能在这三家绑上、扣款成功。
2. 走代理的情况下，三家的网页、命令行登录、推送镜像稳不稳。
3. 平台给的默认网址，以及绑了自己的域名之后，从大陆直接访问通不通、慢不慢。
4. Render：限定权限的密钥对新账号开放了没有；按时间点恢复的接口怎么调；回退实际要多久。
5. Railway：GitHub 账号能不能通过它的自动验证；项目令牌能不能调用回退；可回退的实际时间窗口；MySQL 的按时间点恢复能不能用命令行做；最便宜的套餐有没有备份功能。
6. Fly.io：按时间点恢复能回到多久以前；亚洲机房的托管数据库是不是列表上的价格；镜像实际保留多久。
7. Spring Boot 在最小规格下够不够用，这决定 Java 那套的真实月费。
8. Railway 按用量计费，实际账单是多少。
9. 恢复演练全程要多久，恢复出来的新实例怎么切换过去。
10. 告警邮件会不会进垃圾箱；Slack 在大陆能不能用。
11. Railway 和 Render 的服务条款正文里有没有地区限制，要在浏览器里人工打开读。

## 没做的
