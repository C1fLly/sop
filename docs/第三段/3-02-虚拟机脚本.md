# 3-02 虚拟机脚本：按名字现建、一键还原

2026-11-19。新加 `tests/vm/vm.sh`（虚拟机脚本）和 `tests/vm/selftest.sh`（它的自测）。没用 sudo，没花钱，没动第一段的 vm-a、vm-b。

## 做了什么

- **底盘加覆盖层。** 每种「分区样子」先做一次底盘：从云镜像（`~/sop-vm/images/` 里第一段下好的 Ubuntu 26.04 服务器版）起一次，首次初始化（建账号 `xiaobai`、免密码 sudo、装登录钥匙、写本机代理设置、apt 用国内源）做完，然后关掉首次初始化（以后的各台不再跑）、清空机器编号（各台第一次开机自己重新生成）、关机，磁盘文件设成只读。按名字建的每台虚拟机只是底盘上面的一层覆盖层；新建、还原都是把这层删了重建。
- 两种底盘：`one`（只有一个分区）、`home`（主目录单独一块盘，和第一段 vm-a 的造法一样）。底盘第一次用到时自动做。
- `--extra 10G` 另加一块空白盘，留给 3-37 造「加密加逻辑卷」「btrfs 子卷」用。
- 命令：`new`、`start`、`stop`、`reset`（还原成全新，要先关）、`rm`、`ssh`、`push`（拷文件进去）、`list`、`base`（重做底盘）。每台的登录端口从 2240 起自动分配，记在 `~/sop-vm/vms/<名字>/conf`；开机后主机名改成 `sop-vm-<名字>`。
- 名字 `a`、`b` 不许用，那两台仍由第一段的脚本管。
- 放在 `tests/vm/`，不进 `run_all.py`（那里不开虚拟机）。README 的目录表补了一句。

全部自测（`run_all.py`）前后一样：单元测试 39 项、流程沙箱 22 个剧本、总检查 62 个样例，全部通过。

留在本机的：`~/sop-vm/bases/`（两个底盘，共约 106 MB，因为只记和云镜像不同的部分）。自测建的虚拟机都删了，没有开着的虚拟机，临时的小网页服务也停了。

## 没做的

- 一台一台开没有内存检查：每台默认 4 GB，这台电脑 30 GB，同时开四五台以内没问题；要更多用 `--mem`。
- 各台的 SSH 主机钥匙相同（都从底盘来），只是验证用，不影响。
- 底盘里的系统是做底盘那天的样子，以后不自动更新；要新的就 `vm.sh base one`（要先删掉用它的虚拟机）。
- 3-36 的桌面版虚拟机不走这个脚本（要用安装程序装），到时候另做。

## 自己出的错

- 第一次跑自测，把给 QEMU 的额外参数（`-smbios` 后面那一串）也当成磁盘文件了，QEMU 报错退出。改成用 `--` 把磁盘和额外参数分开。半截的底盘目录删了重做，没有留下东西。
- 开了两个盯日志的监视，第一个盯的是被第二次运行覆盖的同一个文件，报出了上一次的 `exit=1`，看着像第二次失败了；停掉了旧的那个。
