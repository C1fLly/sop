# 第一段 W36：nvm、uv 装进 `~/tools`；体检看主目录在哪个分区

状态：已完成（2026-11-18）。在两台虚拟机上把 nvm、uv 装到 `~/tools` 下，Node、pnpm、Python、靠 Node 运行的命令都正常；改了 pnpm 的几个位置之后，除了 uv 安装时留的一个几百字节的小文件，没有东西写到 `~/tools` 和 `~/Project` 之外。体检的「主目录在哪个分区」三种情况都判对了。

没有调用 AI，没有花钱。都在虚拟机里做，没有动这台电脑（只在这台电脑上只读地跑了一次分区检查）。脚本在 `docs/试验/脚本/第一段/W36/`。

## 虚拟机

两台 Ubuntu 26.04.1 虚拟机，用官方的云镜像加自动配置建的（见 `第一段-虚拟机.md`）：

- vm-a：主目录单独一块盘（`/home` 在 `vdb1` 上），模拟「装系统时把主目录单独分一个区」，和这台电脑一样。
- vm-b：只有一个系统分区（另有系统自带的 `/boot`、`/boot/efi`）。

## 结果

### nvm、uv 装进 `~/tools`

终端启动文件里由工具包管理的一段（设计书 4.3 说的「几行设置」）指向 `~/tools`；nvm 和 uv 用官方的安装脚本、指定装到 `~/tools/nvm`、`~/tools/uv`，并告诉它们不要再改启动文件。两台结果一样：

| 东西 | 结果 |
|---|---|
| Node | v26.13.1（当前的长期支持版），在 `~/tools/nvm/versions/node/` 下 |
| pnpm | 12.21.0，装在 nvm 的 Node 下面 |
| uv | 0.13.9，在 `~/tools/uv/bin` |
| Python | 3.13.18，在 `~/tools/uv/python/` 下 |
| pnpm 装一个依赖并能用 | 正常，包仓库在 `~/tools/cache/pnpm-store` |
| 一个靠 Node 运行、装在别处的命令（模拟 Pi：开头写着「用终端里的 node 运行」） | 正常 |
| 占的空间 | nvm 334 MB，uv（含一份 Python）142 MB，缓存 37 MB |

**第一次装完，有 5 个文件写到了 `~/tools` 之外：** pnpm 的设置文件（`~/.config/pnpm/config.yaml`）、pnpm 的元数据缓存（`~/.cache/pnpm/`，会越用越大）、pnpm 的状态文件（`~/.local/state/pnpm/`），以及 uv 安装时留的一个记录文件（`~/.config/uv/uv-receipt.json`）。

原因和改法：

- 第一次用 `pnpm config set` 设包仓库的位置，它就把设置写进了 `~/.config/pnpm`；pnpm 的缓存和状态默认放在 `~/.cache`、`~/.local/state`。
- 改成在那段启动设置里用环境变量指定。**pnpm 12 只认 `pnpm_config_` 开头的变量**，`npm_config_` 开头的它不认（试了，不认，包仓库跑到了 `/tmp` 下）。用 `pnpm_config_store_dir`、`pnpm_config_cache_dir`、`pnpm_config_state_dir` 指到 `~/tools/cache/` 下之后，再装依赖，`~/tools` 和 `~/Project` 之外一个新文件都没有。
- uv 的那个记录文件只在安装时写一次，几百字节，给 uv 以后自己升级用。列进设计书 4.3「在主目录下、不在 `tools` 里」的小文件里。

### 体检：主目录在哪个分区

试验原型 `主目录在哪个分区.sh`，只读，照设计书 4.3 的表判断。「能用的 Linux 分区」只算真盘上 Linux 格式的分区，不算系统自己在用的（`/`、`/boot`、`/boot/efi`、交换区）。

| 在哪试 | 情况 | 判的结论 |
|---|---|---|
| vm-a | 主目录在 `vdb1`，系统在 `vda1` | 第一种：合格，主目录不在系统盘上 |
| vm-b | 主目录和系统都在 `vda1`；另有系统自带的 `/boot`（也是 Linux 格式） | 第二种：合格，只有一个能用的分区。`/boot` 正确地没算进去 |
| vm-b 临时接一块新盘，分区、格式化成 ext4，不挂上 | 主目录在系统盘上，另有一个没用上的分区 | 第三种：合格，照常装在主目录下，如实提一句「另有分区没用上：/dev/vdb1（ext4，没挂上）」 |
| 这台电脑（只读） | 系统在 `nvme0n1p5`，主目录在 `nvme0n1p6` | 第一种 |

`/boot` 这一点设计书 4.3 没写到：Ubuntu 的云镜像（和一些安装方式）会单独分一个 `/boot`，它也是 Linux 格式，不排除就会把只有一个系统分区的电脑误判成第三种。

## 结论

1. nvm、uv 装进 `~/tools` 可行，Node、pnpm、Python、靠 Node 运行的命令都正常。
2. 要在启动设置里用 `pnpm_config_` 开头的变量指定 pnpm 的包仓库、缓存、状态的位置，不用 `pnpm config set`。
3. uv 留一个小文件在 `~/.config/uv`，列进 4.3 的例外。
4. 体检的分区判断要排除系统自己在用的分区（`/boot` 等）。
5. 「Pi 靠终端里的 Node 运行」：装好新的 nvm 并设好默认版本后正常。真正的 Pi 没有在虚拟机里装。
