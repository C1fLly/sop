# 第二段第 6 到 8 步：假 AI、假 gh、流程引擎、版本机制、流程沙箱

2026-11-18。这三步是连着做的：引擎写出来要靠沙箱跑才知道对不对，沙箱又要引擎才跑得起来。

## 做了什么

### 流程引擎（`kernel/engine.py`、`kernel/steps.py`、`kernel/cli.py`）

- 照 8.4：从当前位置连续执行，碰到「执行者是人或 AI 对话又没人在答」「自动处理的办法用完」「轮数上限」就停下。停下时打印四件事：现在在哪一步、刚才自动做了什么以及各自通过与否、现在需要你做什么、做完后执行什么命令。
- 位置一律由事件回放得出（Y3），本机不另存进度。
- F14 实现：一个 `sop` 进程里给所有不被阻塞的工单各开一个线程走工单流程，并行数有上限（默认 3）。工单之间的依赖按工单文件里的「依赖：」行算。事件都交给同一个写入线程，合并推送（8.2）。
- 「几张工单并行、一张停下等人，别的接着跑」（开工时用户同意的做法）：别的工单的自动步骤接着跑，直到没有能自动往下走的步骤才停，然后一次列出所有在等人的事。
- 每一步都写成「重做也安全」：被打断后重做时，已经做过的不再做（例如开 PR 前先查有没有已经开着的）。
- 各步的处理函数照 7.4、7.5 写。几条要点：
  - AI 步骤：任务包（9.1 的八节，模板在 `prompts/`）；状态目录全新会话每次现建、续接的几步共用一个（F2、F5、F6 一组，F3、F4a 一组），用完封存；按 6.3 的放法起受限环境；结果文件交回问题时（9.3）停下；每步结束后扫描会话日志里的额度报错。
  - 规划类步骤 AI 不提交：脚本先跑可改范围检查和出口检查，再由特权侧提交、推送（6.3）。
  - T4：结果文件、声称的提交、工作区干净、**一个提交都没有不算做完**、可改范围（连被忽略的文件一起看）、已确认内容。
  - T11、F17 验收：这次带来的每一处界面变化列给小白看；通过时更新视觉基准。**T11 的放行等 T13 合进功能分支、核对功能分支上的就是验收时那几张图之后才写**，写完让功能 PR 的守门检查重跑（6.4，v0.9）。F17 的放行在更新基准的提交推送之前写。
  - F18：转正式之前跑一遍受保护路径的兜底，对不上就停，不自动补放行。
  - F19：三项（全档、快档、守门），用的就是 `checks/f19`；失败的先重跑一次。
  - F20：公开仓库脚本合并；私有仓库请小白去网页上点，点完核对合进去的就是 F19 查过的那一份。
  - T8 之后：「改规格的技术部分」「拆工单」由功能这一级接手，重走 F9fix、F7、F8、F9；验收卡或摘要变了才重新打开 F10；「建议放弃」用业务语言问小白，去掉就放弃这张工单。
  - 放弃工单：关 PR、删目录和分支、记放弃事件；它从来没合进功能分支，也就没有放行。
  - 被打断的步骤（7.12）：列出这个工作目录里没提交的改动和被忽略的 AI 设置文件，丢掉，从上一次提交重做；如果那一步是在另一台电脑上开始的，先停下问小白那台电脑是不是还在跑（8.4）。
  - 花费提醒（8.4）：一个功能累计超过 50 美元提醒一次，整个项目每多 200 美元提醒一次；提醒写进日志、终端打印、桌面通知，流程不停。
  - 门禁命令自己跑不起来（没写出报告）算工具包的问题，停下，不生成修复工单。
- 命令：`sop`、`sop answer`/`sop chat`（在终端里回答人的步骤）、`sop status`、`sop cost`、`sop feature new`、`sop feature drop`、`sop self install`、`sop self upgrade`。其余第三段以后。
- 人的步骤：真用时在终端里问（`kernel/human.py` 的 `TtyHuman`）；沙箱里照剧本答。
- `kernel/project.py`：调 wt 时一律带工具包的模板、关掉钩子、执行前核对特权侧要用的文件（6.4 第四层）、执行后重新记下 `.git/config` 的指纹；调 `gh` 之前也核对。

### 版本机制（`kernel/launcher.py`、`kernel/version.py`）

- 启动器 `~/tools/sop/sop`：按项目主线上 `sop.json` 声明的提交编号，在 `~/tools/sop/versions/<提交编号>/` 找到那个版本执行；没装就从工具包仓库装；每次运行前核对那个目录就是声明的提交、没被改过。
- 修补版和大版本（7.11）：**按实际内容比**，流程定义（`flows/`）和技能副本（`skills/`）和当前版本逐字一致才算修补版。原来打算让版本自己声明，又要再核对声明，干脆直接比。
- `sop self upgrade <提交编号>`：大版本在有进行中的功能时被拒；否则开一条升级分支（名字带序号、从没用过）、改 `sop.json`、同步检查流程、**先写放行再推送**、开草稿 PR、转正式、F19 三项过了才合并；功能进行中换修补版时，把主线合进功能分支（只做合并），再让进行中的工单分支跟上（`wt sync --merge`）。

### 假 AI、假 gh、测试用档案

- 假 AI（`adapters/ai/fake/`）：在真的受限环境里跑，照剧本写文件、提交、合并、交回结果文件、写会话日志（可以造额度报错）、睡一会儿（给「被打断」用）。适配器的接口（`adapters/ai/base.py`）照 10.1 定了四个操作。
- 假 gh（`tests/fakes/gh/gh`）：照 S4、W21 实测过的 GitHub 规矩算检查：快档在打开、新推送、重新打开、转正式时跑，有冲突时不跑；全档只在目标是主线、已转正式时真跑，否则记「跳过」；守门检查转正式时不跑，有冲突照跑；公开仓库的分支保护把「跳过」算通过。**守门检查真的执行**：检出主线、按主线 `sop.json` 取工具包那个版本、跑它的 `checks/guard/guard.py`（开工时用户同意的做法）。剧本能让某个检查失败、或一直「还在跑」直到某个 PR 合并。
- 测试用档案 `tests/fakes/profiles/stack/fake/`：门禁照剧本通过或不通过，把 `ui/screens/` 当成页面截图和基准比。只在沙箱里用，不随工具包发给用户。
- 新项目的模板 `templates/project/`：给 AI 的规则、项目检查和守门检查两个流程文件（守门的那个按主线 `sop.json` 取工具包版本再跑）。**项目检查里的门禁命令第 2a 期才接档案，在那之前它明确失败**（宁可红，不能空跑出绿）。

### 流程沙箱（`tests/sandbox/`，22 个剧本）

每个剧本一个「世界」：本机的工具包仓库（开发目录的快照）、项目的假远程、假 gh、用 `wt init --url` 建的项目（裸仓库加工作目录，和真的一样），经启动器执行 `sop`。

## 没做的

- 原样运行 `implement-spec` 的路径（7.6）：受限环境的放法做了、隔离自检验了，窄接口和那条路径的流程第 2c 期。
- 产品流程（7.3）、规范变更（7.11 的 G1 到 G5）、退掉已合入的功能、功能变更（`sop feature change`）：第 2a、2b 期。归属名查重的机制是同一个，已经做好。
- 真的对话窗口（`sop chat` 只是在终端里回答，没有接 AI 工具的对话方式）：第三段的 Claude Code 适配器。
- 回放用「项目声明的那个工具包版本的流程定义」：做到了（启动器按 `sop.json` 找版本），但修补版换上时流程定义本来就不变，大版本又被拒，所以「旧事件遇到新流程定义」的情况在第一版里不会出现；沙箱没有专门造。
- 验收环境（第 13 节）：验收卡和界面变化只是列给人看，没有起验收环境。第 2a 期。
- 维修窗口、`sop self report`：停下时提示了这两个命令，命令本身第三段。
