## 上一个子代理留下的半截改动怎么处理的

它只改了 `runner/docker/service.py`（约 +133/-23），没写测试、没在虚拟机里验。我读完后**大体照用、改了三处**：

- 照用的：「在用」锁（`state/<项目名>/docker.lock`，共享锁，几个 `sop` 可以同时用；修改时间记「最后一次用完」）、`use()` 和 `Lease`、计时器加它触发的服务（服务 `Wants=` 计时器、计时器 `PartOf=` 服务，每分钟跑一次）、闲了停的小脚本拷到数据目录、四份登记文件都 0600 都不 enable、`remove` 删四份。思路从根上就简单：靠系统的文件锁判断「有没有人在用」，进程怎么死锁都会放开，不用自己记进程号、不留死锁文件。
- 改的 1：小脚本原来用 `exec 9>>"$lock" 2>/dev/null || exit 0`。在 dash 里重定向失败会让整个脚本直接退出码 2（我在 `/tmp` 试过），`|| exit 0` 不起作用；而且用「追加」方式打开会在锁文件不在时新建一个。改成先看锁文件在不在（不在就是没经 `sop` 用过，例如隔离自检、手动 `start`，不管），再用只读方式打开拿独占锁。
- 改的 2：上限从哪取。半截改动写的是项目主线 `sop.json` 的 `docker` 段。我改成**技术栈档案 `toolchain.toml` 的 `[docker]` 段**（见下「项目的上限在哪声明」）。
- 改的 3：加了 `Lease.touch()`，`sop` 每一步要用时把修改时间刷成现在。不然一个跑了几个小时的 `sop` 被强制结束，会按它几个小时前开始用的时间算，马上就停。
- 半截改动提到的 `kernel/engine.py` 的 `docker()` 确实没写，是我写的。

## 做了什么

### `runner/docker/service.py`

- 新增计时器 `sop-docker-<项目名>-idle.timer` 和它触发的 `sop-docker-<项目名>-idle.service`（一次性），专用 Docker 起来时带起来、停了跟着停。小脚本 `idle-stop.sh` 拷到 `~/tools/docker-sop/<项目名>/`（专用 Docker 的视野里只有它的 `data`、`exec`、`run` 三个子目录，看不到它）。
- 小脚本：没有锁文件 → 不管；拿不到独占锁（有 `sop` 在用）→ 不管；锁文件修改时间离现在不到 15 分钟 → 不管；否则拿着锁停专用 Docker。停的时候拿着锁，`sop` 这时要用就排在后面，等它停完再起（虚拟机里演过）。
- `use()`：拿共享锁、刷时间、`start()`（没在跑才起、等它答话）；起不来时锁放开。`Lease.release()` 刷时间再放开。
- `check_limits()`：只认 `memory`、`cpu` 两项，写法再由 `render()` 核。
- 命令行加 `use`（像 `sop` 那样拿着锁，回车放开）和 `--idle 秒数`（虚拟机验证时用 120 秒，不等 15 分钟）。

### `kernel/engine.py`、`kernel/steps.py`

- `Engine.docker(prof)`：档案的 `toolchain.toml` 有 `[docker]` 段才起，没选档案或档案没写就返回空（现在的假档案 `fake` 没写，所以流程沙箱不碰专用 Docker）。一个 `sop` 进程只起一次，之后每次要用只刷时间；`run()` 收尾时放开（`release_docker()`）。
- 三处接上：装依赖（T1 的 `t_open`）、门禁（`gate_step`）、工单上的实现那类 AI 步骤（`ticket_impl`、`implement_spec`）。规划、只看不改的 AI 步骤不起、不给通道（不运行项目代码，6.3 四）。
- 「`sop` 退出后 15 分钟」的意思就落在这里：`sop` 推进流程那一轮结束（停下等人、做完、出错）时放开，从那一刻起算。

### 项目的上限在哪声明（3-17 留下的，这次定了）

**定在技术栈档案的 `toolchain.toml` 里**（`[docker]` 段，`memory`、`cpu` 可省，省了用默认：内存一半、一半的核），不放在项目的 `sop.json`。理由：

1. 档案在工具包里，受限侧改不了。`sop.json` 虽然是受保护路径，但每次起专用 Docker 前都要从主线读，多一处要信的项目文件。
2. 「这个技术栈要不要 Docker、大概要多少内存」本来就是档案的事（6.3 四已经写「具体清单写在技术栈档案的 `toolchain.toml` 里」），小白也判断不了该填多少。
3. 有 `[docker]` 段同时就是「这个档案要用专用 Docker」的开关，不用另加一项。

## 没做的

- **真等 15 分钟**没在虚拟机里演，用的是 120 秒（参数一样走、计时器一样每分钟看）；900 秒是写进登记文件的数，单元测试和虚拟机里都核了。
- 停的时机最晚会晚一分钟左右（计时器每分钟看一次，`AccuracySec=5`）。
- 用户级服务在最后一个登录会话结束时会停（3-17 记过），所以注销后专用 Docker 也停，这和「用时才起」不冲突。
- 档案里真的写 `[docker]` 段的是第 2a 期的真档案；现在只有测试用的假档案，没写。
- `sop project remove` 要连同计时器一起删（`remove()` 已经删四份），那条命令在第 3 期。
- 两个项目同时开是 3-19。

## 和设计书的出入（留给 3-48 并入）

1. 6.3 二「重启后自己起来」那一条改成：专用 Docker 不设成登录后自己起来；`sop` 要用（装依赖、门禁、工单上的实现）时才起、等它答话；`sop` 那一轮结束后 15 分钟没有再用就停；重启、注销后不在跑，下次要用时起，镜像、数据卷、容器都在（虚拟机里实测）。和问题 1 的答案一致，第 19 节第三段验收标准第 7 条一起改。
2. 每个项目多两份登记文件：计时器 `sop-docker-<项目名>-idle.timer` 和它的服务；「在用」锁 `~/tools/sop/state/<项目名>/docker.lock`（4.3 的 state 表可以补上）。
3. **项目的上限在技术栈档案 `toolchain.toml` 的 `[docker]` 段声明**（memory、cpu），有这一段就是这个档案要用专用 Docker；没写用默认。6.3 四的清单加这一项。
4. 只给运行项目代码的步骤通道：装依赖、门禁、工单上的实现（`ticket_impl`、`implement_spec`）；规划类、只看不改的不给。6.3 的表可以加一列。

## 自己出的错

1. 虚拟机脚本初稿里「正在停的时候去要」是 `start --no-block` 之后睡 0.3 秒就去要，不一定碰得上「正在停」（跑之前自己看出来的）。改成等到专用 Docker 不是 `active` 了再去要，日志里看到是 `deactivating` 时要的。
2. 「过了 120 秒才停」初稿写成 `>= 120`；被强制结束那一项是从锁文件的修改时间（整秒）算的，可能差一秒，跑之前改成 `>= 118`。实测 171、122 秒，没用上这点余量。
3. 收拾那一步 `rm -rf ~/tools/docker-sop/demo-x` 报了一个「Permission denied」（容器的覆盖层目录是免管理员 Docker 用另一个用户号建的，要用 `rootlesskit rm` 删）。只是虚拟机脚本最后的收拾，不影响结论；虚拟机之后整个还原了。
