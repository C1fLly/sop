# 3-50 体检：网络连通

2026-11-20。由主控窗口派出的子代理做。没调用 AI，没花钱，没开虚拟机。本机只读跑了一遍 `sop machine doctor --readonly`（整个系统只读的 bubblewrap 里，环境里去掉了密钥）。

## 做了什么

- **`machine/network.py`**（设计书 4.4「体检检查 GitHub、AI 服务、各软件源是否连得上」）。逐样试连，只做网络这一层：
  - 网页：连上（要走代理的先让网页代理用 CONNECT 转过去；不加密的网页把整个地址交给代理）、加密的做完握手并核对证书、发一个不带任何凭据的 `HEAD` 请求，对方回了任何状态码（200、301、401、404 都算）就是「连得上」。地址里的账号密码、参数一律去掉；AI 服务只试主机的根路径 `/`。
  - GitHub 的 SSH：连上 `github.com:22`、读对方先发的那一行（`SSH-2.0-…`）就断开，自己一个字节都不发，不用 SSH 密钥，也不跑 `ssh` 命令，所以不会写 `~/.ssh/known_hosts`。SSH 默认不走网页代理，所以先直连；直连不通而经代理能通时，照实说「经代理能连上，但 SSH 默认不走代理，推送会失败」。
  - 试哪几样：GitHub 网页和 SSH；体检找到的每个 AI 工具的服务地址；apt 的软件源（`network.json` 的 `apt_mirror` 加上 `/etc/apt/sources.list*` 里的地址，每个主机一个）；npm、PyPI 的源（网络设置里有就用它，没有用官方的）；安装工具那一步要下载的四个站（uv、nvm、Node、Docker；gh、wt 从 GitHub 取，上面已试）。最多 8 样同时试，每样 8 秒超时。
  - 代理：按 `config/network.json`；还没有这份设置时（第零步之前、这台开发机）按终端里的 `http_proxy`、`https_proxy`、`no_proxy`，报告里写明是哪一种。网络设置写的是「不用代理」时不看终端。`no_proxy` 照 curl 的规矩认（`*`、`.a.com`、`a.com` 管子域名、带 `*` 的写法）。socks 代理不试（第零步只记网页代理），照实写「没试」。代理的账号密码不打印。
  - AI 服务的地址从哪来：先看 `config/ai/<工具名>.env`（M4 记的，问题 5），**只取名字以 `BASE_URL` 结尾的那一行**，别的行（密钥）不留；Claude Code 再看环境变量 `ANTHROPIC_BASE_URL`，都没有就用官方地址。**不打开 Codex、OpenCode、Pi 自己的配置文件**，所以这三样在 M4 做好之前写「服务地址还没登记，这次没试」。
  - 连不上的说清卡在哪一步、可能的原因：域名解析不了（没联网或地址写错）、拒绝连接（地址端口不对；是代理的话代理软件可能没开）、多少秒没连上（可能要走代理）、代理要账号密码、代理不肯转、证书核对不过（可能被网络拦截）、加密握手失败、连上了不回应、回的不是网页或不是 SSH；再按是哪一类写后果（GitHub 连不上推送开 PR 都做不了、AI 服务连不上 AI 步骤会失败、源连不上装依赖会失败、下载站连不上安装那一步会失败）。
- **`sop machine doctor` 的报告加第七项「网络连通」**；有连不上的在结论里加一条「要注意」，不算基础工具没装好、不改退出码。加了 `--no-network`（不试连；自测里真跑命令的那两项用它，不连外面的网络）。试连不写任何文件，`--readonly` 照样一个文件都不写。

## 结果

- 新加单元测试 `tests/unit/test_machine_network.py` 25 项，全部通过。假服务都只听 127.0.0.1，每项测完关掉：
  - 连得上：不加密的网页（回 401 也算，请求里没有地址的参数、没有 `Authorization`）、加密网页（openssl 现造的自签证书）、SSH（假服务只收到「对方断开」，说明我们一个字节都没发）。
  - 连不上：拒绝连接、一个字不回就断开、回的不是网页、不是 SSH 服务、域名解析不了、证书核对不过（不认自签证书）。
  - 超时：网页不回应、SSH 不回应、代理不回应、连接超时，都在设的时间里结束；三样一起试按先后返回。
  - 走代理：不加密的网页整个地址交给代理、加密网页经 CONNECT、代理没开、代理要账号密码（发了 `Proxy-Authorization`，报告里不出现密码）、代理拒绝转、`no_proxy` 里的直连、socks 不试、SSH 直连不通而经代理通。
  - 地址：网络设置和终端代理的先后、apt 两种文件格式（带 `[arch=…]`、带账号密码的地址被去掉、注释行不算、同主机只一次）、`config/ai/*.env` 只取地址那一行、Claude Code 的环境变量（账号密码和路径去掉）和官方地址、试连清单的先后。
  - 报告的文字（有代理、按终端、不用代理三种）、体检报告里的第七项和「要注意」、`--no-network`；试连一遍前后 `config` 里的文件一个没多。
- 改了 `test_machine_doctor.py` 的真跑命令两项：加 `--no-network`、多核对「七、网络连通」，参数重复的也报用法。
- 全部自测：做之前单元测试 157 项、流程沙箱 24 个剧本、总检查 62 个样例全过；做之后单元测试 182 项（多了这 25 项），流程沙箱 24 个、总检查 62 个，全部通过。
- 做完后全部自测一共跑了三遍：第一遍单元测试有 1 项偶尔不过（自己写的测试，见「自己出的错」，改了）；第二遍单元测试 182 项全过，**流程沙箱 24 个里有 1 个没过**（`test_failures` 的 `test_fix_diagnose_decide_and_backtracks`：假 `gh` 里守门检查 `git clone` 本地假远程时报 `fatal: hardlink different from source`，是 Git 本地克隆用硬链接时撞上同时在写的对象，流程引擎和假 `gh` 这次都没改，这一项不碰网络代码）；第三遍原样重跑，单元测试 182、流程沙箱 24、总检查 62 全部通过。那一次没过的原因没深挖，记下来：假 `gh` 克隆本地假远程可以加 `--no-hardlinks` 避开，留给主控窗口决定要不要单拆一个小任务。
- **本机只读跑**：在 `/tmp` 下新建的临时目录里，用 `env -i` 只留 PATH、HOME、语言、代理的几个变量和 `ANTHROPIC_BASE_URL`（密钥 `ANTHROPIC_AUTH_TOKEN` 等都不带进去），再套 bubblewrap「整个系统只读、只有临时目录当 `/tmp` 能写」，跑 `sop machine doctor --readonly`。十几秒跑完。结果：
  - 代理 `http://127.0.0.1:7890`（还没有网络设置，按终端里的），试连 12 样全部连得上：GitHub 网页（经代理，200）、GitHub 的 SSH（**直连**，对方回了 `SSH-2.0-…`）、Claude Code 的服务（环境变量给的地址，经代理，200）、apt 三个源（`cn.archive.ubuntu.com`、`security.ubuntu.com`、`cli.github.com`）、npm、PyPI、四个下载站。Codex、OpenCode、Pi 写「服务地址还没登记，这次没试」。
  - 和实际相符：这台电脑 GitHub 能直连（交接文件里写过），`no_proxy` 里没有这些主机，所以网页都经代理；SSH 不走代理，直连通。设计书 6.5 写的「别的软件源、AI 服务是不是也直连，没有逐个查」，这次查的是「经代理连得上」，直连没另试。
  - 其他六项和 3-06 本机跑的一样（主目录不在系统盘上、5 样不在规定位置、四个 AI 工具的版本）。
  - 核对：输出里没有出现密钥；跑完 `~/tools/sop/config` 仍不存在；`~/.ssh`、`~/.ssh/known_hosts`、`~/.pi/agent/install`、`~/tools`、`~/tools/sop` 的修改时间前后一样；主目录下跑之后新改的文件只有微信自己的登录配置和本会话 Claude Code 的会话目录（都不是这次跑的）。AI 工具查版本留在临时目录里的东西随临时目录一起删了；`/tmp` 下没有留 `sop-doctor-*`、`sop-3-50-*`。本机那个 127.0.0.1:8765 的旧网页服务没碰。

## 没做的

- Codex、OpenCode、Pi 的服务地址：要等 M4（3-10）把地址记进 `config/ai/<工具名>.env` 才试得到；现在不读它们自己的配置文件（里面有密钥）。
- socks 代理不试（第零步只记网页代理；本机终端里另有一个 `all_proxy=socks://…`，没用到）。
- SSH 经代理：只在直连不通时试一次、报告「经代理能连」；SSH 自己的代理设置（`~/.ssh/config` 的 `ProxyCommand`）不读，所以已经配好了经代理走 SSH 的电脑，体检仍会说「直连不通」并提示「已经配了的可以不管」。
- 只看连不连得上，不看速度；不试 GitHub 的 API（`api.github.com`）、GitHub Releases 的下载地址（`objects.githubusercontent.com`），也不试 Docker Hub（容器里联网是第 2a 期的事，6.3 二）。
- 不登录、不发 AI 调用：AI 服务能不能真用是 M4 和适配器 `probe` 的事。
- 没在虚拟机里试（不动系统，任务清单写的是本机只读跑）。

## 和设计书的出入（留给 3-48 并入）

- 体检报告多了第七项「网络连通」和 `--no-network`；试连的清单（含安装工具那一步的四个下载站）、「回任何状态码都算连得上」、SSH 只读对方那一行、还没有网络设置时按终端的代理，设计书都没写细。
- AI 服务的地址从 `config/ai/<工具名>.env` 里名字以 `BASE_URL` 结尾的那一行取：3-10 做 M4 时存地址要用这样的名字（例如 `ANTHROPIC_BASE_URL`、`OPENAI_BASE_URL`），否则体检试不到。
- 4.4 写的「AI 服务」：没登记地址的三个工具这次不试，照实写。

## 自己出的错

- 第一版的单元测试有两处偶尔不过（跑全部自测时 182 项里 1 项）：
  - 「回的不是 SSH 服务」那项用的假网页服务要先收到请求才回话，而 SSH 试连是等对方先开口，两边干等到超时。改成用一个一连上就先说一句别的话的假服务，另加「一连上就断开」一项。
  - 经代理试 SSH 时，读代理的回复一次读 4096 个字节，SSH 那一行和代理的回复挤在同一个包里时被多读走、丢了，结果说「不是 SSH」。改成代理的回复一个字节一个字节读到空行为止（这是真的问题，不只是测试的问题）。改完单独连跑 40 遍都过。
- 读 apt 设置时文件没关（Python 报了 ResourceWarning），改成 `with`。
- 本机跑完看到 `cli.github.com`（gh 的 apt 源）也被标成「Ubuntu 软件源」，改成「系统软件源（apt）」。
