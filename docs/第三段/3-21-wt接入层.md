## 发现的漏洞（已补）

原来决定「核对哪些工作目录」的是「项目根下里面有 `.git` 小文件的目录」。受限侧（专用 Docker 那条路，6.3 二）把某个工作目录里的 `.git` 小文件**换成一个目录**（里面放自己的 Git 配置），或者干脆删掉，这个目录就不在名单里、不被核对了。而 `wt pr`、`wt sync` 是在工作目录里执行的，Git 会照着那份配置做（比如配置里改了推送用的 SSH 命令，就可能带着凭据执行受限侧写的东西——这一步推断没有实际演示）。

改成：Git 登记里有的（`.git/worktrees/<名>`），加上项目根下凡是里面有 `.git` 的目录（文件、目录、链接都算），都核对。核对代码本身不用改：它读到的不是一个写着 `gitdir: …` 的小文件，就报「内容不对」。新加两项测试（小文件换成目录、小文件删了）；换回旧的认法跑，这两项失败。

## 测试怎么做的、结果

用本机的 wt（`~/.local/bin/wt` → `~/tools/wt/wt`，只用）在 `/tmp` 的本地假远程上测。每项测试：工具包根目录、主目录 `HOME`、`TMPDIR` 都指到临时目录；PATH 最前面放一个什么都不做、只记账的假 `gh`（不碰真的 GitHub 和登录）；故意在环境里放上指向 wt 自带模板的 `WT_TEMPLATE` 和一个 `WT_CD_FILE`。

- 正常能用（4 项）：建项目用的是工具包的模板（`.shared/` 里只有 `README.md`、`hooks/`，三个钩子和工具包的一字不差；wt 自带模板里那几份手册没进来）、建完记了指纹、核对通过、`WT_CD_FILE` 没被写、临时主目录和 `TMPDIR` 里什么都没留；项目根不空时不建；建目录 wt 把起点记成基准、指纹跟着重记、准备脚本只链接了 `.env`；`wt rm` 删目录；`wt ls` 能用；这几样都没找 `gh`。
- 登记基准（1 项）：远程有功能分支 `feat/f` 和它下面一张还没开 PR 的工单 `ticket/f-1`。`new` 继续远程已有的工单分支，wt 登记不了基准（没有 PR）；`set_base` 写成 `origin/feat/f` 之后，`wt sync --merge --dry-run` 打出来的基准就是 `origin/feat/f`、没有 `origin/main`。设计书 4.7 写的「用 wt 按它重建并把基准写回 wt 的登记，没有试」，这次在本机假远程上试了。基准不存在、分支不存在、分支名不合法时不写，登记不变。
- 被改过就不执行（7 项）：`post-create` 加一行、`pre-remove` 换掉、`.git/config` 里加一条把钩子目录指到别处、`.git/hooks/post-checkout`、工作目录的小文件改了内容、换成目录、删了、指纹记录没了。每一种都试四个动作（建目录、删目录、登记基准、`wt ls`）：都抛「被改过」、wt 一条都没执行、改过的脚本没被执行（留记号的文件不存在）、目录一个没多没少、`.git/config` 一个字节没变。
- 证明测试会报错：把核对整个换成空的再跑，「被改过」那几项全部失败（当时 6 项，后加的 2 项用旧认法另测，也失败）。

自测：做之前（主控窗口跑的）单元测试 222 项、流程沙箱 24 个剧本、总检查 71 个样例，全部通过。做完：单元测试 234 项、流程沙箱 24 个、总检查 71 个样例，全部通过。
