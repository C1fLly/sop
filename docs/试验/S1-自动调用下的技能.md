# 试验 S1：自动调用下的技能

状态：已完成（第一部分 2026-11-16，后续部分 2026-11-17），**只有一项按用户的决定没做：Codex、OpenCode、Pi 的会话续接**。没做的部分列在末尾。

后续部分调用了 AI，共 8 次。**记账 3.44 美元**：Claude Code 的 3.08 美元是工具自己报告的；另外三个工具的 0.36 美元是我按词元数用偏高的单价估的。全部在受限环境里跑。

## 要验证什么

设计书的主链靠流程命令直接调用 AI 来执行技能。主链上的技能在原文里都标着「只能由人输入命令触发」。如果自动调用时触发不了，T3、T6、F22 等步骤都要改做法。

设计书第 19 节列的四件事：

1. 只允许人触发的技能在自动调用时能否触发。四个工具各做最基本的一项。
2. `tdd` 要求先和用户确认测试切入点时会怎样。
3. `code-review` 没给比较起点时会怎样。
4. `research` 的后台帮手在主会话结束时是否跑完。

## 第一部分：Claude Code（2026-11-16）

环境：Claude Code 2.1.325，Ubuntu 26.04。技能文件来自 mattpocock/skills 的提交 `5863806`（2026-11-12），只复制了 `grill-me` 和 `grilling` 两个到一个空项目的 `.claude/skills/` 下。`grill-me` 标着只能由人触发，它的内容是「调用 grilling」。

| 试验 | 命令 | 结果 |
|---|---|---|
| A 触发 | `claude -p "/grill-me 我想做一个记录每天喝水量的小工具" --output-format json --max-budget-usd 0.60` | 触发成功。输出是追问技能规定的格式：分轮、每题带编号和推荐答案。3 轮对话，27 秒，报告花费 0.27 美元 |
| B 续接 | `claude -p --resume <会话编号> "1 是 2 是 3 是 4 是 5 是" --output-format json` | 续接成功。会话编号不变，AI 记得第 1 轮的答案并给出第 2 轮问题。39 秒，报告花费 0.42 美元 |
| C 对照 | `claude -p "/no-such-skill-xyz 你好"` | AI 明确说这个命令没有安装、没有执行。说明 A 的成功不是 AI 在猜 |

第一部分的结论：

1. **在 Claude Code 上，只允许人触发的技能可以在自动调用时触发。** 写法是把技能命令放在提示词开头。设计书 10.1 里「读取技能文件并照做」的退路在 Claude Code 上用不着。
2. **自动调用下可以续接会话。** F2、F5、F6 要求的「同一个会话」在自动调用下也能做到。
3. **技能确实会向用户提技术题。** 第 2 轮的 Q6 问「工具形态：命令行、本地网页还是顶栏小组件」，Q7 问「只支持 Linux 对吗」。设计书 7.4 的【业务】【技术】标记和统一答法是必要的（S0 验证了它有效）。
4. **花费的量级**：一轮追问约 0.3 到 0.4 美元。B 报告的 0.42 美元是整个会话的累计数（后来在 S0 里弄清的），那一次实际增加了 0.15 美元。

当时观察到的一件事：试验 B 里 AI 自己查了这台电脑的环境并写进回答。那次没有用受限环境。它说明不受限时自动调用的 AI 会主动读取机器信息。之后的试验都放进了受限环境。

## 后续部分（2026-11-17）

环境：Claude Code 2.1.326、Codex 0.169.0、OpenCode 2.3.0、Pi 1.5.2。受限环境和记账用 `docs/试验/脚本/AI共用/` 里的两个脚本。

### 一、另外三个工具在自动调用下触发真实的技能

S5 用的是暗号技能。这里换成真实的 `grill-me`（只允许人触发，内容是「调用 grilling」），和第一部分的试验 A 用同一句话，各一次：

| 工具 | 写法 | 结果 | 用时 |
|---|---|---|---|
| Codex | `$grill-me 我想做一个记录每天喝水量的小工具` | 触发成功。输出是追问的格式：`Q1`、`Q2`，每题带建议答案。接着用到了 `grilling` | 36 秒 |
| OpenCode | `@grill-me 我想做…` | 触发成功。先看了一圈项目，再给出 `Q1` 到 `Q7`，每题带推荐。接着用到了 `grilling` | 23 秒 |
| Pi | `/skill:grill-me 我想做…` | 触发成功。给出 `Q1` 到 `Q3`，每题带建议。接着用到了 `grilling` | 43 秒 |

对照（点名一个不存在的技能）在 S5 里做过：三个工具都明说没有这个技能，没有瞎编。

三个工具问的题数和风格不一样（Codex 2 题，OpenCode 7 题，Pi 3 题），OpenCode 第一题就是技术题（「工具的形态：命令行、网页还是 App」）。这和第一部分在 Claude Code 上看到的一样：不预置技术决定，追问就会问技术题。

### 二、`research` 的后台帮手在主会话结束时是否跑完

在 Claude Code 上，空项目里只放了 `research` 一个技能，问了一个能在官方文档里查到的问题：

`/research Python 标准库 json.dump 的 ensure_ascii 参数默认值是什么？设成 False 有什么效果？以官方文档为准。`

结果：**跑完了。** 主会话结束时，笔记文件已经在项目里（`docs/research/json-dump-ensure-ascii.md`，放在项目规则指定的位置），主会话的回答里有结论、原文引文和「没核实的地方」。211 秒，1.32 美元。

怎么做到的：技能原文说「派一个后台帮手，这样你可以接着干活」。实际上主会话派出帮手后**等它做完才结束**（会话记录里帮手是按普通方式派的，不是放到后台）。帮手读了 8 次网页、写了 1 个文件。所以不存在「主会话先结束、帮手被掐掉」的情况。

注意两点：

- 笔记文件写出来了，但**没有提交**。流程命令在这一步之后要自己提交。
- 受限环境里能联网（代理的设置是放进去的），帮手读到了官方文档。

### 三、单独调用 `code-review` 又不给比较起点

在 Claude Code 上，用 S7 做出来的功能分支（比 `main` 多 10 个提交），只发 `/code-review` 这几个字，什么参数都不给。

技能原文说：没给比较起点就问用户。

结果：**它没有问，自己选了 `main` 当比较起点，把审查做完了。** 回答的第一句就是「Review of `git diff main...HEAD` on `feat/jizhang`」。它照原文派了两个帮手（规范、规格各一个），跑了测试，给出了分轴的发现。104 秒，1.24 美元。

注意两点：

- 自己选的起点这次是对的（功能分支对 `main`）。但设计里不能靠它猜：工单复查的起点应当是功能分支，不是 `main`。**流程命令调用它时必须写明比较起点。**
- **整份审查报告是英文的**，虽然项目规则写了「汇报用中文大白话」。S0 里也出过汇报变英文的事。复查的结果文件是给脚本和带路窗口看的，问题不大；但凡要给用户看的，任务包里要再强调一次。

### 四、没有事先约定测试切入点时的 `tdd`

在 Claude Code 上，一个只有空壳的小项目，项目规则里只写了用什么语言和测试工具，**没有写测试切入点**。发了一句：

`/tdd 给这个项目加一个函数 slugify(text)，放在 textkit 里：把一句话变成网址里能用的小写短横线形式…`

技能原文说：写任何测试之前，先把切入点写下来和用户确认。

结果：**它没有卡死，也没有自行决定。它一行代码都没写，以一组问题结束了这次调用**（36 秒，0.26 美元）：

- 列出了打算用的测试入口和四种要测的情况；
- 问了一件要用户定的事（中文和带音标的字母怎么处理，给了三个选项和它的建议）；
- 最后说「回我『可以，选 A』，我就开始」。

这次调用工具报告的是「成功」，不是出错。项目里没有任何改动。

然后续接这个会话，回答「可以，选 A。」：**它接着把活干完了**（57 秒，0.26 美元）。写了函数和 6 个测试，在受限环境里重跑全部通过，试了几个例子都对。它没有提交（我没让它提交）。

对设计的含义：

- **自动调用下，`tdd` 遇到没约定的切入点会「正常结束但什么都没做」。** 流程命令不能只看退出状态，要看结果文件和提交：没有提交、回答是一个问题，就按设计书 9.3 处理（技术问题交给技术决策角色，答案写成决策记录，再续接或重做这一步）。
- **最好不让它走到这一步**：切入点在规格阶段定好并写进决策记录或档案。S0 和 S7 都是这样做的，`tdd` 一次都没有停下来问。
- 它问的那件事（中文怎么处理）其实是业务题，不是技术题。它没有按【业务】【技术】标记，因为这个试验项目的规则里没有写标记的规矩。

## 结论

1. **四个工具在自动调用下都能点名触发只允许人触发的技能。** Claude Code 用 `/技能名`，Codex 用 `$技能名`，OpenCode 用 `@技能名`，Pi 用 `/skill:技能名`。设计书 10.1 里「读取技能文件并照做」的退路四个工具都用不着。
2. **Claude Code 上自动调用可以续接会话**，这次在 `tdd` 上又用了一次。另外三个工具的续接没有验证。
3. **`research` 的帮手在主会话结束前跑完**，笔记写在项目里，但不提交。
4. **`code-review` 不给起点时不问，自己选。** 流程命令必须写明起点。
5. **`tdd` 没有约定切入点时不卡死、不自决，而是什么都不做、以问题结束。** 流程命令要能认出这种「成功但没干活」，并把问题送去该去的地方；切入点最好在规格阶段就定好。
6. 不预置技术决定时，各工具的追问都会问技术题。
