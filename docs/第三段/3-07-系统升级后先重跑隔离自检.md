# 3-07 系统升级后先重跑隔离自检

2026-11-19。由主控窗口派出的子代理做。没调用 AI，没花钱，没开虚拟机。没有在本机上真跑 `sop` 或隔离自检（理由见「没做的」），只跑了自测（都在 `/tmp` 下的临时目录里）。

## 做了什么

- **`machine/syscheck.py`：推进流程之前先比一下系统组件**（设计书 4.5）。`gate()`：
  - 用 3-05 的 `components.collect()` 只读地查一遍现在的内核、bubblewrap、两条系统规则、往终端塞按键的开关，和 `config/system.json` 的登记比（`config.system_changes`）。
  - **一样**：直接推进，什么都不写（连锁文件都不建）。平常每次都是这样，多花的时间是跑一次 `bwrap --version` 和 `dpkg-query`。
  - **不一样，或者还没登记过**：用大白话说哪几样变了（「上次是……，现在是……」；没登记过的说「还没有隔离自检通过的记录」），然后先跑隔离自检。
    - 通过了：把自检**之前**查到的那一份记进登记（自检验的就是它），说一句「隔离自检通过（N 项，0 项不符合），已记下现在的系统组件版本，接着推进流程」，再进流程引擎。
    - 没通过（含跑到一半出错、跑不起来、超过 15 分钟没跑完）：列出不符合的几行（出错的带最后几行报错），说「受限环境可能已经挡不住 AI，所以停下了，流程一步都没有推进」，指向维修窗口（`sop repair`），退出码 1。**登记不改**，所以下次执行 `sop` 还会重新自检，修好了才能接着走。
  - 几个项目同时启动 `sop` 时：发现变了之后上一把锁（`config/selftest.lock`），拿到锁再比一次，别的 `sop` 已经自检通过、登记好了就不再跑。
  - 隔离自检现在用的是第二段写的本机那份 `runner/selftest.py`（同一个工具包版本里的，用跑 `sop` 的那个 Python 加 `-I` 另起一个进程），通过看退出码。M6 的正式做法是 3-11。
  - 测试用的口子：环境变量 `SOP_SELFTEST_CMD` 换成别的命令（和已有的 `SOP_FAKE_SCRIPT` 那些一样）。
- **`kernel/cli.py`**：只在推进流程的命令（`sop`、`sop answer`、`sop chat`，都走 `run_engine`）之前调用 `gate()`；`sop status`、`sop cost`、`sop feature new/drop`、`sop self upgrade`、`sop machine …` 不自检。
- **流程沙箱**（`tests/sandbox/world.py`）：
  - 「世界」建好后，按这台电脑现在的系统组件先记进临时根目录的登记（等于机器准备时隔离自检已经通过过），所以原来那 22 个剧本照旧不自检。
  - 加了假的隔离自检 `tests/fakes/selftest/selftest`：按剧本通过或不通过；每跑一次记下那一刻日志分支在哪个提交；剧本没想到会自检时一跑就报错（防止别的剧本悄悄触发自检）。
  - 加了 `set_registered`（把登记里的某一样改成旧的，演系统升级）、`registered`、`selftest_runs`、`journal_tip`。
- README 的 `machine/` 一行补了一句。

## 结果

- 新加流程沙箱 `tests/sandbox/test_system_upgrade.py` 2 个剧本，都通过：
  - **bubblewrap 版本变了、自检通过**：登记里的 bubblewrap 改成 `0.10.0`，执行 `sop`：输出里先说「受限环境用的 bubblewrap：上次是「0.10.0……」，现在是……」、「先重跑一遍隔离自检」，后说「隔离自检通过」；假自检只跑了一次，跑的那一刻日志分支还在 `sop feature new` 之后的那个提交上（**先自检**）；之后功能整个做完（**后推进**）；登记里的 bubblewrap 换成了现在的。再执行一次 `sop`：不再自检（这时自检的剧本已撤掉，要是自检就会报错）。
  - **自检不过**：连续执行两次 `sop`，每次都重新自检、退出码 1、输出「隔离自检没通过」、不符合的那一行、`sop repair`；日志分支一个事件都没多，功能的步骤和之前一样，登记还是旧的。`sop status` 照常能看、不自检。之后把自检的剧本改成通过（等于维修窗口修好了），再执行 `sop`：重新自检、通过、功能做完、登记更新。
- 新加单元测试 `tests/unit/test_machine_syscheck.py` 13 项，都通过：没变化时不自检、什么都不写；还没登记过时先自检、通过后记下（目录权限 0700）；内核只换编译加 bubblewrap 打补丁两样都说出来、通过后登记更新、再来不自检；塞按键开关打开、自检不过时停下、登记不改、第二次还自检；记的是自检之前查到的那一份；拿锁之后别的 `sop` 已登记好就不跑；登记文件坏了明说；跑自检的默认命令是同版本的 `runner/selftest.py`、环境变量能换；自检通过、不通过列出不符合的行、中途出错带报错、超时、命令不存在、退出码非 0 但没有「不符合」的行。
- 全部自测：做之前单元测试 94 项、流程沙箱 22 个剧本、总检查 62 个样例全过；做之后单元测试 107 项、流程沙箱 24 个剧本、总检查 62 个样例，全部通过。

## 没做的

- **没有在本机上真跑**：这台电脑上还没有 `~/tools/sop/config/system.json`（3-06 起体检不记系统组件），真跑 `sop` 推进流程会被判成「还没登记过」、去跑真的隔离自检并建出 `config` 目录；真的隔离自检还会在 `/run/user/1000/` 下建（已有就改权限）复用连接的通道目录。都算改动这台电脑，所以没跑。真机上「换一个 bubblewrap 版本，`sop` 先重跑隔离自检再推进」是 3-16 在虚拟机里做。
- **隔离自检只含本机那份**（`runner/selftest.py`）：专用 Docker 那几项（`runner/docker/selftest_docker.py`，三种挂法改 `.shared/hooks`、`.git/config`、`.git/hooks` 等）要有一个起着的专用 Docker，现在只能在虚拟机里手动跑，没接进这次的自检。登记里「免管理员 Docker 那条系统规则」变了时，现在重跑的只是本机那份。M6 的正式隔离自检（3-11）把两份怎么合起来定下之后，`syscheck.selftest_cmd()` 改成调用它。
- **3-11 要接着做的**：M6 自检通过后也要调用 `components.record()` 记下登记（这样装机时就记好了，第一次推进流程不用再自检）；可以直接用 `syscheck.run_selftest`。
- `sop repair`（维修窗口）还没有（16.5，3-42 起），提示里先照现有代码的写法指向它。
- 自检不通过不写进项目的事件日志：这是机器级的事，不属于哪个项目；只打印到屏幕。

## 和设计书的出入（留给 3-48 并入）

- 4.5 写「`sop` 每次启动发现变了，先重跑 M6 的隔离自检」。实际只在**推进流程的命令**（`sop`、`answer`、`chat`）之前比；看进度、看花费、开功能、放弃功能、升级工具包、体检不比也不自检（这些不在受限环境里跑 AI 和项目代码；升级工具包可能正是修自检问题的办法，不能被挡住）。
- 「还没登记过」按「变了」处理：第一次推进流程会先跑一次隔离自检。
- 记进登记的是自检之前查到的那一份；自检不过时登记不改，下次还会自检。
- 几个 `sop` 同时发现变了只跑一次（`config/selftest.lock`）。
- 隔离自检超过 15 分钟没跑完按没通过处理。
- 测试用的环境变量 `SOP_SELFTEST_CMD`。
