# 试验 S9：开工前补做的三个小试验

状态：已完成（2026-11-17）。用户本人也在对话窗口里试过了：都正常，但界面上显示「未登录」（见第二部分）。没做的部分列在末尾。

这三个试验是第三轮独立审查提出来的（`docs/审查/v0.4-第三轮审查.md` 的「严重 2」）：有几样地基没验证，就排在了要用它的那一期后面。用户同意补做。

调用了 AI 三次，**花费 1.36 美元**（都是 Claude Code 自己报告的金额）：做一张工单 1.20 美元；对话方式两次，0.11 和 0.05 美元。真实技术栈那个试验没有调用 AI。

没有用管理员密码。没有改动用户原来的 Docker：试验前后它都是 0 个容器、7 个镜像、3 个数据卷；只从它那里**读**出过三个镜像。专用 Docker 是另起的，试完已停掉，里面的镜像副本已删。没有碰 `~/Project`、`~/tools/wt`（只是使用）、`~/999_`。没有连 GitHub，远程用的是本机的假远程。

## 要验证什么

1. **真实技术栈**：受限环境加专用 Docker，撑不撑得住 Java、Node、数据库、浏览器测试——含装依赖、走代理。
2. **对话方式**：需要人坐在窗口前和 AI 对话的方式，在受限环境里能不能正常用。之前所有试验都是脚本自动调用。
3. **真正的项目结构**：在裸仓库加工作目录、`.git` 只放开几处的结构里，跑一张 `implement` 工单。S0 当时用的是一个普通目录。

顺带验证了审查报告的另外两条：让 wt 用工具包自己的模板（一般 12）；把 `commondir`、`gitdir` 两个小文件锁成只读（一般 4）。

## 试验项目

`/tmp/sop-spike-s9/proj`：用 wt 建的裸仓库加工作目录，三个目录 `main`、`feat-stack`、`ticket-stack-1`。受限环境只放进 `ticket-stack-1` 这一个工作目录；`.git` 用 S2 的「细的放法」，再加上这次新锁的两个小文件。

## 一、真实技术栈

### 先验证了 wt 的模板

审查人指出：`wt init` 会把 wt 自带的模板复制进项目，并马上带着登录凭据执行其中的准备脚本，那一份会安装依赖。克隆一个已有项目时，这就是特权侧在运行项目代码。

做法：给 wt 指定一份工具包自己的模板（环境变量 `WT_TEMPLATE`），里面的准备脚本只链接 `.env`，删除前脚本什么都不做。为了看得出效果，我在假远程的项目里放了一个「一装依赖就会留下记号」的文件。

结果：`wt init`、两次 `wt new` 执行的都是工具包模板里的那一份；记号没有出现。**这个办法有效，不用改 wt。**

### 专用 Docker

照 S2 的做法另起一个（启动命令这次存下来了，S2 当时没存）。

| 试的事 | 结果 |
|---|---|
| 启动 | 起来了，版本和原来的一样（29.9.3），数据另放 |
| **走代理联网拉镜像** | **可以。** 拉一个小镜像 4.6 秒。做法：这个后台程序本身在电脑的网络里，把代理地址用环境变量给它就行 |
| 从原 Docker 复制镜像（导出再导入） | 可以。650MB 的 4 秒，3.65GB 的 20 秒 |

### Java 加 PostgreSQL

一个最小的 Maven 项目：一个往数据库记账的类，一个连真数据库的测试。测试用 Testcontainers（一个在测试里临时起数据库容器的库）。都在受限环境里执行。

| 试的事 | 结果 |
|---|---|
| Java 25、Maven 能不能用 | 能。只读地放进去 |
| **装依赖（走代理下载）** | **可以。** 第一次 44 秒，下载了 38MB，存在受限环境专用的缓存目录里 |
| 编译 | 可以 |
| **测试里起数据库容器** | **可以。** Testcontainers 先起了它自带的清理容器，再起 PostgreSQL，0.7 秒起好 |
| 测试结果 | 1 个测试，通过。整轮 10 秒 |
| 测试结束后容器有没有清掉 | 清掉了 |
| 构建镜像并运行 | 可以 |

要注意的三处：

- **Maven 不认环境变量里的代理。** 要另写一份设置文件放进它的缓存目录。pnpm 认。
- **Testcontainers 要多告诉它一句专用 Docker 的通道在哪**（一个环境变量），否则它会去找默认位置。它的清理容器要把 Docker 的通道再挂进容器里——这正是审查人担心的地方，实测没问题，因为通道就在专用 Docker 的白名单里。
- **我自己出的一个错**：第一次把测试类起名叫 `LedgerIT`，Maven 默认不执行这种名字的测试，结果「构建成功」但一个测试都没跑。我是看到输出里没有「跑了几个测试」才发现的。对工具包的提醒：**门禁不能只看「成功」两个字，要核对跑了几个测试**；测试数是 0 应当算不通过。

### Vue 加浏览器测试

一个最小的 Vue 页面（记一笔、看合计），一个浏览器测试：打开页面、记一笔、核对合计、和基准截图比对。

| 试的事 | 结果 |
|---|---|
| **装依赖（pnpm，走代理）** | **可以。** 12 秒 |
| 构建 | 可以 |
| **在固定的容器镜像里跑浏览器测试**（经专用 Docker，把工作目录挂进去） | **可以。** 1.5 秒 |
| 第一次：生成基准截图 | 生成了，文件属主是当前用户 |
| 第二次：和基准比对 | 通过 |
| 第三次：把标题改成红色再比对 | **不通过**，报出 587 个像素不同。说明比对是真的在起作用 |
| 用 Compose 起一套数据库、等它就绪、在里面执行一句查询、从受限环境连它映射出来的端口、再停掉 | 都可以 |

要注意的三处：

- **pnpm 把它的包仓库建在了工作目录里面**（`.pnpm-store`）。原因是受限环境里工作目录是单独放进去的，pnpm 把它当成了一块单独的盘。后果是每个工作目录各下载一遍，而且这个目录会被 Git 看到。工具包要明确指定 pnpm 的包仓库位置，并把它加进忽略名单。
- **Compose 是一个插件**，装在用户 Docker 目录下的另一个子目录里。受限环境里要把这个子目录只读地放进去，并用一份专用的配置告诉 Docker 去哪找它。
- 这台电脑没有装新式的镜像构建器，用的是旧式的，会打一行提示。能用。

### 这一部分的结论

**受限环境加专用 Docker，撑得住第一版要用的技术栈。** 审查人最担心的那种情况（要退回「单独的系统用户」这个保底方案，重做机器层）没有出现。受限环境里要多放进去的东西比 S2 时多，清单见下面「对设计的影响」。

## 二、对话方式

用户不在场，所以分两步：我先用一个程序模拟终端，替人送按键、读屏幕；再留一条命令给用户亲手试。

### 模拟终端的结果

| 试的事 | 结果 |
|---|---|
| 在受限环境里启动 Claude Code 的对话窗口 | 起来了，界面正常显示 |
| 打一句中文并回车 | 收到了，AI 回答了要它回答的那四个字 |
| 输入 `/cost` 看花费 | 显示了，0.11 美元 |
| 输入 `/exit` 退出 | 正常退出 |
| **关掉受限环境，重开一个，接着上一次的会话** | **可以。** 问它上一次让它记住的暗号，答对了 |
| 两种放法：照以前那样「脱离终端」；不脱离终端 | 两种都能用。第一次用的前一种，续接用的后一种 |

「脱离终端」是以前为了防一种老办法（受限环境里的程序往终端里塞按键）加的设置。这台电脑的内核已经把那种办法禁用了（`dev.tty.legacy_tiocsti = 0`），所以对话方式下可以不脱离终端。

### 新发现：全新的状态目录第一次打开，会先出三屏

设计里每个项目给每个 AI 工具一个专用的状态目录。它是全新的，所以第一次打开对话窗口时，Claude Code 会依次显示：

1. 选界面配色。
2. 一段安全提示，按回车继续。
3. 「你信任这个文件夹吗」。**默认选中的是「不，退出」**，直接回车就退出了，要先按一下方向键。

这三屏是英文的，小白看不懂，第三屏还容易按错。过了一次之后会记住，续接时不再出现。自动调用时没有这三屏。

对工具包的含义：流程命令在第一次启动对话窗口之前，要替用户把这三屏过掉（预先写好状态目录里对应的设置，或者先自动过一遍）。这次没有试哪种办法可行。

### 留给用户做的

模拟终端替不了真人。请在**你自己的终端**里（不是在这个对话里）执行：

```
bash /tmp/sop-spike-s9/chat.sh
```

它会在受限环境里打开对话窗口，接着我试验时的那个会话，不会再出那三屏。请试这几样，然后告诉我有没有不对劲的：

- 打两三句中文，看输入和显示正不正常。
- AI 回答到一半时按 Ctrl-C（或 Esc），看能不能打断。
- 把终端窗口拉大、拉小，看界面会不会乱。
- 输入 `/exit` 退出。

花费几美分。电脑重启过的话这条命令就没了，告诉我，我重新备。

### 用户亲手试的结果

用户在自己的终端里执行了那条命令，发来一张截图（2026-11-17）。从截图能确认的：

- 对话窗口在他真实的终端里正常打开了，标题、工作目录、输入框、底部的状态行都显示正常，中文没有乱码。
- 接上了我试验时的那个会话：前面两问两答都显示出来了。
- 没有再出首次启动的那三屏。

随后他亲手试了打字、打断、拉窗口、退出，反馈是：**都正常，但是显示未登录**。

「未登录」出现在哪一屏，他当时没有说；后来（2026-11-17）说明了：出现在用上面那条命令打开对话窗口、跳过了文件信任那几屏之后。下面是他说明之前我做的排查：我在同样的受限环境里用模拟终端看了状态页和用量页（没有给 AI 发消息），没有找到这几个字；状态页写的是「凭据来自环境变量 `ANTHROPIC_AUTH_TOKEN`」。所以它出现的位置**没有复现，原因是推测**：受限环境里没有放进 Claude Code 的账号登录信息，密钥是靠环境变量给的，工具于是认为「没有登录账号」，但照常能用（他打字有回答就是证明）。这和 `核对-四个AI工具的本机情况.md` 里记的是同一类事：工具自己的「是否已登录」在这台电脑上不准。

对工具包的含义：小白看到「未登录」会以为坏了。小白手册要说明这是正常的；适配器判断能不能用，只能真的发一次最短的调用（设计书 10.2 已有这一条）。

### 这一部分的结论

**对话方式在受限环境里能用，会话能续接。** 模拟终端试过；用户本人随后也亲手试了打字、打断、拉窗口、退出，都正常（见上一小节。这一句原来写的是「真人的手感、打断、拉窗口还没有验证」，是用户试过之后没有更新，第四轮审查指出）。首次启动的三屏要由流程命令处理。

## 三、在真正的项目结构里做一张工单

### 怎么做的

- 项目就是上面那个：裸仓库加工作目录，后端是第一部分那个 Java 加 PostgreSQL 的最小例子。
- 技能四个，原样复制，做之前、做之后各和来源比对一次，都一致。
- 项目规则里预置了技术决定和测试切入点，写了「不要推送」「不要建别的分支」「那行只读报错是正常的」。
- 一张小工单：给账本加一个「按说明查找」的方法，五条验收标准，其中一条有点刁（关键字里有 `%` 和 `_` 时要当普通字）。
- 规划先提交到功能分支并推送，工单分支从功能分支开出。受限环境只放进工单的工作目录。
- 一次自动调用：`/implement <工单文件>`，上限 3.5 美元。

这张工单要 AI 自己在受限环境里编译、经专用 Docker 起数据库跑测试，所以它同时也是「让 AI 亲自用一次专用 Docker」（S2 留下没做的那一项）。

### 结果

**走通了。** 140 秒，1.20 美元，AI 中途没有问问题。

| 核对 | 结果 |
|---|---|
| 提交 | 1 个，在工单分支上；工作区干净 |
| 改了哪些文件 | 3 个：账本类、它的测试、工单文件（把验收项打了勾）。没有改别的 |
| 我在受限环境里重跑全部测试 | 5 个测试，全部通过，每个都真的起了数据库 |
| `main`、功能分支的指针 | 没被动过 |
| 工作目录的数量、分支 | 没有多出来的 |
| 新锁的 `commondir` | 内容没变 |
| 技能文件 | 和来源一致 |
| 会话记录里越界的命令 | 0 条 |
| 调用的技能 | `tdd` 2 次（按名字调用成功）、`code-review` 1 次 |
| 帮手 | 2 个，都是自查派的（规范、规格各一个） |
| 余额不足的报错 | 这次 0 次 |
| 专用 Docker 里留下的容器 | 没有 |

**把 `commondir`、`gitdir` 锁成只读之后，提交照常成功。** 受限环境里试着改这两个文件，都报只读。审查人指出的那处漏洞，这个修法可用。

**自查拿什么做比较起点**（审查报告的疑问 2）：这一次它比的是「还没提交的改动」（`git diff HEAD`），也就是只审了这张工单自己的改动，没有把功能分支上前面的内容带进来。审查人担心的「从 `main` 比起，越往后越贵」这次没有发生。只观察了一次；它是 AI 自己选的，换一次可能不同。

**主链上「实现」这一步，在真正的项目结构、真实技术栈、原样技能、专用 Docker 这几样凑齐的情况下走得通。** 追问、规格、工单三步在这种结构里还没走过。

## 对设计的影响

下面这些已写进设计书 v0.5（6.3、5.6、4.3、14.2、第 19 节）：

1. **wt 一律用工具包自己的模板**（`WT_TEMPLATE`）。模板里三个脚本：准备脚本只链接 `.env`；删除前脚本什么都不做；忽略名单照 wt 原样。
2. **受限环境的 `.git` 放法再锁两个文件**：工作目录登记里的 `commondir` 和 `gitdir`。隔离自检加上这一项。
3. **受限环境里要放进去的东西**，比 S2 时多了这些：
   - 只读：JDK、Maven、Node、Docker 的命令行程序、Compose 插件所在的目录。
   - 可写：每个项目一份依赖缓存（Maven 的、pnpm 的），放在工作目录外面，映射到主目录下它们习惯的位置。
   - 环境变量：Java 的位置、专用 Docker 的通道、给 Testcontainers 的通道位置、Docker 的配置目录。
   - Maven 的代理要写在它的设置文件里。
4. **专用 Docker 联网拉镜像**：把代理地址用环境变量给它的后台程序。设计书 6.5 里「代理还没有做」可以改掉。
5. **pnpm 的包仓库位置要明确指定**，并加进忽略名单。
6. **门禁要核对测试数**，0 个测试算不通过。
7. **对话窗口首次启动的三屏**要由流程命令替用户过掉。
8. **对话方式下不脱离终端**，前提是内核禁用了往终端塞按键；隔离自检查一下这个开关。
9. 项目规则里「那行只读报错是正常的」这句要保留，这次 AI 没有被它绊住。
