## 设计里最容易记错的几点

- 特权侧（流程命令，拿着登录凭据）不运行任何项目代码；AI 和一切项目代码都在读不到凭据的受限侧运行。「读不到凭据」是必须做到的，没有退路。
- 凭据不只是文件：系统钥匙串的通道、SSH 代理的通道、环境变量里的密钥都算。所以专用 Docker 不能为了按容器限资源而接上用户的会话通道。
- 进度是单独分支 `sop/journal` 上的事件日志；一个 `sop` 进程替所有工单攒批写。只有明确的「重新打开」事件才让记录失效。
- 每张工单一个 PR，目标是功能分支；落后时用合并，不变基。仓库只允许压成一次提交的合并，所以**任何东西都不能靠提交编号跨过一次合并去对**。
- 守门检查凭「归属、路径、内容指纹、序号」的放行事件放行；同一路径只认序号最大的那条；工单上的放行等合进功能分支后才写（v0.9）。
- **被条件跳过的检查，GitHub 算「成功」；转正式的那一瞬间合并状态也显示「可以合并」。** F19 只认真跑完的全档记录。
- 受限环境里 `.git` 要锁死三个小文件；运行中才建的目录，特权侧先核对再碰。
- 受限环境按步骤的种类放（6.3 的表）。只有工单上的实现由 AI 自己提交；规划类和起草规范的步骤 AI 不提交，提交内容也只读。
- AI 工具的状态目录按会话从模板现建（5 项设置），不共用；用完封存成只读。
- 专用 Docker：每个项目一个用户级后台服务（第三段改成用时才起）；资源上限设在项目的分组上，不能按单个容器设；容器默认直接上网。**它的视野里的「只读」挡不住有心的容器**（实测，含 `.git`），所以特权侧的状态放在 `~/tools/sop/state/<项目名>/`，不在项目根下；wt 钩子、`.git/config` 这几个挪不出去的，特权侧每次用之前核对。
- 放行：工单上的放行（验收后的截图）等工单合进功能分支后才写；所有归属名带序号、不重复；F19 看全档、快档、守门三项。
- 公开仓库的守门检查用的 `pull_request_target`，GitHub 2026-12-02 起默认禁用，要靠仓库的事件规则放开（W40，没实测）。
- wt 一律带 `WT_TEMPLATE` 用工具包自己的模板。
- 门禁不能只看「成功」，要核对跑了几个测试。可改范围检查按不转义的路径比。
- 线上密钥放在限定只有 `main` 能用的部署环境里；仓库级不放任何密钥。
- 不开通 GitHub 付费计划：公开仓库用分支保护，私有仓库由用户在网页上手动点合并。
- 环境迁移是「规定位置装新的，旧的由用户选留还是卸」；Q4 要停掉用卷的容器，出错一定起回来。
- SOP 用到的一切都装在 `tools` 目录下；「不占系统盘」靠主目录单独分区，`~/tools` 永远是普通文件夹。pnpm 的位置用 `pnpm_config_` 开头的变量指定。
- 一个项目同一时刻只用一个工具包版本；有进行中的功能时只能换修补版；技能换版本算大版本。
- T14 解决冲突后回 T4。
- 部署相关的开发整个暂缓（W23）。
- 技能文件一个字都不改。
- 自动调用的 AI 有问题要问时会「正常结束、什么都没做、交回一个问题」；它说「做完了」不算数（第一段又碰到一次：记忆没写成，它说记好了）。
