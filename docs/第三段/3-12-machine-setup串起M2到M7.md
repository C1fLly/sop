## 做了什么

### `machine/setup.py`，命令 `sop machine setup [--recheck]`

- 按 4.5 的先后做 M2、M3、M4、M5、M6、M7。每一步打一行「【第 i 步，共 6 步】M? 名字」，做完跑出口检查，过了说「做好了，出口检查通过」，再做下一步。
- **一步没过就停**：说「停在『M? 名字』：这一步的出口检查没通过，后面的步骤先不做（后面几步要靠它）」，加上那一步自己的原因（哪样没装上、哪一项不通过），再说「按上面说的处理好之后，再执行一次 sop machine setup：做好了的会跳过，从这一步接着做」。退出码 1。
- **已经合格的跳过**：每一步先跑它的出口检查，合格就说「已经合格，跳过」，什么都不做：
  - M2：清单里第零步、这一步的工具（第零步的 git、curl、uv 也核对，缺了顺手补）都符合清单，缓存目录在，`~/.bashrc` 里那一段是最新的。
  - M3：`ghsetup.check()`；M5：`wtsetup.check()`；M7：`globalrules.check()`。
  - **M4（替用户定的，可否决）**：上次在 `sop machine setup` 里自检通过后记下 Claude Code 的「样子」：程序的实际位置、版本（`--version`，不花钱）、登记文件 `config/ai/claude.env` 的编号、大小、修改时间（不读、不记密钥）。下次这几样都没变，而且不花钱的那一半检查（文件在、只有自己能读、有地址有密钥）都对、机器级登记 `config/tools.json` 里最近一次自检是通过的、通过时的版本就是现在的版本，就**不再真调**，说「这次不再真调 AI（每调一次花几美分）。想再真调一次：sop machine setup --recheck」。哪一样变了（重填了密钥、Claude Code 升级了、推进流程时自检失败过）就真调一次。
  - **M6**：系统组件登记（`config/system.json`，只在隔离自检通过时写）和现在一样，就不再跑；变了（系统升级了）或还没登记过就跑。和 `sop` 推进流程之前的判断（3-07 的 `gate`）是同一条。
  - `--recheck`：M4 也真调一次、M6 也重跑一次，不管变没变。
- **中途断了接着做**：进度记在 `~/tools/sop/config/setup.json`（0600）：每一步开始前记下「正在做哪一步」，做完（通过或没通过）才清掉；各步通过的时间、M4 的「样子」。下次执行，先说「上次执行 sop machine setup 时，『M? 名字』那一步没做完就断了（几点开始的）。这次从头逐步核对：已经合格的跳过，从没做完的那一步接着做」。然后照样从 M2 起逐步核对：前面做好的出口检查一过就跳过，所以自然从断的那一步接着做。各步本来都能重做（安装脚本先放旁边再换名，登录、登记、写规则都是先查再做）。按 Ctrl+C：说在哪一步停了、再执行一次接着做，退出码 130。
- **同一时刻只能有一个**：文件锁 `config/setup-running.lock`（进程怎么退出锁都会放开）；第二个说「另一个窗口正在执行 sop machine setup（进程几号、几点开始）」，什么都不做，退出码 3。
- 结尾：都通过时说「这台电脑装好了：M2 到 M7 都通过了」，每一步是「本来就合格」还是「这次做的」，这次在 AI 自检上花了多少（工具报告的金额），下一步执行 `sop machine doctor` 看体检报告，再 `sop project new` 或 `sop project clone`。
- 自己的话都立刻刷到屏幕上（安装脚本、gh 直接往终端写，不刷的话先后会乱，沙箱里看到过）。
