## 做了什么

新模块 `machine/migrate/inventory.py`（包 `machine/migrate/`，Q2 到 Q6 以后也放这里）。**只读**：只看、只量、只问 Docker「有什么」，不装、不删、不停、不起任何东西。

1. **认出几种不在规定位置的 Docker**（一台电脑上可以同时有几份，各列各的）：
   - `docker.io`（Ubuntu 软件源）、`docker-ce`（Docker 官网）：按 `dpkg-query` 看装了哪些包；
   - 免管理员但位置不对：`~/bin` 里有 `dockerd`/`rootlesskit`、`~/.local/share/docker` 在、或者用户级服务 `docker.service` 的启动命令不指向 `~/tools/docker`（规定位置那份自己的服务不算）；程序不在 `~/bin`、由 `docker-ce-rootless-extras` 带的也认得出；
   - snap 版（`/snap/docker`、`/var/snap/docker`）、Docker Desktop（`docker-desktop` 包、`~/.docker/desktop`、`/opt/docker-desktop`）：如实列出，写明第一版不自动带走、不自动卸载（4.8）；
   - 多认了一种「以前卸过、东西还留着」（软件包卸了只剩设置 `rc`，或者 `/var/lib/docker` 还在）。
2. **量大小**：系统自带的连 `/var/lib/containerd` 一起量；每处写明占不占系统盘。系统盘上那两个目录普通用户读不了，免管理员那份的数据目录里也有容器内部账号的目录读不全：给了 `--admin` 才用 `sudo du` 量全，没给就写「至少多大」。
3. **列旧 Docker 里的东西**（它在运行时）：每个镜像（大小、属于哪个项目、最近一次用、哪些容器在用）、每个数据卷（大小、属于哪个项目并写明是「编排文件里写的 / 看用它的容器 / 看名字猜的」、匿名卷、最近一次用：取用过它的容器最后一次起停的时间，用过它的容器都删了就明说看不出来）、每个容器（在不在运行、项目、用哪些卷、容器里没放进数据卷的改动多大，到 1 MB 才在报告里提醒）。调 docker 命令时总是明说通道（`--host`）、用一个现建的空设置目录（`--config`），不靠也不碰终端里的默认指向和 `~/.docker`。
4. **残留清单**（Q6 逐项核对用），只记现在真有的：
   - 软件包：用 `apt-get -s purge --autoremove <Docker 的包>`（只模拟，普通用户就能跑，不改任何东西）减去本来就会被自动清掉的，算出「卸它会连带卸掉哪些随它自动装进来的」；`apt-get` 用不了时退回第一段实测的那几个并写明是估的；
   - 系统服务 `docker.service`、`docker.socket`、`containerd.service`（containerd 不跟着卸时不算）、用户组 `docker`、`/var/lib/docker`、`/var/lib/containerd`、`/etc/docker`、`/etc/default/docker`、`/etc/systemd/system/docker.service.d` 等、`/etc/containerd`；
   - 指向 `download.docker.com` 的软件源文件（或 `sources.list` 里的那几行）和它用的钥匙文件；
   - `daemon.json` 里另指的数据目录（系统的、免管理员的都看）；
   - 免管理员的：先数据目录（4.8：先删数据、再删程序）、`~/bin` 里每个 Docker 程序、用户级服务登记文件和它的附加目录、开机自启的链接、AppArmor 那条系统规则（只有这一项要管理员密码）。
5. **别的工具**（uv、nvm、Node、pnpm、gh、wt）另有一份不在规定位置的：沿用体检的找法（`locate.find_others`），再写明是 apt 装的（`dpkg-query -S`）、snap 的、主目录里的、还是系统目录里自己放的，卸载要不要管理员密码。
6. 大白话报告 `describe()`；`save()` 存到 `~/tools/sop/config/migrate/inventory.json`（0600，先过 `guard_home`）。手动跑：`python3 -m machine.migrate.inventory [--admin] [--json] [--save]`，默认不用 sudo、不存。**没接进 `sop machine migrate`**（命令留给 3-31，`machine/cli.py` 原来就写着「3-31 起」）。

单元测试 `tests/unit/test_migrate_inventory.py` 26 项。用的命令输出不是凭空写的：先在三台全新的虚拟机里造了三种旧 Docker、取了真命令的原样输出放进 `tests/fakes/migrate/{system,ce,rootless}/`（脚本 `tests/vm/migrate-q1.sh`、`migrate-q1-guest.sh`），测试里再用临时目录造出「系统」的目录和文件。每项测试都核对清点只跑了只读的命令（`dpkg-query`、`apt-get -s`、`apt-mark showauto`、`systemctl show`、`du`、docker 的 `ls`/`inspect`/`system df`）。

## 结果

- 单元测试 399 → 425 项，流程沙箱 43 个剧本，总检查 95 个样例，全部通过（见下）。
- **虚拟机里用正式代码清点**（`tests/vm/migrate-q1.sh <名字> --inventory [--admin|--json]`）：`q1sys`（docker.io 29.1.3）、`q1ce`（docker-ce 29.10.0）、`q1rl`（官方一条命令的免管理员 29.10.0），每台三遍（不用管理员、`--admin`、`--json`），31 项检查全对：每遍正常结束；旧的那几处（45 到 79 项）大小、修改时间、权限一样都没变；服务和容器的状态没变。清点结果和放进去的东西对得上（3 个镜像、3 个卷、2 个容器，项目、在不在用、3.2 MB 的容器改动；docker.io 残留 16 项、docker-ce 19 项、免管理员 16 项）。
- **旧的停着时不去连**（`--stopped`，只停 `docker.service`、通道 `docker.socket` 还在听）：清单写明「没在运行，要它运行才列得出」，清点之后 `docker.service` 仍停着；对照：随手敲一条 `docker version`，它马上被系统自动起来了。所以 Q1 不能「顺手看一眼」停着的系统 Docker。
- 本机：在整个系统只读、`/run/user/<编号>` 盖掉（连不到用户的 Docker）的 bubblewrap 里跑了一遍（不用管理员）：Docker「没找到不在规定位置的」（用户的 Docker 在 `~/tools/docker`，服务指向它，正确地不算）；别的工具列出 `~/.local/bin/uv`、`~/.nvm`（Node、pnpm 在它里面）、`~/.local/share/pnpm`、`/usr/bin/gh`（apt 装的），和 3-06 体检、3-08 的记录一致。
- 三台虚拟机用完删了。虚拟机里那几遍跑的是后来两处小改（`daemon.json` 另指的数据目录、报告里「在 … 里面」写成 `~`）之前的代码；这两处只有单元测试，本机只读那一遍是改之后的。

虚拟机里实测到的几样事实（3-31 到 3-35 用得上）：

- `apt-get -s purge --autoremove docker.io` 连带 7 个：containerd、runc、bridge-utils、pigz、ubuntu-fan，**加上 dnsmasq-base、dns-root-data**（第一段只认出前 5 个）。docker-ce 连带 pigz。
- Docker 官方软件源已经有 Ubuntu 26.04（resolute）：照官网现在的写法（`/etc/apt/sources.list.d/docker.sources`、`/etc/apt/keyrings/docker.asc`）装上 docker-ce 29.10.0、containerd.io 2.4.2。docker-ce 会带 `/etc/default/docker`、`/etc/containerd`。
- 现在的官方免管理员安装脚本放进 `~/bin` 的是 11 个程序（没有 vpnkit、rootlesskit-docker-proxy 了），服务登记文件的启动命令是 `~/bin/dockerd-rootless.sh --iptables=false`，还建了一个叫 `rootless` 的默认指向（context）。
- containerd 存镜像的新版本里，自己 `docker commit` 出来的镜像也带 `RepoDigests`，**看不出镜像是不是从网上拉的**；`image inspect` 的 `Size` 是压缩的内容大小（busybox 2.2 MB），`docker system df -v` 给的是解开以后的（6.8 MB），清单用后者。
- `/var/lib/docker` 权限 0710、`/var/lib/containerd` 0700：不用管理员只量得到 4 KB。

## 和设计书的出入（留给 3-48）

1. 4.8 Q1 没说旧的 Docker 停着时怎么办。实测系统自带的那种一连通道就被系统自动起来，所以 Q1 停着就不连、写明列不出；要不要先起它（这算动了旧的）、怎么问小白，留给 3-31 的命令。
2. 4.8 Q1「脚本」执行，没说要不要管理员密码。现在默认不用，`--admin` 才 `sudo` 看系统盘上 Docker 的目录和（不在 docker 组时）镜像数据卷；`sop machine migrate` 里怎么问，留给 3-31。
3. Q6 的残留清单比 4.8 列的多：`docker.socket`、`/etc/default/docker`、`/etc/systemd/system/docker.service.d` 一类的附加设置、`/etc/containerd`；随装的包用 `apt-get -s` 现算（多出 dnsmasq-base、dns-root-data）；免管理员那种的残留（`~/bin` 的程序、用户级服务的登记文件和附加目录、开机自启的链接、AppArmor 规则）4.8 只写了「停掉服务、删程序和数据目录」。
4. 多认了一种「以前卸过的 Docker 留下的东西」（4.8 表里没有）。
5. 清单存在 `~/tools/sop/config/migrate/inventory.json`（4.8 只说「清单已生成」）。
6. 镜像「从网上拉的、可以不带」判断不出来（见上），报告里不写这一句；Q3 的建议要另想（例如看镜像名里有没有仓库地址、或者问小白）。
7. 容器里没放进数据卷的改动不到 1 MB 不在报告里提醒（在运行的容器总有几 KB 零碎），清单里照记。

## 自己出的错

1. 第一版按镜像有没有 `RepoDigests` 判断「从网上拉的、不带也行」，虚拟机里取回的输出一看，自己提交出来的镜像也有，判断是错的，删了。
2. `apt-get` 用不了时的退路，第一版要求「装着的」包里有，可是查装没装的那条命令根本没查 bridge-utils 这些包，退路永远少三个；单元测试抓到，改成只看 `apt-mark showauto`（它本来就只列装着的）。
3. 「以前卸过、东西还留着」那种，containerd 还被别的软件用着时，第一版仍把 `/var/lib/containerd` 记成要删的；单元测试抓到，改了。
4. 本机那一遍报告里「在 … 里面」显示了完整的主目录路径，改成 `~` 开头。
5. 虚拟机里造 docker-ce 时写了 `sudo -E curl`，`sudo` 提示 `-E` 被忽略（取钥匙文件仍然成功），不影响结果；造的环境里还多放了一个代理设置 `/etc/apt/apt.conf.d/99q1proxy`，是造环境用的，不是 Docker 的东西，清单里正确地没有它。
