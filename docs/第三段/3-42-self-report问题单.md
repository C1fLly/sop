# 3-42 `sop self report`：把工具包自己的问题打成问题单

2026-11-22，主控窗口派的子代理做的。没动隔离、放行事件、事件日志（事件日志只读本机那份，`kernel/journal.py` 没改）；没碰 Docker、没用 sudo；**没碰真 GitHub**（只用假 `gh`）；**没调用 AI，0 美元**。

## 做了什么

设计书 16.5 第 1 条：流程命令或维修窗口判断是工具包自己的问题时，执行 `sop self report`，把现象、相关日志、工具包版本打成一份问题单，登记到工具包仓库，日志先去掉密钥。

| 文件 | 内容 |
|---|---|
| `kernel/redact.py` | **去掉密钥和个人信息**，只用标准库。一条规则一种写法，按先后做（见下） |
| `kernel/selfreport.py` | 命令本身：收集、抹掉、存草稿、问一句、`gh issue create` 登记 |
| `kernel/cli.py` | `sop self report` 在找项目之前分派（不在项目里也能用，例如 `sop machine setup` 出的错） |
| `kernel/commands.py` | `self report` 从 `PLANNED` 挪到 `DONE` |
| `tests/unit/test_commands.py` | 分派核对加上 `kernel.selfreport.cli` |
| `tests/fakes/gh/gh` | 假 gh 加 `issue create`（`--body-file -` 从标准输入读，正文超过 65536 个字照 GitHub 那样报错）、`issue list`，问题单记在 `$FAKEGH_HOME/issues.json`；`auth.json` 里有 `token` 时 `auth token` 打出它 |
| `tests/unit/test_self_report.py` | 19 项（见「验证」） |

### 用法

```
sop self report [--text <一句话说明>] [--log <日志文件>]… [--yes]
sop self report --send <草稿文件> [--yes]
```

1. **收集**：小白自己的一句话（在终端里又没给 `--text` 时问一句，可以直接回车跳过）；工具包版本（正在运行的这一份的提交编号、有没有没提交的改动、在不在装好的版本目录里）；电脑的几样版本（系统、内核、Python、Git、gh、bubblewrap）；**在项目里时**再加：主线 `sop.json` 声明的工具包版本、公开还是私有，本机事件日志里最近 10 条「停下来的步骤」和「工具包问题」（只读本机那份，不联网），运行日志 `state/<项目名>/runs/error-*.txt` 里最近 3 份（流程引擎碰上工具包自己的代码出错时写的）的最后 4000 个字；`--log` 给的日志最多 5 份、每份最后 8000 个字。
2. **抹掉**：每一段先抹再截（截断不会把一个密钥切成两半漏出去），整份再抹一遍。
3. **草稿**存在 `~/tools/sop/reports/<时间>.md`（目录 0700、文件 0600），第一行是标题。打出草稿在哪、抹掉了哪几类各几处，并说清「自动抹不保证抹得干净，登记之后谁都看得到，请打开草稿从头看一遍，项目名、文件名、报错里带出来的代码也会公开，想改就直接改」。
4. **问一句**：「确认把这份问题单登记到 GitHub 上公开的 C1fLly/sop 吗？任何人都看得到。要登记输入 y，不登记直接回车」，默认不登记。**不在终端里又没加 `--yes`**（例如维修窗口替小白执行）只存草稿，说清看过之后执行 `sop self report --send <草稿> --yes`。
5. **登记**：`gh issue create --repo <所有者/仓库名> --title … --body-file -`（小白自己的 gh 登录）。登记之前把草稿**再抹一遍**（小白可能改过草稿、往里加了东西），抹到了就改进草稿并说一句。登记好记 `<草稿>.sent.json`（网址），同一份不重复登记；打出网址，再说一句修好后用 `sop self upgrade` 换上。

**登记到哪个仓库**：环境变量 `SOP_REPORT_REPO`（只给自测用）→ 在项目里时主线 `sop.json` 的 `toolkit.repo` → `SOP_TOOLKIT_REPO` → 默认的公开仓库 `https://github.com/C1fLly/sop.git`（`kernel/projectnew.py` 的 `DEFAULT_REPO`）。不是 GitHub 上的仓库（例如流程沙箱里的本地仓库）就只存草稿，说可以自己发给维护工具包的人。

### 去掉密钥：规则和先后

| 规则 | 抹什么 | 换成 |
|---|---|---|
| `known` | **运行时**读出来、知道值的：`~/tools/sop/config/ai/*.env` 里的**每一个值**（服务地址也算，可能透露用的是哪家服务）、终端里名字像密钥的环境变量的值（8 个字以上）、`gh auth token` 的值（gh 从自己的登记里读，不联网）；连同 JSON 转义、网址编码两种写法。值不写进代码，6 个字以下的不按值抹 | `[已抹掉：密钥]` |
| `private_key` | 私钥块：完整的 BEGIN…END；没有结尾的（只抹 BEGIN 和后面连着的像 base64 的行、PEM 头、空行，碰到别的行就停）；只剩后半截的（连着几行像 base64 的加 END） | `[已抹掉：私钥]` |
| `auth_header` | `Authorization:`、`Proxy-Authorization:`（`Bearer`、`Basic`、`token` 等方式都认，JSON 里的也认），单独出现的 `Bearer <12 个字以上>` | `[已抹掉：凭据]` |
| `url_userinfo` | 网址里的 `账号:密码@` | `[已抹掉：账号密码]@` |
| `anthropic` | `sk-ant-…` | `[已抹掉：密钥]` |
| `openai` | OpenAI 风格 `sk-…`、`sk-proj-…`（不含 `sk-ant-`） | 同上 |
| `github` | `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_`、`github_pat_` | 同上 |
| `aws`、`google`、`slack`、`jwt` | `AKIA`/`ASIA`、`AIza`、`xox?-`、`eyJ….eyJ….…` | 同上 |
| `assignment` | 名字像密钥的赋值：名字按 `_`、`-`、`.`、大小写分开后有 key、token、secret、password、pass、pwd、auth、credential、cookie 等词的（`PWD`、`OLDPWD`、以 Error/Exception/Warning 结尾的类名除外），写法 `KEY=值`、`export KEY='值'`、`"apiKey": "值"`、`secret: 值`、`--token 值` | 只抹值 |
| `long_token` | 兜底：32 个字以上、大写小写数字都有的长串（提交编号、会话编号只有小写和数字，不抹） | `[已抹掉：疑似密钥]` |
| `email` | 邮箱（`git@github.com` 这种 SSH 写法除外） | `[已抹掉：邮箱]` |
| `home` | 主目录（账号记录里的和 `HOME` 两个） | `~` |
| `host` | 本机名 | `<本机名>` |
| `user` | 本机用户名（账号记录、`USER`、`LOGNAME`，3 个字以上，整词） | `<用户名>` |
| `name` | `~/.gitconfig` 里设的名字和邮箱（只读 `git config --global --get`） | `[已抹掉：名字]` |
| `project` | **私有**项目的名字（公开项目的名字本来就公开，不抹） | `<项目名>` |
| `ip` | IPv4 地址（`127.*`、`0.0.0.0` 除外） | `[已抹掉：IP 地址]` |

先后有讲究：知道值的最先（最准）；Anthropic 在 OpenAI 风格之前；赋值在各家前缀之后（前缀抹完，值已经是 `[已抹掉…]`，不重复算）；本机名在用户名之前（本机名常带着用户名，例如 `alice-pc`）；兜底的长串放在各家前缀之后。抹过的再抹一遍一个字不变（单元测试核对），所以登记前再抹一遍不会越抹越乱。

### 个人信息怎么处理（自己判断的，写明理由）

任务要求「本机用户名、邮箱也要提醒或抹掉」。定的是**能认出来的一律抹掉，抹不了的在问之前提醒**：

- **抹掉**：本机用户名、主目录、本机名、邮箱、`~/.gitconfig` 里的名字、IP 地址（127.* 除外）、私有项目的名字。理由：问题单登记在公开仓库上，任何人都看得到；用工具包的不只是这位用户，别人的用户名可能就是真名；这些对修工具包几乎没用（路径换成 `~` 之后照样看得出是哪个文件）。事件日志里每条都带着本机名，不抹就公开了。
- **和 3-41 的出入**：用户 2026-11-22 定「工具包仓库 `docs/` 里路径中的本机用户名 `sanchuanzl` 不抹」。那是工具包仓库自己的文档，问题单是另一回事（每次都是新内容、可能是别的小白的），所以这里照抹。
- **抹不了、只提醒的**：项目名（公开项目）、文件名、报错里带出来的项目代码片段、小白自己写的话里的东西。打出草稿时说清楚，请他从头看一遍。
- **GitHub 账号**：问题单是用小白自己的 gh 登录建的，账号名必然公开（谁建的问题单），没法避免；草稿里出现的账号名不另外抹。
- 代价：用户名是常见词（例如 `dev`、`ubuntu`）时会多抹（`ubuntu-26.04` 会变成 `<用户名>-26.04`）；3 个字以下的用户名、6 个字以下的已知值不按值抹（太短会把正常的字也抹掉）。

## 验证

`tests/unit/test_self_report.py`，19 项，全用临时主目录（`TempHome`）、假 gh：

- **每一种都有样例**（24 个）：Anthropic、OpenAI 风格 `sk-`/`sk-proj-`、GitHub `ghp_`/`gho_`/`github_pat_`、`Authorization: Bearer`、`Authorization: token`、单独的 `Bearer`、`KEY=value` 环境变量、`export KEY='…'`、JSON、YAML、`--token`、私钥块（完整、没有结尾、只剩后半截）、网址里的 `user:pass@`、AWS、Google、Slack、JWT、兜底长串、知道值的、邮箱、主目录、本机名、用户名、Git 名字、私有项目名、IP。逐个抹、合在一起抹，都一个不剩。
- **反着试（自动）**：`test_each_rule_is_needed` 拿掉 20 条规则里的任何一条，它的样例就有漏出来的；规则和样例的种类必须一一对上（加一条规则不加样例就不过）。为了做到这一点，每个样例故意避开别的规则（例如只用小写和数字，兜底的长串就认不出），这样拿掉哪条都看得出来。
- **`config/ai/*.env` 的值**：测试现造随机值写进临时的 `config/ai/claude.env`、`codex.env`（带引号、`export`、注释），从登记文件读出来再抹，值和地址都不剩。代码里没有任何真实的值。

- 另在 `/tmp/sop-3-42/` 里用临时主目录、临时 `SOP_HOME`、假 gh 从命令行真跑了一遍，看了生成的问题单的样子（用完删了）。

## 没做的

- **真 GitHub 上没走**：真的在 `C1fLly/sop` 上建一张问题单是在 GitHub 上建东西，要用户答应。3-45（`sop self fix`）本来就要「真的在工具包仓库上走一张小问题单」，推荐到那时一起走：建一张、看样子、关掉。**也没查 `C1fLly/sop` 有没有关掉 Issues**（新建的公开仓库默认开着；3-41 只改了合并方式），关掉了会报错、草稿留着。
- 问题单不加标签：GitHub 上没有写权限的人建问题单时加的标签会被丢掉（经验之谈，没核实），所以标题统一以「sop self report：」开头。
- 不查重：同一个问题报了好几次会是好几张。
- 流程命令自己判断是工具包问题时**不会自动执行**它，只是提示小白执行（流程引擎原来就这样提示）；维修窗口（`sop repair`）是第 3 期。16.5 第 2 条「项目先怎么办」只说了一句「等修好、修好后 `sop self upgrade`」，`sop self rollback` 是 3-43。
- 认不出样子、又不知道值的密钥（例如某家服务 20 个字的全小写密钥、放在普通句子里）抹不掉；IPv6 地址、MAC 地址不抹。所以登记前一定给小白看。
- 草稿目录 `~/tools/sop/reports/` 是设计书 3.2 没有的新位置，留给 3-48。

## 自己出的错

- 没有结尾的私钥一开始抹到了整份日志的最后（见上），整条走的测试抓到后改了。
- 抹掉类别的说明里原来写了 `"token": 值` 这样的字，再抹一遍时会被「赋值」规则当成密钥抹掉，不是一个字不变。改成不带这种写法的说明。
- 认 `Bearer` 的规则一开始也认 `token <词>`，会把「token verification」这种普通的话抹掉，改成只认 `Bearer`（`Authorization: token …` 由 Authorization 那条管）。
- Python 报错里的 `KeyError: 'ai'` 一开始被「赋值」规则当成名字带 key 的赋值抹掉了，加了「以 Error/Exception/Warning 结尾的是类名」。
