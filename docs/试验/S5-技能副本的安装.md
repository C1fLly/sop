# 试验 S5：技能副本的安装

状态：已完成（2026-11-17）。把技能整目录复制到两处目录后，四个工具都认得。没做的部分列在末尾。

调用了 AI，共 21 次。**记账 1.95 美元**（三项合计上限 30 美元）。其中 Claude Code 的 0.78 美元是工具自己报告的；另外三个工具不报告金额，是我按词元数用偏高的单价估的，见下面「花费」。

全部在 S2 定下的受限环境里跑。没有打开 Codex、OpenCode、Pi 的密钥文件和会话记录；它们这次的会话存在受限环境里的临时位置，受限环境一关就没了。

## 要验证什么

设计书第 19 节：复制技能到各工具的目录后，四个工具是否都能识别。

设计书 10.2 另外留给它一项：OpenCode 三处技能目录都认，同一个技能会不会出现两次。

## 怎么做的

- **技能来源**：mattpocock/skills 的提交 `5863806`，和 S0、S1 同一版。
- **试验项目** `/tmp/sop-spike-s5/proj`：一个空项目。把 21 个技能**整个目录**复制了两份，一份放 `.claude/skills/`，一份放 `.agents/skills/`。复制后和来源逐个比对，没有差异。这 21 个是设计书附录 B 用到的那些，其中 12 个标着只允许人触发。
- **另加两个试验用的「暗号技能」**，内容只有一句「被调用时回答暗号是某某」：
  - 一个标着只允许人触发，一个允许 AI 自己选用。
  - 两处目录里的暗号故意写得不一样（一个带「CLAUDE目录」，一个带「AGENTS目录」）。这样从回答就能看出工具到底读的是哪一处的文件，也能证明它是真的读了技能文件，不是在猜。
- **每个工具问四件事**，每件一个全新会话，都是自动调用：
  1. 列出你能用的全部技能的名字。
  2. 「S5 的暗号是什么？」（看 AI 会不会自己选用技能）
  3. 用这个工具的写法点名调用那个只允许人触发的暗号技能。
  4. 点名调用一个不存在的技能（对照，看它会不会瞎编）。
- 四个工具的版本：Claude Code 2.1.326（比前几项试验时的 2.1.325 新了一版，是它自己更新的）、Codex 0.169.0、OpenCode 2.3.0、Pi 1.5.2。

能不调用 AI 就查清的，先查了：四个工具的帮助里都没有「列出技能」的命令（Pi 只有「加载某个技能」和「不加载技能」两个开关），所以只能真的问。

## 结果

### 四个工具认不认得

| | Claude Code | Codex | OpenCode | Pi |
|---|---|---|---|---|
| 点名调用只允许人触发的技能 | **成功**，暗号正确 | **成功**，暗号正确 | **成功**，暗号正确 | **成功**，暗号正确 |
| 点名调用的写法 | `/技能名` | `$技能名` | `@技能名` | `/skill:技能名` |
| 读的是哪一处 | `.claude/skills` | `.agents/skills` | `.agents/skills` | `.agents/skills` |
| 允许 AI 选用的技能，在不在它的清单里 | **不在**（见下） | 在，10 个都在 | 在，10 个都在 | 在，10 个都在 |
| 只允许人触发的技能，在不在它的清单里 | 不在（应当如此） | 不在（应当如此） | 不在（应当如此） | 不在（应当如此） |
| 问「暗号是什么」时会不会自己选用技能 | 没有选用，是搜文件找到的 | 会，暗号正确 | 会，暗号正确 | 会，暗号正确 |
| 点名一个不存在的技能 | 明说没有这个技能，没有执行 | 找了一遍，明说没找到 | 明说没有这个技能 | 找了一遍，明说没找到 |
| 同一个技能出现两次吗 | 不会 | 不会 | **不会** | 不会 |

「清单」指工具在会话开始时告诉 AI 的「你有这些技能可以用」。21 个技能加 2 个暗号技能里，允许 AI 选用的有 10 个：`code-review`、`codebase-design`、`diagnosing-bugs`、`domain-modeling`、`grilling`、`pr`、`prototype`、`research`、`tdd`，加一个暗号技能。Codex、OpenCode、Pi 列出的正好是这 10 个（外加它们各自自带的几个）。

### Claude Code 上的一个情况

**在这个受限环境里自动调用时，项目里的技能不出现在 Claude Code 给 AI 的清单里。** 清单里只有它自带的 14 个。旧一版（2.1.325）也一样，所以不是新版本造成的。

但技能是能用的，两条路都通：

- 用 `/技能名` 点名调用：成功。
- 让 AI 用它的「技能工具」按名字加载：成功。实测 AI 按名字加载了暗号技能，拿到了正文。

这对设计的影响：

- 主链不受影响。主链上每一步都是流程命令点名调用；技能之间互相调用也是写明名字的（比如 `implement` 的原文是「用技能工具调用 `tdd`」）。S0 里 `implement` 调到了 `tdd` 和 `code-review`，和这里对得上。
- 受影响的是「AI 看描述自己决定用哪个技能」这种用法。在 Claude Code 上不能指望它。任务包里要用到哪个技能，必须写明名字（设计书 9.1 的任务包本来就有「技能」一节）。
- 原因没有查清。可能和受限环境里用的是一个全新的状态目录有关，也可能和这台电脑接的服务有关。没有在受限环境外面对照。

### 同名技能

mattpocock 的 `code-review` 和 Claude Code 自带的一个技能重名。实测让 AI 按名字加载 `code-review`，加载进来的是**项目里的那一份**（正文开头是 mattpocock 的原文，路径在 `.claude/skills/code-review`）。所以重名时项目里的优先。

### OpenCode 会不会重复

**不会。** 同一个技能在 `.claude/skills` 和 `.agents/skills` 里各有一份，OpenCode 的清单里每个名字只出现一次，用的是 `.agents/skills` 那一份。设计书 10.2 担心的重复没有出现。

两处内容不同时它悄悄用了 `.agents/skills` 那份、没有任何提示。工具包安装时两处是同一份内容，所以不成问题；但升级技能时两处必须一起换，不能只换一处。

### 只允许人触发的标记，各工具守不守

| | 标记写在哪 | 清单里隐藏了吗 | AI 自己能绕过去加载吗 |
|---|---|---|---|
| Claude Code | 技能文件开头 | 是 | 没试 |
| Codex | 技能目录里的 `agents/openai.yaml` | 是 | 没试 |
| OpenCode | 技能文件开头 | 是 | **能。** 点名调用时，其实是 AI 自己用技能工具按名字加载的，不是工具替它展开的 |
| Pi | 技能文件开头 | 是 | 没试 |

Codex 那一列证实了一件事：**复制技能必须整个目录一起复制。** 13 个只允许人触发的技能在 Codex 的清单里都没有出现，靠的就是技能目录里的 `agents/openai.yaml`。

OpenCode 那一列说明：在 OpenCode 上，「只允许人触发」只是不列进清单，挡不住 AI 知道名字后自己去加载。对本设计没有影响（流程命令本来就是要点名调用这些技能），记下备查。

### 各工具点名调用时实际发生了什么

- **Claude Code、Codex、Pi**：工具自己把技能正文展开，直接送给 AI。Pi 的输出里看得最清楚，送进去的内容是 `<skill name="sop-canary-human" location="…/.agents/skills/sop-canary-human/SKILL.md">` 加技能正文。
- **OpenCode**：`@技能名` 这几个字原样送给 AI，AI 看懂了，自己用技能工具去加载。结果一样，但多了一步，靠的是 AI 的理解。

### 一个卡住的地方

Pi 第一次调用卡了 5 分钟，没有任何输出，超时。原因在我的脚本：启动它时没有把键盘输入关掉，它在等输入。关掉之后每次 5 到 13 秒正常返回。工具包的适配器启动 Pi 时要把键盘输入关掉。这次卡住没有读到用量，按规矩记了 0.30 美元，实际多半是 0。

## 结论

1. **两处目录（`.claude/skills` 加 `.agents/skills`）够四个工具用。** 整个目录复制过去之后，四个工具都认得，都能点名调用只允许人触发的技能。设计书 5.2 和 10.2 的做法成立。
2. **OpenCode 不会把同一个技能列两次。**
3. **复制时必须整个目录一起复制**，这一条被 Codex 的结果证实。
4. **在 Claude Code 上，不能指望 AI 看描述自己选用项目里的技能**；点名调用和按名字加载都可以。任务包要写明技能的名字。
5. 重名时项目里的技能优先于工具自带的。
6. **另外三个工具在自动调用下能点名触发技能**——这本来是 S1 后续部分的第一项，这里用暗号技能顺带验证了。用真实技能再验一次放在 S1 后续部分里做。

## 没做的

- Claude Code 的清单里为什么没有项目技能：原因没查清，没有在受限环境外面对照。
- `.opencode/skills` 这第三处目录没试（设计里不用它）。
- 技能引用的附带文件（比如 `tdd` 目录里的另外三个文件）各工具读不读得到：没有单独试。S0 里 Claude Code 用 `tdd` 是正常的。
- Claude Code、Codex、Pi 上，AI 能不能绕过「只允许人触发」的标记自己加载：没试。
- 用户在主目录下装的全局技能：受限环境里看不到，没试。
- 用真实的主链技能在另外三个工具上跑一遍：属于 S1 后续部分和第 5 期。
