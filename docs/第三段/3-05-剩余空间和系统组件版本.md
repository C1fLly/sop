# 3-05 体检：剩余空间和系统组件版本

2026-11-19。由主控窗口派出的子代理做。没调用 AI，没花钱，没开虚拟机，没动这台电脑（本机只读地查了一遍剩余空间、读了几个系统文件、跑了 `bwrap --version`、`dpkg-query`）。

## 做了什么

- **`machine/space.py`：剩余空间提醒**（设计书 4.3、W39）。只读，只看剩余空间，不删任何东西。
  - 提醒线按用户定的：系统盘剩不到 10 GB、主目录所在的分区剩不到 20 GB 时提醒；两者是同一个时只报一行，按 20 GB。
  - 低于提醒线时说清后果（系统盘满了 Ubuntu 可能进不了桌面；主目录满了镜像、缓存、数据库写不进去），并指向 `sop machine clean`。这个命令第 3 期才做（W31），所以提醒里如实说「在那之前先自己删掉不要的大文件，拿不准的问维修窗口」。只提醒，不挡流程。
  - 「是不是同一个」按**文件系统**算：设备号一样算同一个；不一样时再看 `findmnt` 的来源名，btrfs 子卷去掉后缀是同一个设备也算同一个（btrfs 每个子卷的设备号都不一样，但共用一个池子）。加密加两个逻辑卷的，底下是同一个分区，但是两个文件系统、各有各的剩余空间，各按各的线。查不出来时按「不是同一个」，两行都报，不会少报。
  - 剩余空间按普通用户能用的算（不含留给管理员的那 5%），GB 按 10 的 9 次方字节，和 Ubuntu「磁盘使用情况」显示的一致。正好等于提醒线不提醒。查不出来的照实写「查不出来」。
- **`machine/components.py`：系统组件的版本和状态**（设计书 4.5），记进 `config/system.json`（3-03 写的登记）。值只求「变了就看得出来」，给 3-07 比对用：
  - 内核：版本号加编译记录（`uname -r` 加 `uname -v`；Ubuntu 有时版本号不变、只重新编译一次）。
  - bubblewrap：`bwrap --version` 的版本，加软件包的版本（安全补丁只改软件包版本，例如 `0.11.1-1ubuntu0.3`）。
  - 免管理员 Docker 那条系统规则：`/etc/apparmor.d/` 下按 rootlesskit 真实路径起名的文件（`~/tools/docker/bin/rootlesskit` → `home.<用户名>.tools.docker.bin.rootlesskit`，官方安装脚本的起名办法），记文件名和内容指纹（sha256 前 12 位），连同它引用的 `local/` 下同名文件；没有就记 `missing`。
  - **多了一样**「系统对普通用户建隔离空间的限制」（`userns_policy`）：总开关 `kernel.apparmor_restrict_unprivileged_userns` 的值，加 `bwrap-userns-restrict` 那条规则的指纹。理由：本机这个开关是开着的，bubblewrap 和免管理员 Docker 都是靠各自那条规则放行的；系统升级改了这两样，bubblewrap 可能就起不来，3-07 要能看出来。设计书 4.5 写的是「系统安全规则」，没有只限 Docker 那一条，任务清单只列了 Docker 那条。为此在 `config.SYSTEM_PARTS` 里加了这一样。
  - 往终端塞按键的开关：读 `/proc/sys/dev/tty/legacy_tiocsti`，`0` 关着（合格）、`1` 开着、老内核没有这个开关记 `missing`（等于开着）。后两种报告里写「AI 对话的步骤不会启动」。
  - `collect()` 查一遍、`record()` 记进登记、`describe()` 给几行大白话（还没登记过时说「先跑一次隔离自检，过了再记下来」；和登记不一样时说哪几样变了、会先重跑隔离自检）。3-06 的体检报告、3-07 的启动比对直接用。
- 两个模块都能单独跑看结果：`uv run python -m machine.space`、`uv run python -m machine.components`（后者只读登记，不写）。
- README 的目录表 `machine/` 一行补了「体检的几项」。

## 结果

- 新加单元测试 `tests/unit/test_machine_space.py` 13 项，全部通过：
  - 剩余空间 8 项：两个文件系统都够用；系统盘剩 9.9 GB 提醒且只指一次 `sop machine clean`；主目录剩 19 GB 提醒、系统盘剩 12 GB 不提醒；同一个分区剩 15 GB 按 20 GB 提醒；正好 10 GB 不提醒、留给管理员的那块不算；查不出来；「是不是同一个」五种（设备号一样、btrfs 子卷、加密两个逻辑卷、`findmnt` 跑不成、路径不存在）；本机只读查一遍。
  - 系统组件 5 项：用假命令、临时目录造一遍，五样的值都对、只跑了两条只读命令、记进登记后再比没有变化、文件权限 0600；内核版本号变、只换编译、bubblewrap 只打安全补丁、bubblewrap 升级、Docker 规则改一行、加 `local/` 文件、限制开关关掉、bubblewrap 规则改了、塞按键开关打开，每一样都只报它自己；什么都没有的电脑（没 bubblewrap、没 dpkg、没 Docker 规则、老内核、没限制开关）照样记、大白话对；规则名按真实路径（工具目录是链接时解开）；本机只读查一遍（记进的是临时根目录）。
- 全部自测：做之前单元测试 68 项、流程沙箱 22 个剧本、总检查 62 个样例全过；做之后单元测试 81 项（多了这 13 项），其余一样，全部通过。
- 本机只读跑了一遍（没有建出 `~/tools/sop/config`，跑完确认它仍不存在）：
  - 系统盘（/）还剩 83.7 GB（共 109.9 GB），主目录所在的分区还剩 120.0 GB（共 152.6 GB），都够用；判成两个文件系统，和实际（`nvme0n1p5`、`nvme0n1p6`）相符。
  - 内核 `7.0.0-43-generic`；bubblewrap `0.11.1`（软件包 `0.11.1-1ubuntu0.3`）；Docker 规则 `home.sanchuanzl.tools.docker.bin.rootlesskit` 有；限制开关 `1`、`bwrap-userns-restrict` 有；塞按键 `0`（已禁用）。和直接读系统文件看到的一致。

## 没做的

- 没有加命令：`sop machine doctor` 是 3-06 的事；`sop` 每次启动和登记比对、变了先重跑隔离自检是 3-07 的事。这次只给了查和记的函数。
- 「把一个分区塞到低于提醒线、看到提醒」在虚拟机里真做，是 3-37 的事；这次用造出来的数测。
- 规则只记内容指纹，不看它是不是真的加载进了内核（`/sys/kernel/security/apparmor/profiles` 普通用户读不了）。改了文件没重新加载、或加载了别的，这里看不出来；隔离自检（M6）真起一次才算数。
- `kernel.unprivileged_userns_clone`（Debian 系老内核的另一个开关）没记：Ubuntu 26.04 上起作用的是上面那个 AppArmor 的开关。

## 和设计书的出入（留给 3-48 并入）

- 系统组件登记多了一样「系统对普通用户建隔离空间的限制」（总开关加 `bwrap-userns-restrict` 规则），4.5 的「系统安全规则」写明是两条（Docker 的、bubblewrap 的）加一个开关。
- W39 的数写进设计书：10 GB、20 GB、同一个按 20 GB；「同一个」按文件系统算（加密两个逻辑卷各按各的线），GB 按 10 的 9 次方、按普通用户能用的算。
- 剩余空间提醒指向 `sop machine clean`，但那个命令第 3 期才有；在那之前提醒里说先自己删、拿不准问维修窗口。
- 各样记成什么写法（内核带编译记录、bubblewrap 带软件包版本、规则记指纹、没有的记 `missing`）。

## 自己出的错

- 取 bubblewrap 版本时直接用了 `catalog.parse_version` 的结果，它返回的是数字的元组，不是文字，第一次本机跑之前看代码发现，改成拼回「0.11.1」。
- 第一次本机跑时为了不碰真的登记，把 `SOP_HOME` 指到了 `/tmp`，结果工具目录也跟着变到 `/tmp` 下，Docker 规则显示成「还没有」。不是代码的错（工具目录本来就跟着 `SOP_HOME` 走），改成不设 `SOP_HOME` 再跑（这几个函数只读登记、不写），结果对了。
- 「正好等于提醒线」那条测试第一次没过：造数时按 4096 字节一块取整，10 GB 被截成了比 10 GB 少一点。是测试造数的问题，改成按 1000 字节一块造。
