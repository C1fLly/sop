接手时先读懂再跑：在临时主目录里只跑了这两个测试文件（全是假命令、临时目录，不碰本机），49 项当时就全过（上一个说的「正在修测试细节」看来修完了，只是没来得及跑全部自测）。然后逐条对照设计书 4.8 和任务清单 3-32 那一行读了一遍代码：骨架是对的（只认 `ready_for_q6`、停掉的旧容器没起回来不卸、逐条打印再确认默认不卸、系统自带的一个一个点名连同随装的包一起 purge、先删数据再删程序、残留逐项核对、默认指向先切回再切到新的），**大体照用**，自己补了下面 7 处：

1. **真卸之前再用 `apt-get -s purge <这些包>` 算一遍**（只模拟，不用管理员）：卸这几个包会连带卸掉屏幕上没列出来的包（清点之后又装了依赖 Docker 的软件）就一样都不动、说清楚。原来只信 Q1 当时算的，Q1 到 Q6 之间可能隔着很久的 Q4，打印的「要删什么」就可能不是真要删的。
2. **系统服务卸完的核对放严**：原来只有 `LoadState=loaded` 算还在，被屏蔽（`masked`，指向 `/dev/null` 的登记）的会被当成清掉了；改成只有 `not-found` 才算没了，`systemctl` 没回答算「查不了」（也算不空）。
3. **默认指向不从留着的另一份 Docker 身上切走**：snap 版也用系统那条通道 `/var/run/docker.sock`，小白卸 docker.io、留 snap 版时，原来会把默认指向从 `default` 切到新的，敲 `docker` 就看不到留着的那份了。改成留着的那几份用的通道一律不切走（也不按「通道文件不在了」切走：留着的那份可能只是停着）。
4. **迁移记录里「临时小镜像还没删」那一条随旧的一起删掉**（`record.forget`，新加）：卸掉旧的后这条记录留着，`sop` 每次启动都会去连一份已经没了的 Docker 报提醒；旧的是免管理员那种时更糟——规定位置那份会接过同一条通道，`sop` 启动按记录去删 `alpine:3.20`，删的就是规定位置那份里同名的镜像。反着试过：去掉这一行，那项测试不过。
5. **规定位置的 Docker 没装好（找不到 `docker-host`）就不卸**，连问都不问（4.8「新的先装好，才谈旧的」，Q2 核对过，这里是保险；原来这时会照卸、只是不管默认指向）。
6. **自测的保险**（3-59）：要卸的有能自动卸的那几种时，先过 `paths.guard_home`，测试漏设 HOME 就一样都不删（加了一项测试）。
7. 零碎：路径写法的 `apt-line` 那一项没记文件名时算「查不了」不报错；卸完把清点时记下的提醒（`~/.bashrc` 里照官方装法加的 PATH、`DOCKER_HOST` 几行，containerd 还有别的软件在用）再打一遍；接过服务名换了一个规定位置那份的连接对象时，旧的那个也关掉；读服务登记文件没关文件的警告。

## 做了什么（现在的样子）

`sop machine migrate` 走完 Q5 之后接着 Q6（`machine/migrate/uninstall.py`），只管 Q3 里选了「卸掉」的 Docker：

- **能不能卸**：带了数据的那份（有能连的 Docker 程序的：docker.io、docker-ce、免管理员但位置不对的）只认 `config/migrate/carry.json` 里这一份的 `ready_for_q6` 是真（3-31 存的：选了带走的都备份、试还原、核对过；什么都没选带走时也记真）；迁移停掉的旧容器还没起回来（`stopped.json` 里还有容器）不卸；免管理员的那份没用后台服务而在跑着，工具包停不了它，不卸；规定位置的 Docker 没装好不卸。这几种连问都不问，说清楚为什么，旧的照常在。
- **再确认一次**：逐条编号打印要删掉的（Q1 的残留清单每一项、各目录多大）、旧 Docker 里的容器（不带走）、选了「不要了」的数据卷、没带走的镜像、Q3 里跳过的；带走的几个数据卷和镜像已经核对过、备份在哪不删；要管理员的先说一句「系统会问登录密码」。问「确定现在卸掉它吗」，默认「否」，不在终端里按默认。
- **系统自带的**（docker.io、docker-ce、以前卸过留下的）：`apt-get -s` 再核对一遍 → 停系统服务 → `apt-get purge` 一个一个点名（Q1 算出来的连同随装的，不用 `--autoremove`，免得顺手卸掉别的「没人要了」的包；用 3-56 的 `sop_apt` 等住软件包的锁）→ 软件包没卸掉就停在这里、不删它的数据目录 → 删数据和设置目录、官方软件源文件、钥匙文件（写在 `sources.list` 里的只删那几行，注释掉的不动）→ 删 `docker` 用户组 → 重新载入服务登记。要管理员的每一步用 `sudo -p` 中文提示，密码由小白自己输。
- **免管理员但位置不对的**：停掉、取消它的用户级服务（停不下来就不往下删）→ 先删数据目录（里面有属于容器内部账号的文件，自己删不掉就借旧的那份的 `rootlesskit rm -rf` 删）→ 再删 `~/bin` 里的程序和服务登记（`~/bin` 里小白自己的别的程序不动）→ 删那条系统安全规则（先 `apparmor_parser -R` 再删文件，要管理员）→ 旧的程序确实没了，规定位置那份原来用 `sop-docker` 这个名字的接过 `docker` 这个服务名和通道：服务登记去掉 `sop-docker` 多出来的四行（结果和安装脚本按 `docker` 这个名字写的一字不差）、起来后 30 秒内连得上才换 `~/tools/docker/etc/docker-host`、删 `sop-docker.service`；接不过去就退回 `sop-docker`、通道文件不改、如实说。
- **snap 版、Docker Desktop**：第一版不自动卸，只打印官方的卸载步骤和网址。
- **默认指向**（`docker context`，用规定位置的 docker 命令、明说设置目录 `~/.docker`）：卸之前它若指着新的，先切回指着旧通道的那一个（卸到一半停下时，敲 `docker` 看到的还是原来那份）；卸完、旧的程序确实没了（主软件包都不在了，或者 `~/bin` 里的程序都删了），再切到新的：已有指着新通道的就用它，没有就新建 `rootless`（名字被占了用 `sop-rootless`）。只在它指着旧的、新的、或通道文件已经不在时才切；指着留着的另一份 Docker、远程的，不动。旧的程序还在就不动。
- **卸完逐项核对**：按 Q1 记下的残留清单一项一项再看（软件包问 `dpkg-query`、服务问 `systemctl show`、用户组看 `/etc/group`、路径看在不在、软件源看那几行还在不在、snap 看 `/snap/docker`），都没了才说「卸完了：残留清单 N 项逐项又看了一遍，都没有了」；有一项不空就说「没卸干净」，列出还在的每一项（查不了的写「查不了：…」，按规矩不删的写「没删：…」），给出自己清掉的命令。最后核对规定位置那份仍然过清单的检查命令、连得上，不正常就照实说、退出码 1。结果记在 `config/migrate/uninstall.json`。
- **删之前核对路径**：根目录、太靠近根的（`/var` 这种）、主目录和它上面的、`~/tools` 里面的（`daemon.json` 另指的数据目录落在那里时），一律不删，列为残留并写明为什么。

旧的 nvm、uv、pnpm 选了「卸掉」时，迁移最后说「卸载这一步还没做好（任务 3-61），现在照常在」。

## 没做的

- **真卸**：本机不卸任何东西；三种装法在虚拟机里用正式命令走 Q1 到 Q6 是 3-33（docker.io）、3-34（docker-ce）、3-35（免管理员但位置不对）。假命令只能验「按什么顺序、跑了哪些命令、核对逻辑对不对」，真的 `apt-get purge` 的输出、`systemctl show` 对卸掉的服务回什么、`rootlesskit rm -rf` 删不删得掉、接过服务名后容器回不回来，都要在那里验。
- 旧的 nvm、uv、pnpm 的卸载是 3-61。
- 官方免管理员装法提示加进 `~/.bashrc` 的那几行（PATH 加 `~/bin`、`DOCKER_HOST`）不删，只在卸完时提醒（设计书没说要删；`DOCKER_HOST` 指的那条通道接过服务名后就是规定位置那份，还能用）。
- 没加单独「只做 Q6」的命令：小白说「不卸」之后想卸，再执行一次 `sop machine migrate`，Q3 重新选，带走过的会跳过。

## 和设计书的出入（留给 3-48）

1. Q6 真卸之前再用 `apt-get -s` 核对一遍要卸的包，多出来就不卸（设计书没写）。
2. 默认指向在「旧的程序确实没了」时就切到新的，不等残留全空（例如只剩用户组没删掉）；设计书写的是「卸完逐项核对残留清单，再把默认指向切到新的」，先后照做，但没说残留不空时切不切。指着留着的另一份 Docker 的不切走。
3. 免管理员那种的「接过默认的名字」具体做法：改写规定位置那份的服务登记（`sop-docker.service` → `docker.service`，去掉四行）、换 `docker-host`、接不过去退回；不重跑官方安装脚本，`rootless` 默认指向由 Q6 自己建。
4. 删之前的路径核对规则（根、太靠近根、主目录和上面、`~/tools` 里面的不删）。
5. 规定位置的 Docker 没装好时 Q6 不卸（4.8 规矩的落实）。
6. 迁移记录里只剩临时小镜像那一条时，旧的卸掉后删记录（4.8 的「停容器记录」没提这一种）。
