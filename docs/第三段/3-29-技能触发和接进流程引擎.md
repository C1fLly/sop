# 3-29 适配器：技能触发、接进流程引擎

2026-11-21，主控窗口派的子代理做的。**没动隔离**（`runner/` 一个字没改）；**没动放行事件、事件日志**；没碰 GitHub（只用假 gh）；技能副本 `skills/mattpocock/` 一个字没改；`~/tools/wt` 只用（流程沙箱经它建项目）。**真实调用 5 次，0.1884 美元**（其中一次只打开窗口不发消息，0）。**改了流程引擎**（`kernel/engine.py` 修了一个原有的问题、`kernel/steps.py` 加了「点名的技能没加载就停下」），不是隔离、放行、事件日志那三处。

## 做了什么

1. **流程引擎按配置选适配器**（`adapters/ai/__init__.py` 新、`kernel/cli.py`）：有哪些适配器列在 `adapters/ai/__init__.py`（`claude`、`fake`）；`sop` 选哪个按「环境变量 `SOP_AI`（只给流程沙箱、自测用）→ 主线 `sop.json` 的 `ai.tool`（10.3 的角色配置，第 1 期所有角色用同一个工具，只能写 `claude`，写 `fake` 或别的报错）→ 默认 `claude`」。**原来没设 `SOP_AI` 时默认是假 AI**，现在默认是 Claude Code。`sop.json` 模板没加 `ai` 这一项（不写就是默认），`project new` 写的内容没变。
2. **每次启动的演练提醒**（10.1）：`sop`（推进流程）启动时问适配器 `reminder()`：Claude Code 的版本和登记里「最近一次演练通过的版本」不一样、或还没演练过，就先打一行「提醒：……」，流程照常。没装 Claude Code 时不提醒（到 AI 步骤再说）。查版本用的是原来那个套了只读 bubblewrap 的 `--version`。
3. **技能触发**（`adapters/ai/claude/adapter.py`）：任务包（`task.json` 的 `skill`）点名了技能时，提示词最前面是 `/<技能名> `（S1：技能命令放在提示词开头才触发），自动调用、对话窗口的开场、续接的第一句都这样。**工作目录里没有 `.claude/skills/<技能名>/SKILL.md` 就不调用**（不花钱），说清楚；技能名只认小写字母、数字、「-」。调用之后从会话日志里认这次有没有真的加载：Claude Code 加载一个技能时会话日志里有一条用户消息，开头是 `Base directory for this skill: <目录>`，目录是 `…/.claude/skills/<技能名>` 才算（只认项目里的副本，Claude Code 自带的同名技能不算，10.2 第 8 条）；续接时只数这一次新加的。结果放在 `Outcome.skill_loaded`（`True`/`False`/`None`=没点名或认不出，假 AI 一律 `None`）。
4. **流程引擎在点名的技能没加载时停下**（`kernel/steps.py` 的 `skill_problem`）：流程定义点名了技能、适配器说这次没加载（没有副本没调用；或调用正常结束但日志里没有加载记录），这一步记「没通过」并停在原地（`hold`），说「先停下，启动维修窗口（sop repair）」——这不是 AI 做得不好，重做一遍也一样，多半是 AI 工具升级后写法或日志的样子变了。调用本身出错（退出码不是 0、超时）的照原来的路走；对话步骤不在终端里没调用的不算。
5. **真实 AI 演练**（16.2，新文件 `adapters/ai/claude/drill.py`，`python3 -m adapters.ai.claude.drill`）：在 `/tmp` 现建的一次性小项目里（工作目录里放一个技能副本 `wait-what`：原文标着只允许人触发、正文一段话），①交互：`check_screens`（打开一次对话窗口不发消息，没出首次启动的那几屏）、再在模拟终端里 `start_interactive`，开场内容是点名了技能的任务包，要求输入框出来、没出那几屏、退出码 0、它回答了、技能加载了；②自动调用：`run_headless` 执行点名了技能的任务包，要求退出码 0、技能加载了、结果文件过 `checks/result_file`、工作目录没被改；③反着试：点名一个没有副本的技能，适配器不调用。**都过了才调 `mark_drilled` 记下演练过的版本**（3-27、3-28 留下的接线），之后 `probe` 和 `sop` 启动时不再提醒，直到版本又变了。余额不足、额度类的报错停下不重试。`check_screens` 3-28 已接进 `probe`，这次又是演练「交互」那一样的第一步。
6. **修了流程引擎原有的一个问题**（`kernel/engine.py`，3 行）：一轮里同一个范围最多走几步（8.4 防打转的总保险，`SOP_MAX_STEPS_PER_RUN`，默认 200）。功能那一级到上限会停；**工单到上限时，工单线程停了，`run_tickets` 却又把它当成能走的、重开一个线程**，马上又到上限，一直这样转，`sop` 永远不退出——真用时就是「回头路走得太多」那条保险在工单上不起作用，卡死而不是停下说明。改成记下这一轮到上限的范围（`over_limit`），不再重开它，等别的工单走完后停下说明。真实调用的脚本用这条保险让 Claude Code 只跑一步时撞上的。
