## 做了什么

新模块 `kernel/projectclone.py`，命令 `sop project clone <GitHub 账号名/项目名>`（`kernel/cli.py` 加了一个分支，不在项目里也能用）。按顺序做：

1. **克隆**：先用 gh 查 GitHub 上有这个仓库（没有就停、什么都不建）；经接入层 `wtx.init(..., hook=False)` 调 `wt init <所有者/项目名> --url <地址> --no-hook`
   （不加 `--create` 就是取下已有的仓库），带 `WT_TEMPLATE` 指向工具包的模板，所以 `.shared/hooks/` 是工具包的那三个（4.7「项目的 wt 钩子：克隆时安装」），
   wt 自带的装依赖脚本不会被执行。项目根是 `~/Project/<项目名>`，和建项目的那台电脑同一个位置；地址和 I2 一样（`git@github.com:<所有者>/<项目名>.git`，
   `SOP_GITHUB_URL_PREFIX` 换前缀）。仓库名不合项目名的规矩（小写字母、数字、「-」）就停。
2. **装 `sop.json` 声明的工具包版本**：读主线上的 `sop.json`（项目名和仓库名对不上就停），用和启动器同一个装法装到 `~/tools/sop/versions/<提交编号>/`，
   装完核对就是那个提交、没被改过。
3. **重新生成 `.shared/.env`**：按仓库主线上的清单 `.env.example` 原样写出（权限只有自己能读写）；值空着的几项当成第三方测试密钥，连同它上面的说明列出来，
   让小白按引导自己填。仓库里没有清单就不生成（说一句）；已经有 `.shared/.env` 的不动。生成之后在 `main/` 里执行一次 `wt hook`（工具包的准备脚本只做一件事：把 `.env` 链接进来）。
4. **出口检查**：在项目根跑 `wt doctor`，没有失败项（和 I2 的出口检查同一个函数）。
5. **按远程分支和事件日志重建进行中的工作目录**（4.7）：
   - 进行中的功能（日志里登记了、没结束也没放弃；F1 做完才有分支；F20 合进主线之后分支删了，剩下的清理、复盘只用 `main`，不建）：`wt new feat/<功能>`，wt 继续远程已有的分支。
   - 它的工单里 T1 做完了（日志里有开工单目录的登记）、没做完、没放弃、没合进功能分支的：远程有这条分支（T4 通过后就推送了）就继续它；
     远程还没有（T4 之前，实现从没推送过）就从 T1 登记的起点 `base_commit` 重新开，丢的是那一步（4.7「自动步骤进行到一半时……丢一个步骤，重做」）。
   - **基准**：开了 PR 的，wt 自己按 PR 的目标分支补记（S3 的做法）；还没开 PR 的（T10 之前的工单、F12 之前的功能），按事件日志里登记的那一份
     （F1 的 `base`、T1 的 `base`）经 `wtx.set_base` 写回 wt 的登记 `branch.<分支>.wtBase`。wt 补记的和日志里的对不上就停下，不猜哪个对。
   - 工单目录照 T1 那样在本机登记一组端口（5.5）。
   - 已经建好的目录不再建，所以断了重跑就是接着做；第二次执行说「上次已经克隆过」，什么都不变。
