用户 2026-11-19 定：一个「主控窗口」只排任务、核对、汇总，自己不写代码；每个小任务交给一个全新的子代理，一个一个串着做（交接文件「用户已经定下的事」）。本文件是主控窗口具体怎么做，2026-11-21 从第一个主控窗口的做法整理出来。

## 开工

1. 读 `docs/交接.md`、本文件、`docs/主控/总账.md`（之前每个任务的结果）。
2. `cd ~/tools/sop/dev && git status --short`。工作区不干净 = 上一个子代理被打断了，见下面「接手半截改动」。
3. 拍本机底照：`mkdir -p /tmp/sop-orch && docs/主控/snap.sh > /tmp/sop-orch/snap-base.txt`（只记大小和修改时间，不读内容）。
4. 跑一遍全部自测记基数：`docs/主控/run_tests.sh 基数`。
5. 用三五句大白话告诉用户现在在哪、下一个是哪个，然后直接开始。

## 派子代理

- 用 Agent 工具，`subagent_type: general-purpose`，`run_in_background: true`，一次只派一个。
- 提示词照下面的模板，填任务编号、刚跑出来的基数，再按任务加几条注意。**只给指针（文件路径），不抄内容。**
- 等通知。「在等它自己后台的东西」那种通知不算做完，只简短告诉用户还在跑。
- **自己不要在子代理跑的时候跑全部自测、改交接或任务清单**（会和它打架）。主控要改交接，等子代理做完再改、再提交。

### 子代理提示词模板

```
你是一个全新的会话，用户让你做一个小任务。用户给你的完整指令就是这份文件的原文，请先读它并照做：

  /home/sanchuanzl/tools/sop/dev/docs/小任务-通用提示词.md

用户点名的任务编号：**<编号>**（<任务名>）

和通用提示词不同的几点（因为你是被一个「主控窗口」派出来的子代理，用户看不到你，也不能回答你）：

- 第 4 步「先用三五句大白话说一下」写在你最后的汇报开头即可，不用等回复，直接开始。
- 你不能问用户。碰到要用户答应、要用户自己动手、或你拿不准该不该做的事：**不要做那一步**，做到能停的地方停下，在汇报里写清楚卡在哪、要用户定什么。主控窗口会去问。
- 主控窗口的做法已记在 `docs/交接.md`「用户已经定下的事」和 `docs/主控/做法.md`，读一下。
- 做之前的自测基数（主控窗口刚跑过）：单元测试 <n> 项、流程沙箱 <n> 个剧本、总检查 <n> 个样例，全部通过。做完后再跑一遍全部自测，不能少。全部自测里不要加会真调 AI 的测试。
- AI 服务出过几次报错（余额不足 403、服务端没有可用账户 503）把子代理打断。尽早把阶段性的发现写进记录文件草稿（`docs/第三段/<编号>-*.md`，没提交也行）。真实调用 AI 碰到余额不足或额度类报错：停下、不重试。
- 在本机上跑任何程序之前，先想清楚它会不会改动本机的任何东西（包括文件和文件夹的时间）；拿不准就套「整个系统只读」那一层，或放到 `/tmp` 的临时目录、虚拟机里做。测试照 `tests/safehome.py`（3-59 的保险）用临时主目录。真改动了要在汇报第 4 条如实写。
- <按任务加：只在虚拟机里真做 / 只用假 gh 不碰真 GitHub / 每次真实调用 AI 都记账到 docs/第三段/记账.json / ~/tools/wt 只用不改、git 命令加 GIT_OPTIONAL_LOCKS=0 / 动了隔离、放行事件、事件日志要在记录里单列 / 不要为了过而放宽标准 / 会改设计的先试、试不成停下把两条路的代价写清>
- 只做 <编号> 这一个，做完提交后停下，不要接着做下一个。

最后的汇报用中文大白话，按这个格式写（主控窗口会逐项核对，请写真实情况，没做成就说没做成）：

1. 做了哪个任务、怎么做的（三五句）
2. 改了哪些文件
3. 自测结果：单元测试 / 流程沙箱 / 总检查 各多少项、是否全部通过
4. 其他验证做了什么、结果；有没有改动本机任何东西；有没有留下还在跑的进程、虚拟机或临时文件
5. 记录文件路径；提交编号（git log 第一行）
6. 任务清单里这一项改成了什么状态；有没有拆出新任务（编号、名字）
7. 花了多少钱（调用 AI 的记账；没有就写 0）
8. 自己出的错、和设计书的出入、没做的
9. 要用户答应或决定的事（没有就写「没有」）
10. 按清单看下一个能做的任务是哪个
```

## 子代理交回来后，主控自己核对（不信它说的「做完了」）

1. `git status --short` 干净；`git log --oneline -1` 是它说的那个提交。
2. `git diff <上一个提交> HEAD --name-only`：没改 `skills/mattpocock/`（技能副本一个字不许改）；设计书改了的话跑 `python3 docs/试验/脚本/文档核对/check_refs.py docs/设计书.md`。
3. 记录文件在；任务清单这一项状态改了；交接「进行到哪里」加了一行。
4. `docs/主控/run_tests.sh <编号>`：三个数都不比之前少、全部通过；**本机关键文件和底照一样**。
5. 按任务查：虚拟机删了（`ls ~/sop-vm/vms/`、`pgrep -af qemu-system`）；没在本机建 `sop` 的用户服务（`systemctl --user list-units --all | grep -i sop`）；`~/tools/sop/config` 不存在；`GIT_OPTIONAL_LOCKS=0 git -C ~/tools/wt log --oneline -1` 还是 `9502f8c`；碰了 GitHub 的任务只读看一眼 `gh repo list --limit 6`；调了 AI 的看 `docs/第三段/记账.json` 加了几笔，并用本机的密钥变量 `git grep -lF` 查仓库历史里没有密钥（不打印密钥）。
6. 在 `docs/主控/总账.md` 加一行：编号、提交、自测三个数、子代理用量、AI 记账、备注。
7. 用大白话告诉用户：做了什么、我核对了什么、花了多少、替他定的事（单列，他可以否决）、下一个是哪个。然后直接派下一个。

本机上这些变动是正常的，不是子代理干的：`~/.codex` 下的日志（用户自己一直开着的 Codex 后台服务）、`~/tools/docker/data` 里的缓存（用户原来的 Docker 服务）、`127.0.0.1:8765` 的网页服务（11-18 第一段旧脚本留的，别动）、`~/.claude/projects/` 等（主控窗口自己）。

## 停下来问用户的情况

- 核对里任何一项不对（自测少了、本机被动了、禁区被碰了），**整条线停下**，把现场查清楚、说清楚，给选项和推荐，等用户答。不跳过、不自己修。用户答了以后把他的判断补进那份记录、提交。
- 子代理说要用户答应或决定、而且挡住了后面的：问。不挡的：照推荐先做，单列出来让他否决。
- AI 服务 403「余额不足」：停下，请用户充值，等他说继续。

## 接手半截改动（子代理被服务报错打断时）

1. `git status`、`git diff --stat` 看留下了什么；`git diff > /tmp/sop-orch/<编号>-半截改动.patch` 存一份副本；看有没有开着的虚拟机、`/tmp/sop-<编号>*`。
2. 403：先停下请用户充值。503 等临时错误：可以直接重派。
3. 重派时在提示词里写明：上一个留下了哪几样（改了哪些文件、开着的虚拟机、临时目录），**先读懂、自己判断用不用**，不要因为已经写了就当它对；最终验证在全新或还原过的虚拟机上跑；记录里写明怎么处理的。（用户 2026-11-20 定的：留着交给新的子代理。）

## 独立审查

动了隔离、放行事件、事件日志三处之一的，补进交接「等用户回答或处理的事」里独立审查那几条（第 7 条事件日志、第 8 条隔离），告诉用户。审查由用户自己开新窗口做，不挡后面的任务。

## 换窗口

主控窗口换新会话前：等正在跑的子代理交回来、核对完、提交；总账、交接都是最新的。新窗口用 `docs/主控-通用提示词.md`。
