# 3-43 `sop self rollback`：退回上一个版本

2026-11-22，主控窗口派的子代理做的。**没动隔离、放行事件、事件日志**（放行事件的写法没改：退回复用升级那一段，照旧给 `sop.json` 和检查流程写放行；事件日志只多了一个字段 `back`、一种记录 `工具包退回`，`kernel/journal.py` 没改）；没碰 Docker、没用 sudo；**没碰 GitHub**（只用假 gh、本机的假远程）；**没调用 AI，0 美元**。

## 读到的设计

- 7.11：退回旧版本（`sop self rollback`）和升级走同一条路，本质上是改主线上 `sop.json` 声明的版本；修补版、大版本**按实际内容比**：`flows/`、`skills/` 都逐字一致才算修补版，有一处不一致就是大版本（第二段写在 `kernel/version.classify` 里，这次原样用，没另定）。功能进行中只能在修补版之间换，隔着大版本的不行。
- 16.5 第 2 条：项目先怎么办，三种之一是退回上一个版本，前提是上一个版本没有这个毛病；功能做到一半时只能在修补版之间退。
- 启动器（`~/tools/sop/sop` → `~/tools/sop/launcher.py`，第零步和 `sop self install` 写）：**在项目里**按主线 `sop.json` 声明的版本找 `versions/<提交编号>/`（没装就从工具包仓库按提交编号装、装好核对）；**不在项目里**用 `versions/latest` 记的版本。所以「换版本」在项目里就是改主线的 `sop.json`，不在项目里就是改 `versions/latest`。

## 做了什么

| 文件 | 内容 |

| `kernel/cli.py` | `sop self rollback` 在找项目之前分派（不在项目里也能用） |
| `kernel/commands.py` | `self rollback` 从 `PLANNED` 挪到 `DONE` |
| `tests/unit/test_commands.py` | 分派核对加上 `kernel.version.rollback` |
| `tests/unit/test_rollback.py` | 9 项（见「验证」） |
| `tests/sandbox/test_rollback.py` | 流程沙箱 2 个剧本（见「验证」） |

### 在项目里：`sop self rollback`

1. 拿项目锁，取回主线，读主线 `sop.json` 声明的现在版本。
2. **上一个版本**按主线 `sop.json` 的历史找（`git log --first-parent -- sop.json`，每个提交读出声明的版本），排成一个「版本栈」：换到新版本就压上去，**换回栈里已经有的版本就当作退回，把它上面的弹掉**，连续相同的只算一个。栈顶是现在的，下面那个是上一个。所以 A → B → 退回 A 之后，A 的上一个不是 B（B 正是因为有毛病才退掉的），再退就说没有了；之后换上修好的 C，再退回到的是 A。只改了 `sop.json` 别的字段不算换版本。
3. 没有上一个：说清「一直用的就是现在这个版本（或者之前用过的都已经退回过了）」，指向等修好后 `sop self upgrade`。
4. 上一个版本**只从本机已装好的里找**（`versions/<提交编号>/` 在、`kernel/main.py`、`kernel/launcher.py` 在、Git 记的就是那个提交、文件没被改过），不联网下载；不行就说清是哪一样、「什么都没改」。
5. 按内容分类（`classify`）。**大版本又有进行中的功能（或还没合并的产品规划）**：拒绝，说清上一个和现在的流程定义或技能不一样、功能叫什么、7.11 的规矩，给两条路：停下等修好的修补版用 `sop self upgrade` 换上；或放弃这个功能（`sop feature drop`）再退。主线、事件日志一点不动。
6. 否则和升级走同一段代码 `switch`：登记分支 `upgrade/<上一个版本>-<序号>`（**沿用 6.4 升级分支的名字**，没另起名字）、写新的 `sop.json`、把上一个版本的检查流程复制过来、先写放行再推送、草稿 PR 转正式、等检查、合并（私有仓库请小白点）；有进行中的功能时把主线合进功能分支、进行中的工单分支 `wt sync --merge` 跟上；记一条 `工具包退回`。提交和 PR 标题写「工具包退回到 …」。
7. 合并后，经启动器执行的 `sop` 按主线 `sop.json` 用的就是旧版本。

### 不在项目里：`sop self rollback`（设计书没写，自己定的）

**理由**：项目外面的命令（`sop machine …`、`sop project new/clone`、`sop self report`）用的是 `versions/latest`；最新的版本要是在这些命令上出了错，没有项目可退，小白也得有办法退回去。同一个命令按在不在项目里分：在项目里退项目的，不在项目里退项目外面用的，说明里两边都写清。

1. 上一个版本按 `versions/history` 找（新文件：`write_launcher` 每次把 `latest` 换成别的版本时在末尾记一行；有 history 之前就装着的那个版本第一次也记上，所以 3-43 之前第零步装的也退得回去）。版本栈规则和项目里一样；history 没跟上 `latest` 时以 `latest` 为准。
2. 上一个版本同样只从本机已装好的里找、先核对（同上 4），不行就拒绝，`latest`、启动器一点不动。
3. **先备好再原子换**：`write_launcher` 写 `launcher.py`、`sop`、`latest`、`history` 都是先写同目录的临时文件（写完 `fsync`）再 `os.replace` 一下换名，出错就删掉临时文件；`latest` 在 `launcher.py`、`sop` 之后换，换之前目标版本已经核对过。中途哪一下断了，`latest` 要么还是现在的、要么已经是上一个，两个都是装好的完整版本；再执行一次 `sop self rollback` 能接着退好。
4. 项目外面没有「进行中的功能」，7.11 只在功能进行中挡大版本，所以这里大版本也能退（有单元测试）。

### 顺手改的一处原有毛病（升级也受益）

功能刚 `sop feature new`、还没执行过 `sop`（F1 还没建功能分支）时换修补版，升级合并后去取远程的功能分支，取不到报 `couldn't find remote ref`，整条命令失败（PR 已经合了）。改成远程没有功能分支就不做「主线合进功能分支」（F1 以后从新的主线建）。流程沙箱第一个剧本正好走到这里（改之前这一步不过）。

## 验证

- **单元测试 `tests/unit/test_rollback.py` 9 项**，都在临时 `SOP_HOME` 里现造几个版本目录（各是一个 Git 仓库，提交编号就是目录名，`kernel/main.py` 打出自己的名字），经**真的启动器**（`sop` → `launcher.py` → `versions/latest`）执行看用的是哪个：
  - 版本栈的六种走法；项目的版本栈按主线 `sop.json` 历史（A→A 改别的字段→B→退回 A→C 得 [A, C]）。
  - v1 → v2 后退回：`latest`、`launcher.py` 换成 v1 的，经启动器执行打出「我是版本 v1」，没留临时文件；再退说没有上一个；装了 v3 再退回到 v1。
  - 只装过一个、一个都没装：说清楚。
  - 有 history 之前就装着的版本也退得回去；同一个版本重复写不改 history 的修改时间。
  - 上一个版本不在、不完整、被改过、不是那个提交：四种都拒绝，`sop`、`launcher.py`、`latest`、`history` 逐字节不变，启动器照样用 v2。
  - **中途断了**：换名那一下、`fsync` 那一下、写文件写到一半（拦 `open`，不管写临时文件还是直接写正式文件都拦得到），各在第 1、2、3 个文件断一次，共 9 种：每种之后 `latest` 指的都是装好的完整版本、经启动器能执行、不留临时文件，再退一次结果和没断过一样。
  - 项目外面大版本也能退；多给参数打用法。
- **流程沙箱 `tests/sandbox/test_rollback.py` 2 个剧本**（本机假远程、假 gh，经启动器执行）：
  - 新项目退回 → 没有上一个版本；开功能后换上一个「修补版」（门禁命令表写错了），F15 崩；把上一个版本的目录挪走 → 说清本机没有装、不联网下载，主线 `sop.json` 不变；挪回来退回 → 说「上一个 …（修补版）」「工具包已退回到 …」，主线 `sop.json` 是旧版本，放行事件里有 `sop.json`；接着 `sop` → F15 过了、功能做完，F1、F13 都只做过一次（没重做）；再退 → 没有上一个版本。
  - 没有进行中的功能时换上大版本（允许）；开功能后退回 → 拒绝（「大版本」「还在进行中，不能退」「sop feature drop」），主线一点没动；放弃功能后退回 → 成功（大版本）。
- **反着试**（改坏、看测试不过、改回）：
  - 去掉功能进行中挡大版本那一条：沙箱第二个剧本不过（退回成功了，退出码 0）。
  - 去掉核对本机装好的版本：「上一个版本不能用」四种全不过，另一项报错。
  - 版本栈不弹回（退回过的还算上一个）：版本栈、项目版本栈、退回后再退、中途断了（6 种）都不过。

## 和设计书的出入（留给 3-48）

1. **不在项目里也能 `sop self rollback`**，退的是 `versions/latest`（设计书只写了项目里的）；新文件 `versions/history`（3.2 的目录没有）。
2. **退回去的版本只从本机已装好的里找，不联网下**（主控窗口给的要求；设计书没写）。代价：换了电脑 `sop project clone` 之后，本机没装过上一个版本，就退不回去，只能等修好的版本。另一条路是像升级一样按提交编号从工具包仓库装（启动器本来就会这样装、装好核对提交编号），用户可以选。
3. 退回的分支沿用 `upgrade/<版本>-<序号>`（6.4 只给升级定了名字），事件 `register` 多一个 `back` 字段，记录叫「工具包退回」。
4. 「上一个版本」定为版本栈里的下一个（退回过的弹掉），设计书没细说。
5. 16.5 的「前提是上一个版本没有这个毛病」没法自动判断；版本栈保证不会退回到刚退掉的那个。

## 没做的

- **退回的版本里少了的检查流程文件不删**：退回时只把上一个版本的检查流程复制过去，新版本多出来的文件留着（和升级一样，原来就是这样）。修补版之间一般不加减检查流程文件；真碰上要删，得想清楚删文件怎么写放行，没做。
- 退回走 PR 到一半断了（PR 没合）：和升级一样，再执行一次会登记下一个序号的分支、上一个工作目录留着，没另做收拾。这期间主线 `sop.json` 没变，启动器照旧用现在的版本，不会指向不存在的版本。
- 「升级后门禁自检不通过则退回」（7.11）不是这个任务，没接。
- 真 GitHub 上没走（工具包仓库在 GitHub 上的 PR 要四个检查全绿，项目试验仓库是 3-26）。
