## 问题

T1 开工单目录时按档案的 `setup` 在受限侧装依赖。`sop project clone` 在另一台电脑上重建出来的工单目录，日志里 T1 早就做完了，流程命令不会再装，
档案有 `setup` 时后面的门禁、实现可能跑不起来（7.2 末尾「项目的依赖由流程命令随后在受限侧安装」）。

顺带查出来：**功能目录在哪台电脑上都没装过依赖**，F15 却在功能目录里跑完整门禁。档案 fake 的 `setup` 是 `true`，所以以前的沙箱看不出来。

## 做了什么

- `kernel/steps.py` 新函数 `ensure_deps`：这台电脑上这个工作目录没有对得上的「装过依赖」记号，就在受限侧按档案的 `setup` 装，装好写记号。
  - **记号**放在 `state/<项目名>/deps/<目录名>.json`（项目根外面，受限侧碰不到，6.2 第 2 条），记着目录名、目录的设备号和 inode、档案名、
    没展开的 `setup` 命令（不带工具包的路径，所以升级工具包不会每次重装），另记什么时候、哪一步装的。
  - 目录删了重建（inode 不一样）、档案换了 `setup`、记号坏了，都算对不上，重装。删目录（`wt done`、`wt rm`，都经 `Project.wt_remove`）时把记号一起删。
  - 装不好：这一步记「没通过、停在这里」（和 T1 原来装不好一样），不写记号，下次执行 `sop` 接着装。
  - 档案没有 `setup`、还没选档案、目录不在：什么都不做。
  - 和以前不一样的一处：T1 被打断重做时，以前每次都重装；现在装完写了记号的不重装（没装完就被打断的没有记号，照样重装）。
- **什么时候装**：T1 开工单目录时（原来的那段代码换成调它）；另外在**每个会运行项目代码的步骤开始前**（`kernel/steps.dispatch`）：
  门禁 T5、F15，工单上的实现 T3、T6、T7、T14。划法和「给不给专用 Docker 通道」是同一条（6.3 四：会运行项目代码的才给），
  复查、规划、人的步骤、开 PR、合并、清理不运行项目代码，不装。所以：
  - A 上 T1 装一次，之后 T3、T5 记号对得上，不再装；
  - B 上重建的工单目录，在 B 上第一个要运行项目代码的步骤之前补装一次；一直走不到这种步骤的（例如只剩验收、合并），不装；
  - 功能目录在第一次 F15 之前装一次。
  - 补装时停下的报告「刚才自动做了什么」里多一行「装依赖：这台电脑上 <目录> 还没装过依赖，先在受限侧装好了」（T1 自己就是开目录装依赖，不另列）。
- 测试用的档案 fake：`setup` 从 `true` 换成 `setup.py`，每装一次在目录里 `.fake-deps/installed.log` 记一行（目录里放一个忽略一切的 `.gitignore`，
  像 `node_modules` 那样被 Git 忽略，工作区还是干净的）；门禁 `gate.py` 把「这个目录装过几次」写进报告 `deps_installs`。
