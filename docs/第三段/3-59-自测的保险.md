# 3-59 自测的保险：起 `sop` 子进程的测试一律用临时主目录

2026-11-21，主控窗口派的子代理做的。**没调用 AI，0 美元**；没碰 GitHub；没用 sudo；没动 Docker；没开虚拟机。本机那些文件跑前跑后逐项比对，**一样都没变**（见「本机有没有被改」）。

## 做之前查到的

- 本机 PATH 里在主目录下的：`~/.opencode/bin`、`~/tools/docker/bin`、`~/.nvm/.../bin`、`~/.local/bin`（真的 claude、codex、pi、uv、wt 都在这里）。真的 gh 在 `/usr/bin/gh`（系统目录，去不掉）。
- 终端里有 `ANTHROPIC_` 开头的密钥和地址、`CLAUDE_CODE_` 开头的本会话变量、`DOCKER_HOST`、`DOCKER_CONFIG`、`SSH_AUTH_SOCK`、`NVM_` 开头的。
- 起子进程的测试多数是 `{**os.environ, …}`，继承测试进程的整套环境；`TempHome` 原来只换 `SOP_HOME` 和运行时目录。所以测试进程自己的 HOME 是真的，任何漏设 HOME 的子进程就在真的主目录里跑（3-12 那次就是这样）。
- 从零拼环境时要是漏了 HOME，Python 的 `Path.home()` 会退回去查账号记录，还是真的主目录。
- 会写主目录的入口：`shellenv.install_block`（`~/.bashrc`，M2 和第零步都用）、`ghsetup.setup`（`~/.ssh`、`~/.gitconfig`）、`globalrules.install`（各 AI 工具的全局规则文件）、`install.install` 和 `install_tool`（Docker 的用户级服务登记写 `~/.config/systemd/user`，系统软件包要管理员密码）、`aisetup.setup`（登记写在工具包根目录下，但会真调 PATH 里的 claude）、`wtsetup.install`（经 `install_tool`）。
- 测试里有几处是故意只读用本机真的主目录：`test_machine_wt.py` 从 `~/tools/wt` 克隆一份、`test_machine_space.py` 读 `~/tools` 下 Docker 的规则名、`uv`、`wt` 从 `~/.local/bin` 找。

## 做了什么（两层）

### 一、测试这一侧：默认就是假主目录

- **`tests/safehome.py`**（`tests/__init__.py` 导入它；`run_all.py` 开头也 `import tests`，只跑总检查时一样生效）。tests 这个包一被导入，整个测试进程：
  - HOME、`XDG_CONFIG_HOME`、`XDG_CACHE_HOME`、`XDG_DATA_HOME`、`XDG_STATE_HOME` 指到 `/tmp/sop-test/shared-home-*`（现建，进程结束删掉）；
  - 去掉 `ANTHROPIC_`、`CLAUDE`、`OPENAI_`、`CODEX_`、`OPENCODE_`、`GEMINI_`、`GH_`、`GITHUB_`、`DOCKER_`、`NVM_` 开头的变量，以及 `SSH_AUTH_SOCK`、`SSH_AGENT_PID`、`GPG_AGENT_INFO`、`PNPM_HOME`、`npm_config_*`；
  - PATH 去掉本机主目录下的目录（仓库自己的 `.venv` 留着）；测试要用的 uv、uvx、wt（只用不改）链接进假主目录的 `bin`，放在 PATH 最前面。所以测试里找不到真的 claude、codex、pi、opencode；
  - 假主目录里放一份只有测试身份的 `~/.gitconfig`（见「自己出的错」第 1 条）；
  - 设 `SOP_UNDER_TEST=<假主目录>`，工具包那一侧认它。
  - 子进程又导入 tests 时（HOME 已经是那个假主目录）什么都不做。
  - 要只读地用本机真的主目录时用 `tests.safehome.REAL_HOME`（按账号记录取）：`test_machine_wt.py` 的 `LOCAL_WT`、`test_machine_space.py` 改成用它。
- **`TempHome`**（`tests/helpers.py`）：每个测试另外有自己的主目录 `<临时根目录>/test-home`（HOME 和 XDG_* 跟着它，里面也放那份测试身份的 `.gitconfig`）。测试自己另设 HOME 的照样可以设。

这样一来，测试漏设 HOME 时：用了 `TempHome` 的，落在这个测试自己的临时主目录里；没用 `TempHome` 的，落在公用的假主目录里，而那里会被第二层挡住。

### 二、工具包这一侧：会写主目录的入口先过一道保险

- **`kernel/paths.guard_home(what)`**，抛 `paths.HomeGuard`（是一种 `SopError`）。两种情况停下，一个字都不写：
  1. 主目录就是自测那个公用的假主目录（`SOP_UNDER_TEST` 的值）：说明这个测试没给自己设 HOME。
  2. 主目录是这个账号真的主目录（按账号记录取，不看 HOME；链接到它也算），或者 HOME 没设，同时环境里有自测的痕迹：`SOP_HOME`、`SOP_TOOLS_DIR`、`SOP_PROJECTS_DIR` 不是默认的位置，设了 `SOP_TOOLS_TOML`、`SOP_RUNTIME_DIR`、`SOP_UNDER_TEST`，或者 HOME 没设。用户自己平常执行时这些变量都没有，不受影响（虚拟机里的验证脚本也没设这些，查过 `tests/vm/*.sh`）。
- 接在：`setup.run`（一开头，进度、锁都还没写；`setup.main` 接住它，打一句话、退出码 1）、`install.install`、`install.install_tool`（真跑安装脚本之前；已经装好的照样只查）、`shellenv.install_block`（只在写默认的 `~/.bashrc` 时；调用的人明确给了别的文件就照写）、`ghsetup.setup`、`globalrules.install`、`aisetup.setup`、`wtsetup.install`（经 `install_tool`）。
- 报的话例如：「自测的保险：sop machine setup 要改主目录里的东西，主目录却是这台电脑真的主目录 /home/…，而环境像是在自测里（SOP_HOME 指到 /tmp/…；…）。什么都没做。请在测试里把 HOME 指到临时目录」。

## 证明保险有效

### 自动的测试（在全部自测里）

- **单元测试 `tests/unit/test_home_guard.py` 14 项**：
  - 测试进程本身：HOME 是公用的假主目录、在 `/tmp/sop-test` 下、不是真的；XDG_* 跟着它；没有 AI、GitHub、Docker、SSH 代理的变量；PATH 里没有本机主目录下的目录（`.venv` 除外）；claude、codex、pi、opencode 找不到真的；子进程继承的也是假主目录；`TempHome` 的测试有自己的主目录。
  - **故意漏设 HOME**（这几项故意不用 `TempHome`、不设 HOME）：`setup.run`、`install.install`、`install.install_tool`、`shellenv.install_block`、`ghsetup.setup`、`globalrules.install`、`aisetup.setup`、`wtsetup.install` 一个个都被挡住；公用假主目录里每一样的大小和修改时间都没变，工具包根目录、工具目录都没被建出来；setup 的步骤一步都没调。**3-12 出事的那个测试原样再来一次**（用测试进程的整套环境执行 `sop machine setup`）：退出码 1、说「自测的保险」、一步都没开始、什么都没写。
  - 「真的主目录」那几种：把 `paths.account_home` 换成 `/tmp` 下一个「装作是真的」的目录（不拿本机真的主目录试）。平常用（HOME 是真的、自测变量一个没有，或者变量写的就是默认位置）不挡；带着 `SOP_HOME`、`SOP_TOOLS_DIR`、`SOP_PROJECTS_DIR`、`SOP_TOOLS_TOML`、`SOP_RUNTIME_DIR`、`SOP_UNDER_TEST` 任一样都挡；HOME 没设或是空的挡；HOME 是链接到真的主目录的也挡；测试自己的临时主目录带着自测变量不挡。整条入口：「装作是真的」的主目录加临时的 SOP_HOME（3-12 出事时的样子），写 `~/.bashrc`、写全局规则都被挡住，文件一个字没变；**对照**：把保险换掉，同样的调用在这个 `/tmp` 目录里就写了 `~/.bashrc`。
- **流程沙箱 `tests/sandbox/test_machine_setup.py` 加 1 个剧本** `TestForgotHome`：假「电脑」样样齐全、照样能装，只是 HOME 漏了（用的是继承来的公用假主目录）。`sop machine setup` 一开头就停下：退出码 1，什么都没装、假 sudo 没被调、没写进度，假「电脑」的主目录、工具目录、工具包根目录、公用假主目录里每个文件的内容和修改时间都没变。

## 没做的

- `runner/docker/service.py`（专用 Docker 的用户级服务登记写 `~/.config/systemd/user`）和 `runner/selftest.py` 没接保险：那是隔离的代码，动了要再开一次独立审查；测试里它们已经被第一层（假主目录、`XDG_CONFIG_HOME`、`SOP_SYSTEMD_USER_DIR`）罩住。`syscheck.prepare` 只写工具包根目录下的登记，也没接。要的话以后单拆一个任务，这次没拆。
- `python -m machine.globalrules`、`machine.ghsetup`、`machine.install`、`machine.aisetup`、`machine.wtsetup` 这几个给虚拟机验证用的直接入口，被挡住时打的是 Python 报错（保险那句话在最后一行），没改成一句话；`sop machine setup`（小白用的那条）是一句话、退出码 1。
- 从零拼环境、漏设 HOME 的子进程，只有第二层管（第一层罩不住，Python 会退回去用账号记录里的主目录）。这种情况在自动测试里只在进程内调 `guard_home` 验，没在子进程里真跑（真跑万一保险坏了就会写真的主目录）；子进程那一遍是上面手动演示的，在只读的 bubblewrap 里。
