## 做了什么

照 3-33、3-34 的验收脚本加了「免管理员但位置不对」（没另起一份，三种共用）：

- `tests/vm/migrate-io.sh <虚拟机名字> [--ce | --rl] [--reboot]`：加 `--rl`。
- `tests/vm/migrate-io-guest.sh --prepare rl`：先记下装之前的样子（系统文件、软件包，另加**主目录里的全部路径**和 `~/.bashrc`），再**照 Docker 官网的免管理员装法**装一份：
  - `sudo apt-get install uidmap`；给 `~/bin/rootlesskit` 写官网原文那条系统安全规则 `/etc/apparmor.d/home.xiaobai.bin.rootlesskit`、`sudo systemctl restart apparmor.service`；
  - `curl -fsSL https://get.docker.com/rootless | sh`（经本机代理）。官方脚本（29.10.0）第一次说缺系统要求、给出 `sudo sh -x` 要执行的命令（`modprobe nf_tables`），脚本照它给的命令做了再跑一次，装好：程序 11 个在 `~/bin`，用户级服务 `docker`（`~/.config/systemd/user/docker.service`，登录后自己起来），数据在 `~/.local/share/docker`，建了默认指向 `rootless` 并切过去；
  - 照它最后的提示往 `~/.bashrc` 加了 `export PATH=/home/xiaobai/bin:$PATH`（脚本从官方脚本的输出里取，原样加）；
  - 拉镜像要经本机代理：照官网的办法加了 `~/.config/systemd/user/docker.service.d/proxy.conf`；照网上教程在官网写的免管理员设置文件 `~/.config/docker/daemon.json` 里限了日志大小；
  - 放的镜像、卷、容器和 3-33 一样（在跑的「数据库样子」的 `shop-db-1`，里面的数据归 70:70，宿主上是映射出来的账号，小白自己删不掉）。
- `--run1`：规定位置的 Docker 先不装。第一遍 `sop machine migrate`，Q4 打包时 kill -9 整组。新加的核对：Q2 看到 `docker` 这个服务名被原来那份占着、**规定位置这份另起服务名 `sop-docker`**（通道 `/run/user/1000/sop-docker/docker.sock`，在跑、登录后自己起来），**原来那份的服务登记一个字没动、照样在跑**，两份同时连得上、各用各的数据目录，默认指向还是原来那份的 `rootless`。之后下一次 `sop` 把旧容器起回来（和 3-33 一样）。
- `--run2`：先建一个指着 `sop-docker` 的默认指向 `sop-new` 切过去（模拟小白自己切过），第二遍走完 Q1 到 Q6，Q6 切回原来那份之后暂停看。新加的核对：
  - sop 说的先后：先停旧的 → 先删数据（**自己删不掉，借旧的 `~/bin/rootlesskit` 删**）→ 再删程序和服务登记 → 删系统安全规则 → 接过服务名；
  - `~/.local/share/docker`、`~/bin` 里的 11 个程序、`~/.config/docker` 都没了；旧的系统安全规则文件删了、也从系统里拿掉了（`/sys/kernel/security/apparmor/profiles` 里没有），规定位置那份自己的还在；
  - **接过默认的名字**：`~/tools/docker/etc/docker-host` 换成 `unix:///run/user/1000/docker.sock`，`sop-docker.service` 删了、系统里查不到，`docker.service` 现在启动的是 `~/tools/docker` 的程序、在跑、登录后自己起来；照官方提示设 `DOCKER_HOST=unix:///run/user/1000/docker.sock` 的程序连到的也是规定位置那份；
  - 残留清单自己逐项再查：`~/.config/systemd/user/docker.service` 和 `default.target.wants/docker.service` 这两项卸完又在了——是规定位置那份接过服务名以后的（启动的是 `~/tools/docker` 的程序），按这个认；
  - 主目录和装之前比：多出来的里没有旧 Docker 的（只剩 `~/.docker` 的默认指向、接过来的 `docker.service`），原来就有的一样没少；`~/.bashrc` 里小白自己加的那一行没被动、sop 提醒了；
  - **再装一遍规定位置的 Docker**（以后升级工具包就是这样）：安装脚本 `--plan` 认它是自己的（`unit=docker`），真装一遍后服务登记文件一个字没变、修改时间也没变（安装脚本看着一样就不写）——即接过来的和安装脚本自己按 `docker` 这个名字写的一字不差；通道、带走的卷都在。
- `--after-reboot`：另看登录后自己起来的 `docker` 是规定位置那份、没有 `sop-docker` 了。

验收标准逐条：

1. **用正式命令走通 Q1 到 Q6**：两遍 `sop machine migrate`（第一遍 Q4 被 kill -9，下一次 `sop machine tools` 起回旧容器、删临时小镜像）；第二遍 Q1 认成「免管理员的 Docker，但不在规定位置」，Q4 打包、试还原、核对，Q5 核对，Q6 退出码 0；卸完敲 docker 是规定位置那份，带走的两个卷内容、归属（70:70，含符号链接）、权限、项目标签和原来一样，重启后也对。

5. **残留为空**：sop 说「残留清单 17 项逐项又看了一遍，都没有了」；脚本按 Q1 存的清单逐项再查也为空（两项是接过来的，见上）；和装之前的系统比：软件包只多了规定位置那份要的 `uidmap`、`libsubid5`，系统文件多出来的只有规定位置那份的系统安全规则（和系统自己的软件目录缓存），主目录里多出来的没有旧 Docker 的。

## 验出的真问题（已改正式代码，加了单元测试）

1. **官网写的免管理员设置文件 `~/.config/docker/daemon.json` 不在残留清单里，卸完会留下，sop 却说「都没有了」。** 规定位置那份启动时用 `--config-file ~/tools/docker/etc/daemon.json`，不读它，留着就是旧 Docker 的残留。反着试：虚拟机里只把这次的改动去掉，同样的流程 sop 说「16 项都没有了」，主目录里却还有 `~/.config/docker/daemon.json`（脚本 3 项「不对」）。改法（`machine/migrate/inventory.py`）：`~/.config/docker` 在就列进残留清单（排在程序后面，删程序时一起删，不是数据）；里面除了 `data-root` 还有别的设置的，Q1 和卸完都提醒一句「规定位置那份不读它（它的设置在 `~/tools/docker/etc/daemon.json`）；卸掉旧的时这个目录一起删，要用的设置先记下来」。
2. **Q1 提醒「`~/.bashrc` 里有照官方装法加的几行」认不出官方脚本真提示的那一行。** 官方脚本提示的是写死主目录的 `export PATH=/home/xiaobai/bin:$PATH`，原来只认 `$HOME/bin`、`~/bin`（还会把 `~/bin2` 当成）。改成也认写死主目录的，`~/bin` 后面跟着别的字母的不算。

单元测试加 2 项（`test_rootless_config_dir_and_bashrc_written_out`、`test_rootless_bashrc_without_old_lines`），`test_migrate_uninstall.py` 的免管理员那组造了 `~/.config/docker/daemon.json`、核对卸完它没了；去掉改动这 3 项都不过。

## 看到但不是问题的

- 卸完 `~/bin` 是个空目录、`~/.local/share` 等空目录留着：`~/bin` 是 Ubuntu 给小白放自己程序的地方（`~/.profile` 在它存在时把它放进 PATH），不知道是不是官方脚本建的，不删；残留清单只列官方脚本放进去的那 11 个程序（3-32 定的，`~/bin` 里小白自己的程序不动）。
- `~/.bashrc` 里照官方提示加的 `export PATH=/home/xiaobai/bin:$PATH` 留着（工具包不改小白的终端启动文件，只提醒）。`~/bin` 里没有 docker 了，敲 docker 是规定位置那份，不影响。
- 小白自己建的、指着 `sop-docker` 通道的默认指向（这次的 `sop-new`）卸完后指着一条不在了的通道。Q6 切回原来那份、卸完再切到「指着新通道的那一个」（`rootless`），默认的不是它；它只是 `docker context ls` 里多一行。工具包自己没建过指着 `sop-docker` 的默认指向（3-09：规定位置那份用 `sop-docker` 时不跑官方脚本），所以不去删小白自己建的。
- 官方脚本提示的 `sudo loginctl enable-linger`（开机不登录也起来）这次没照做：3-17 定的专用 Docker 不开 linger，旧的这份开没开不影响卸载（停服务、取消登录后自己起来照样做）。
- 规定位置那份接过服务名时要停一下再起来，带走的容器按各自的重启设置回来（这次带走的只有卷和镜像，没有在跑的容器）。

## 和设计书的出入（留给 3-48）

1. 4.8 Q6 免管理员那种的残留要补 `~/.config/docker`（官网写的免管理员设置目录），删程序时一起删；里面有设置的先提醒。

## 没做的

- 和 3-33、3-34 一样：没走第零步装的启动器；真的输管理员密码（虚拟机 sudo 免密码）没验，留给 3-15。
- 旧的这份停着、要先起来的那条路（`systemctl --user start docker.service`）没在真虚拟机里走（这台的旧的一直在跑）；没用后台服务、自己跑着的那种（工具包不卸）也没在虚拟机里造，单元测试有。
- 免管理员但程序在 `/usr/bin`（`docker-ce-rootless-extras` 带的、和 docker-ce 一起装的）那种没在虚拟机里走，单元测试有。
- 旧的这份在 `daemon.json` 里另指数据目录的，没在虚拟机里造（单元测试有）。
- 旧的设置（例如国内常配的镜像加速 `registry-mirrors`）不会搬到规定位置那份，只提醒；而规定位置那份的设置文件由安装脚本每次重写（数据位置、代理），小白自己加的设置重装时会被盖掉——要不要让工具包管「小白自己的 Docker 设置」，没有任务管，写在这里留给 3-48 一起看。
