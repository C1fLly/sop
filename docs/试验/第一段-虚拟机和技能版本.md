## 一、验证用的虚拟机

### 装的什么、装在哪

- 虚拟机软件：**QEMU**（`qemu-system-x86`、`qemu-utils` 两个软件包加它们依赖的十几个小包），用户本人 2026-11-18 在自己的终端里执行脚本、输了管理员密码装的（脚本 `docs/试验/脚本/第一段/虚拟机/装虚拟机软件.sh`，先用大白话说明要装什么、装在哪）。装在系统盘上，属于必须占的。没有加开机自动运行的服务。
- 选它的理由：命令行就能用、不要常驻的后台服务、磁盘文件想放哪就放哪。VirtualBox 要往系统里装内核模块；multipass 默认把数据放在系统盘上。
- 这台电脑的处理器支持虚拟化，用户的账号本来就能用虚拟化设备，不用改用户组。
- 虚拟机的磁盘文件在 `~/sop-vm/`（主目录那个分区），设计书 16.4 定的位置。现在一共 6.9 GB：两台的系统盘、vm-a 的主目录盘、下载的官方云镜像（822 MB）、自动配置用的文件、登录虚拟机用的专用钥匙（不碰 `~/.ssh`）。

### 两台虚拟机

用 Ubuntu 官方的 26.04 云镜像（下载后核对了官方给的校验值），开机时由 cloud-init 照写好的配置自动建账号、分盘、配代理，不用人点。脚本 `vm.sh`。

| | vm-a | vm-b |
|---|---|---|
| 分区 | 主目录单独一块盘（`/home` 在 `vdb1`），模拟「装系统时把主目录单独分一个区」 | 只有一个系统分区（另有系统自带的 `/boot`、`/boot/efi`） |
| 配置 | 4 核、4 GB 内存、系统盘 40 GB、主目录盘 30 GB | 4 核、4 GB 内存、系统盘 40 GB |
| 系统 | Ubuntu 26.04.1 LTS | 同左 |
| 上网 | 经这台电脑的代理（虚拟机里 `10.0.2.2` 就是这台电脑） | 同左 |
| 开机到能登录 | 28 秒 | 26 秒 |

虚拟机里的账号 `xiaobai` 免密码 `sudo`，只在虚拟机里，代表「小白输管理员密码」的那几步。

不用时已关机，不占内存。以后工具包的装机、迁移部分有改动，用 `vm.sh start a`（或 `b`）再开。

### 和设计书写的「全新安装」不完全一样

设计书第 19 节写的是「两台全新安装的 Ubuntu 虚拟机」「用 Ubuntu 的全自动安装配置写明分区」。这次用的是官方云镜像加开机自动配置，不是跑安装程序：

- 好处：几十秒建好、完全由脚本做、不要人点。对第一段要验的东西（分区情况、迁移、专用 Docker、nvm 和 uv）效果一样。
- 差别：云镜像是服务器版，没有桌面、没有系统钥匙串和 SSH 代理的通道。第 1 期第三段要验「全新电脑从第零步走到体检全部通过」，那时要用桌面版的安装程序装一台，隔离自检要挡的那几样凭据通道才齐全。

### 没做的：桌面安装程序里怎么手动给主目录分区

第 19 节第一段要「顺带核实：Ubuntu 26.04 的安装程序里手动给主目录分区怎么点、系统分区留多大合适，写进小白手册」。**没有做。** 这要下载几 GB 的桌面版安装镜像、在有图形界面的虚拟机里一步一步点安装程序并截图，用户不在场时做不了截图的核对。网上的 26.04 安装教程写着有「手动安装」选项，能把一个分区设成 `/home`（经网页摘要读到，见设计书附录 C），没有亲手核实。挪到第 1 期第三段，和「桌面版装一台做第零步」一起做。
