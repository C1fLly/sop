# 第一段：7.6 路径补的锁

状态：已完成（2026-11-18）。v0.6 在 7.6 的路径（原样运行 `implement-spec`）上补的锁，锁上之后原来的做法照样走得通；特权侧「先核对小文件再碰目录」能拦住被改过的工作目录。

没有调用 AI，没有花钱，没有连 GitHub（远程是本机的假远程）。脚本在 `docs/试验/脚本/第一段/7.6的锁/`。

## 要验证什么

设计书第 19 节第一段：「7.6 补的锁：功能目录的那两个小文件锁住之后，原来的做法还走不走得通。本机做，不调用 AI。」以及 7.6 里 v0.6 加的几条：项目根下不属于本功能的其他工作目录盖成只读；运行中才建的工单目录，特权侧每次先核对它的三个小文件内容符合预期，再去碰它；核对公共配置里没开「工作目录专用配置」的扩展。

## 怎么做的

- 用 wt（带工具包的模板）建了一个项目：本功能的功能目录 `feat-demo`，另一个功能的目录 `feat-other`，`main` 目录；三张工单。
- 受限环境照 S7 的放法放进整个项目根，再加上 v0.6 补的锁：功能目录登记里的 `commondir`、`gitdir` 只读；`feat-other` 目录和它的登记只读。
- 窄接口的特权侧（`broker.py`）照 S7 的那一份，加了一个核对函数：报告已合入、报告全部完成时，先核对相关工作目录里指向 `.git` 的小文件、登记里的 `commondir` 和 `gitdir` 内容符合预期，公共配置里没开那个扩展，都对才继续。
- 在受限环境里手工走一遍（不调用 AI）：要目录、在工单目录里提交、在功能目录里本地合并、报告已合入；再试几样越界的。

## 结果

| 做的事 | 结果 |
|---|---|
| 工单 01、02：经窄接口要目录、提交、在功能目录里本地合并、报告已合入 | 都成功，特权侧核对后推送。功能目录登记里那两个小文件锁着，本地合并照常 |
| 改功能目录登记里的 `commondir`、`gitdir`，改功能目录里指向 `.git` 的小文件 | 都报「只读」 |
| 写另一个功能的目录、写 `main` 目录 | 都报「只读」 |
| 工单 03：先把它目录里指向 `.git` 的小文件改成指向一个假仓库（运行中才建的目录，这个文件设不成只读，预料之中），再报告已合入 | **特权侧拒绝**：「核对小文件不通过，不碰这个目录：……的内容被改过」 |
| 改回原样再报告 | 通过、推送 |
| 报告全部完成 | 通过 |
| 事后核对：全部工作目录、三张工单都已合入、远程和本地一致、功能目录干净、`main` 没动、四个目录的三个小文件都符合、没开扩展 | 全部符合。事后核对里进到功能目录执行的那条只读命令，两个小文件锁着也照常 |

## 结论

1. v0.6 在 7.6 路径上补的锁可行，原来的做法不受影响。
2. 「先核对小文件再碰目录」能拦住运行中才建的工单目录被改过的情况。
3. 这次是手工走的，没有让 AI 跑；第 2c 期用 AI 原样运行 `implement-spec` 时再跑一次（第 19 节第 2c 期的验收标准里已有）。

## 没做的

- AI 原样运行 `implement-spec`（第 2c 期）。
- 工单之间有冲突、合并帮手自己解决冲突（第 2c 期）。
- 依赖由特权侧另起受限脚本安装（v0.7 写的做法）：这个项目没有依赖，没有试到。
