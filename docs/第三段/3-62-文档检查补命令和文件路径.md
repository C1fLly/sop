### 怎么认「命令」

- 只看反引号里的，代码块（```）里的不看。设计书里的 `sop …` 全在反引号里（查过：反引号外一处都没有）。
- 命令的词到第一个 `<…>`、`[…]`、`--` 为止，要正好是命令表里的一条。后面还跟着别的词（`sop feature new login`）只有那条命令要填参数才行；`sop status now` 报错。`sop machine …` 这样以省略号结尾的算一组命令的统称，要有以这几个词开头的命令。
- 开关（`--readonly` 之类）不核对。

### 还没做的命令怎么处理（自己判断的）

设计书 8.5 列了全部命令，其中 20 条要后面的任务或后面几期才做。三种办法：一律算悬空（设计书本来就该写以后的命令，这样检查永远红，只能放松）；一律不查（就什么都不查了）；**写进命令表的 `PLANNED`，每条写明排在哪（选了这个）**。为了不让 `PLANNED` 变成什么都能放的地方：单元测试要求它每条都是设计书里写着的、现在代码里确实分派不到；做好了不挪到 `DONE` 单元测试就不过。检查算它通过，但把还没做的逐条打出来（现在 20 条）。

排在哪是按设计书第 19 节和任务清单写的：`self report` 3-42、`self rollback` 3-43、`self fix` 3-45；`accept`、`profile test` 第 2a 期；`guide`、`standards`、`feature change`、`feature revert` 第 2b 期；`repair`、`health`、`backup`、`backup restore`、`machine clean`、`project remove`、`self uninstall` 第 3 期；`release`、`incident`、`prod doctor` 第 3 期且部署相关暂缓；**`check [步骤]` 设计书 8.5 有，还没排进哪个任务**。

### 怎么认「仓库内的文件路径」

- 反引号里不带空格、带「/」、第一段是工具包仓库最上一层的东西（3.2 那张目录，加上仓库里实际有的 `.github`、`README.md` 等）的，算工具包仓库里的路径，要存在。`<…>` 和 `*` 当通配，至少对上一个；以「/」结尾的要是目录。
- **目录要里面有文件才算有**：Git 不记空目录。本机的 `profiles/`、`guide/`、`templates/project/docs/agents/` 都是空目录，GitHub 上取出来就没有；不这样认会本机过、GitHub 上不过（在 `/tmp` 按 `git ls-files` 造的副本上先碰上了，见「自己出的错」）。
- `~/tools/sop/dev/…` 是开发仓库里的，同样查；`~/tools/sop/…` 的第一段要是装好的目录里有的（`sop`、`config`、`state`、`versions`、`dev`），后面的不查（是电脑上的状态）。别的 `~/…`、`/…` 都是电脑上的位置，不查。
- 项目仓库里也有 `docs/`、`.github/`。项目仓库里的路径按 `templates/project/` 里有的认，模板里还没有的列在检查里的 `PROJECT_ONLY`（`docs/agents/`、`docs/baseline/`、`docs/notes/`、`docs/product/risk.json`，加第一段 W21 试验仓库的 `.github/sop/`），每条写明是什么。不在这几样里的 `docs/…` 一律当工具包的查。
- 还没有的路径没有类似 `PLANNED` 的表：写进文档时不放反引号、写明「还没有」（README 的 profiles/ 就这样改的）。
