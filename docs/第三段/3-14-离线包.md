# 3-14 离线包

2026-11-20。主控窗口派的子代理做的。没调用 AI、没花钱。真的下载、apt、sudo、断网只在虚拟机里做（`tests/vm/vm.sh new`，全新的 `one` 底盘，虚拟机里用了 sudo，用户 2026-11-19 已答应）；本机没用 sudo、没起网页服务、没动网络设置，只跑了单元测试和全部自测（都在 `/tmp` 的临时目录里）。打出来的离线包约 45 MB，只在虚拟机和 `/tmp` 里，没进 Git 仓库。

## 做了什么

- **离线包是一个文件**：`sop-offline-<提交编号前 8 位>-<处理器>.sh`（约 45 MB）。小白在能上网的电脑上下载、U 盘拷到断网的电脑，在终端里执行 `bash <这个文件>`。文件开头是一小段 bash（`machine/offline/header.sh`）：先按写在里面的校验值核对文件有没有拷坏、拷全，再解到 `/tmp` 的临时目录，运行里面的 `bootstrap.sh --offline`，做完把临时目录删掉。后面跟着一个 tar，里面有：
  - `bootstrap.sh`：那个提交的第零步；
  - `debs/`：git、curl 和它们要的全部系统软件包（49 个，28 MB），按「什么都没装」算的，所以桌面版缺什么都补得上；带软件包索引（`Packages`、`Release`）；
  - `uv/`：uv 的官方压缩包（17 MB），打包时按官方给的校验值核对过；
  - `sop.bundle`：工具包仓库 `main` 连同历史的 Git 打包文件（1.1 MB），第零步照常用 git 从它取；
  - `VERSION`、`ARCH`。
- **打包脚本** `machine/offline/pack.sh --repo <工具包仓库> [--out <文件>]`：由做工具包的人在一台能上网的 Ubuntu 26.04 上运行，不用管理员密码、不改那台电脑。apt 的索引、下载缓存、「已装了什么」都放在 `/tmp` 的临时目录里（不上锁、不读系统 `apt.conf.d` 里的钩子），做完删掉。只用系统自带的东西（wget、dpkg-deb、sha256sum），不用另装 `dpkg-dev`。
- **`bootstrap.sh --offline <目录>`**：
  - 网络这一步不试连、不问代理，网络设置记成「不用代理」（`source: detected`），以后能上网了可以改；
  - 缺 git、curl 时只用离线包里的软件包装：一次 sudo，里面临时建一份只指向离线包的软件源设置和索引目录（`Dir::Etc::SourceList`、`Dir::State::Lists` 等指到临时目录），**系统的软件源设置和索引都不动**，用完删掉；
  - 工具包从 `sop.bundle` 取，取到的提交编号要和离线包写的一样；
  - uv 从离线包里的压缩包装（`machine/install/uv.sh` 加了 `SOP_UV_ARCHIVE`，给了就不下载）；之后的小帮手带 `UV_OFFLINE=1`；
  - 其余（分区报告、网络设置、启动器、`~/.bashrc` 那一段、出口检查、提示 `sop machine setup`）和在线一样。
- **虚拟机脚本**：`tests/vm/vm.sh` 加了 `new --offline`（QEMU 的 `restrict=on`：虚拟机连不到本机、也连不到外面，只留本机进虚拟机登录的那一个口；本机的网络设置一点没动）、`start --usb <镜像文件>`（把一个磁盘镜像当成 U 盘插上，USB 3 接口、可移动）、`pull`（拷文件出来）。`tests/vm/offline.sh`（本机）和 `tests/vm/offline-guest.sh`（断网的虚拟机里）把整个过程串起来，不进 `run_all.py`。

## 结果

### 单元测试

新加 `tests/unit/test_offline.py` 6 项：软件包索引的写法（现做一个小软件包，带日期、校验值）；uv 从压缩包装、一次都不下载（假 curl 一叫就算错）；拼一个离线包（工具包是本机的 Git 打包文件、uv 是转给跑测试这份的小包装），包头里的占位都填上了；`bash <离线包>` 从头跑完第零步，一次都没叫过 wget、sudo，版本对、网络设置不用代理、临时目录删了、主目录里只多 `tools` 和 `.bashrc`，再跑一遍都跳过；缺 git 时 sudo 传的是只指向离线包的软件源设置，离线包里没有软件包就停下明说；改一个字节、少一截都说「拷坏了」、什么都不装。

全部自测：做之前单元测试 151 项、流程沙箱 24 个剧本、总检查 62 个样例全过；做之后**单元测试 157 项**（多了这 6 项）、流程沙箱 24 个剧本、总检查 62 个样例，全部通过。

### 虚拟机（`tests/vm/offline.sh`，最后一遍 29 处全对）

1. 能上网的全新虚拟机 `offp`（经本机的代理上网）：打包 285 秒（大半是取软件源索引），出来 45 MB；打包的电脑上 `/tmp` 没留临时目录、主目录里只有拷进去的仓库和脚本。在里面做一个 160 MB 的 FAT 格式 U 盘镜像、把离线包拷上去，拷回本机 `/tmp`，然后删掉 `offp`。
2. 断网的全新虚拟机 `offa`（`--offline`），插上这个 U 盘：
   - 断网是真的：直连 GitHub、软件源连不上，经本机的代理也连不上，连不到本机；
   - 造成像桌面版：卸掉 git、curl；
   - 虚拟机认出 U 盘（`/dev/sda`，接口 usb、可移动），像桌面那样挂到 `/media/xiaobai/SOPUSB`；
   - `bash <U 盘上的离线包>`：小白一个问题都不用答，只有一次 sudo；2 秒做完。git 2.53、curl 8.18 从离线包装上，工具包版本对、版本目录没改过，uv 0.13.9 在 `~/tools/uv/bin`，网络设置「不用代理」，报告了分区，提示 `sop machine setup`；apt 没报警告；解开的目录和 apt 的临时目录都删了；**系统的软件源设置和索引没动**；
   - 新开终端（还是断网）`sop machine tools`、`sop machine doctor --readonly` 能跑；`~/tools` 之外只改了 `~/.bashrc`；`~/tools` 44 MB；
   - 再跑一遍：都跳过、不要密码、启动器、版本、`~/.bashrc` 不重写；
   - 改坏一个字节的离线包：说「拷坏了」、停下、什么都没装。

两台虚拟机用完都删了，本机 `/tmp/sop-offline-vm.*` 删了；没起任何网页服务（127.0.0.1:8765 那个不是这次的，没碰）。

## 没做的

- **离线包放在哪给小白下载还没定**：工具包的 GitHub 仓库还没建（3-41）。最顺的做法是每次发版时把离线包挂到仓库的 Releases 上，手册「完全连不上网」那一节给下载地址。挂 Releases 是在 GitHub 上改东西，拆成新任务 **3-51**（要等 3-41，做之前问用户）。
- 「另一台电脑」上的下载、真的 U 盘、桌面上自动挂 U 盘、文件管理器拖进终端都没试（虚拟机里是手动挂上的）；真的输密码那一下没验（虚拟机 sudo 免密码），和 3-13 一样留给 3-15。
- 只打、只验了 amd64 的；arm64 的打包写了处理器的对应关系，没试。
- 打包要在 Ubuntu 26.04 上做（软件包按那台电脑的软件源取）。软件包按「什么都没装」下，带了 libc6 这类基础包；断网的电脑上已有的更新的版本照用、不降级，但如果那台电脑比打包时旧（很久没升级），apt 会顺带把这几样基础包升到离线包里的版本。没造这种情况试。
- 离线包只管第零步。之后的 `sop machine setup`（nvm、Node、Docker、gh、wt、登录 GitHub 和 AI）都要上网，断网的电脑走不下去；设计书 4.2 第 3 条也只说了第零步。断网电脑能不能用工具包干活，设计书没说，留给 3-48 写明「离线包只解决第零步」。
- 断网的虚拟机开机要等约 134 秒（系统等网络就绪，等不到才放行），不影响结果。

## 和设计书的出入（留给 3-48 并入）

1. 4.2 第 3 条补上离线包的做法：一个自带校验的 `.sh` 文件，`bash <文件>` 运行；里面有什么；打包命令 `machine/offline/pack.sh`；系统的软件源设置不动。
2. 离线包装完网络设置记「不用代理」；只解决第零步，`sop machine setup` 仍要上网。
3. `machine/install/uv.sh` 多了 `SOP_UV_ARCHIVE`（从压缩包装）。

## 自己出的错

1. `uv.sh` 加「从压缩包装」那一段，第一次是用一段 Python 字符串替换改的，没加「必须找到」的检查，原文对不上就什么都没改，我没发现；单元测试报「下载不下来」才看出来，改用编辑工具重做。之后的替换都加了检查。
2. `install_apt` 里新加的一行用了 `$OFFLINE`，单独调用这个函数的老测试（没走 `main`，变量没定义）在「变量没定义就报错」下失败了；全部自测抓出来，改成 `${OFFLINE:-}`。
3. 第一遍虚拟机打包时下载 uv 的校验值文件失败了一次（本机直接下是好的，多半是经代理一时断了，3-08 也碰到过），打包脚本当时只试一轮；改成最多三轮，失败时把 wget 的原话印出来。
4. 第二遍打包到最后写不出文件：`--out` 给的目录不存在，脚本没先建。改成先建。
5. 第三遍全过，但看输出时发现 apt 报了三条英文警告（临时目录 `_apt` 账号进不去、软件包索引的 `Release` 没有日期）。小白会被吓到，改成临时目录给 `_apt` 能进、`Release` 写上日期，虚拟机脚本加一条「apt 没报警告」；第四遍 29 处全对。
