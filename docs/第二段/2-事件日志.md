# 第二段第 2 步：事件日志

2026-11-18。代码 `kernel/journal.py`，测试 `tests/unit/test_journal.py`。原型是 S6 的 `journal.py`、第一段 W21 的 `release.py`、W17 的 `batch.py`。

## 做了什么

- 日志在单独的分支 `sop/journal` 上。写的时候不检出：直接造一个提交接在远程最新的后面，不强制推送，被抢先就取回重来（S6）。
- **一个进程只有一个写入线程**（8.2，v0.9）。哪一步要写事件，就把事件交给它，**等推上去了才返回**；同一时刻排着的几批合成一个提交、一次推送。
- 文件放法：`events/project/…`、`events/feature/<功能>/…`（工单的事件放在它的功能下面）、`releases/<归属>/<路径的散列>/<序号>.json`、`names/<名字>.json`。回放只读项目级和当前功能这两个目录。
- 放行事件的序号由写入线程在生成提交时，按日志里同一归属、同一路径现有的最大序号加一；同一批里有两条也依次加。
- **归属名登记成一个文件**。名字用过了，文件已经在日志里，这一项就被拒（`NameTaken`），同一批里别的项照常写。两个进程同时抢同一个名字，只有一个能成，因为推送不强制，后到的取回后会看见文件已经在了。
- 事件种类：7 种步骤事件（开始、完成、失败、跳过、人的确认、重新打开、放弃），加上登记、放行、记录（`note`）。「记录」是开工时用户同意加的，用来放指标、额度报错、花费提醒、绕开说明，不影响位置。
- 断网：取不回远程就报「取不到远程的事件日志，流程停下（不在本地攒着）」。
- 测试用的开关 `SOP_TEST_DIE_BEFORE_PUSH=N`：第 N 次推送之前进程直接退出，模拟 `sop` 被强制结束。

## 没做的

- 往真的 GitHub 写的用时：第 2a 期在真仓库上量（W17）。复用 SSH 连接的设置已经写进 `gitx.py`，本机测试用的是本地目录当远程，用不上 SSH。

## 自己出的错

- 登记名字时调用方传的 `kind=` 和内部区分「事件、放行、名字」的字段同名，被盖掉了。内部字段改名成 `_item`。
- 几个进程同时更新本机同一个远程跟踪指针时，Git 报「incorrect old value」。原来只把另外两种报错当作本机抢占，这一种被当成断网，流程就停了。已加上。
- 推送失败时我按报错文字猜是不是「被别人抢先」，猜得不准（本机当远程时两个推送同时抢一个指针，报的是另一种文字），三个进程同时写时偶尔误报断网。改成不猜：推送失败就重新取回，取不回才算断网，取回了就重来。改完连跑 6 次都过。
