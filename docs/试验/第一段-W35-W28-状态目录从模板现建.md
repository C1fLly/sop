# 第一段 W35、W28：AI 工具的状态目录按会话从模板现建；对话窗口首次启动的几屏怎么过

状态：已完成（2026-11-18），只试了 Claude Code。模板里写 5 项设置，对话窗口打开就是输入框，一屏英文都不出；前一个会话往状态目录里留东西、后一个会话被它影响，这条路实测存在，从模板现建就断了。

调用了 AI 11 次（含一次对话窗口，一次被服务以 400 拒绝、没有花钱），**记账 0.60 美元**（Claude Code 自己报告的金额；对话窗口那一次 0.09 美元是窗口里记的数，手工记账）。脚本在 `docs/试验/脚本/第一段/W35-W28/`。

Claude Code 试验期间又自己升了一版，现在是 2.1.327。

## 要验证什么

- W28：状态目录每次现建之后，每一次对话步骤都是「第一次启动」。S9 看到第一次启动会先出三屏英文（选配色、安全提示、是否信任这个文件夹，第三屏默认是「不，退出」）。要找出模板里写哪几项设置能让这几屏都不出。
- W35：按会话分、从模板现建之后，前一步写进状态目录的东西，后一步读不到。另外设计书写过：「后面的会话真的会读到前面留下的东西」本身没有实测。
- 顺带看用户说过的「未登录」。

## 怎么做的

- `mkstate.py`：从模板现建一个状态目录，模板只有一个文件 `.claude.json`。
- 对话窗口：照 S9 的做法，用一个模拟终端的小程序在受限环境里打开 Claude Code，记下屏幕上出现过的文字。在受限环境里用「不逐条询问」的方式（设计书 10.2：四个工具在受限环境里都这样运行），这和 S9 当时不同。
- 留东西的三条路，各试一次，每次都和「从模板现建的新状态目录」对照：AI 自己的记忆功能；状态目录里的用户级规则文件 `CLAUDE.md`；状态目录里的设置文件 `settings.json` 里的钩子（「每次会话开始时执行一条命令」）。

## 结果

### W28：首次启动的几屏

| 模板里写了什么 | 打开对话窗口时 |
|---|---|
| 引导已做过（`hasCompletedOnboarding`、`lastOnboardingVersion`）、这个工作目录已信任（`projects.<目录>.hasTrustDialogAccepted`）、不自动升级（`autoUpdates: false`） | 选配色、安全提示、是否信任这个文件夹三屏**都不出了**；但出了另一屏英文：「警告：Claude Code 运行在不逐条询问的模式下……不，退出／是，我接受」，默认选中「不，退出」，直接回车就退出了 |
| 再加一项：这个模式的警告已接受（`bypassPermissionsModeAccepted`） | **一屏都不出**，直接是输入框。打了一句「请只回复两个字：收到」，它回答了。0.09 美元 |

- 这一屏警告 S9 没有碰到，因为 S9 的对话窗口没有用「不逐条询问」的方式。受限环境里要用这个方式，否则小白每隔几步就会被问「允许执行这条命令吗」。
- Claude Code 自己会在状态目录里写一个 `settings.json`，里面有 `skipDangerousModePermissionPrompt: true`，作用相同。模板里写 `.claude.json` 的那一项就够了。
- **「未登录」**：这次整个屏幕的文字里没有「未登录」或「Not logged in」，状态栏上显示的是「API Usage Billing」（按用量付费）。用户 S9 时看到的「未登录」多半是这一类显示；没有复现出原样的字，仍是推测。

所以模板就是这 5 项：

```json
{
 "hasCompletedOnboarding": true,
 "lastOnboardingVersion": "<当前版本>",
 "autoUpdates": false,
 "bypassPermissionsModeAccepted": true,
 "projects": { "<工作目录>": { "hasTrustDialogAccepted": true } }
}
```

这几个设置名是 Claude Code 自己定的、没有公开承诺的，升级后可能变。适配器的 `probe` 要在版本变了之后重试一次「打开对话窗口不出任何一屏」（10.1 的版本核对）。

### W35：前一个会话能不能影响后一个

| 留东西的路 | 前一个会话做了什么 | 沿用同一个状态目录的新会话 | 从模板现建的新会话 |
|---|---|---|---|
| AI 的记忆功能 | 让它「记进长期记忆」：它说记好了，记在 `/Users/claude/.claude/...` | 不知道 | 不知道 |
| 状态目录里的 `CLAUDE.md` | 让它在 `~/.claude/CLAUDE.md` 写一行暗号，确实写进了状态目录 | 不知道（这个文件这次没有被自动读进去） | 不知道 |
| 状态目录里 `settings.json` 的钩子 | 模拟前一个会话往里加了一条「会话开始时执行」的命令 | **执行了**：会话开始时那条命令跑了（它在工作目录里留下了一个记号文件）；钩子要是往会话里加话，这台电脑接的服务直接报 400 拒绝（和 S0 的「不接受自定义系统提示词」是同一回事） | 没执行 |

- 记忆功能这一行要单独说明：给 AI 的说明里写的记忆位置是 `/Users/claude/...`，这台 Linux 电脑上根本没有这个目录。受限环境里它往那儿写，写进的是受限环境里临时的根目录，关掉就没了，**可它仍然回答「记好了」**。这个位置从哪里来，没有追查（多半是服务那一头给的说明），这件事说明 AI 说「做完了」不能信（原则 Y6）。
- 用户级规则文件这一行，这次没有被读进去，原因没有追查。

### 结论

1. **W28 解决（Claude Code）**：模板里写 5 项设置，对话窗口打开就是输入框。
2. **W35 解决（Claude Code）**：前一个会话影响后一个，实测有一条路是真的：在状态目录的设置文件里留一个钩子，后一个会话开始时就会执行它（在受限环境里执行，但它能做的事和 AI 一样多）。从模板现建状态目录，这条路就断了。另外两条路这次没生效，但不靠它们不生效：现建的做法对哪条路都管用。
3. 状态目录用完封存成只读（6.3）仍然要做：钩子就在这个目录里。
4. AI 声称「记好了」而实际没有写成，又一个不能采信自述的例子。
