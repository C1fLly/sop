# 第二段第 3 步：流程定义和回放

2026-11-18。代码 `flows/feature.toml`、`flows/ticket.toml`、`flows/README.md`、`kernel/flowdef.py`、`kernel/replay.py`；测试 `tests/unit/test_replay.py`。

## 做了什么

- 照 7.4、7.5 把功能流程（F1 到 F23）和工单流程（T1 到 T15）写成 TOML。每步按 8.1 写明：执行者、受限环境的放法（6.3 的表）、处理函数或任务包、技能、全新会话还是续接哪一组、执行条件、失败去哪、轮数上限、可改范围、会不会改动已确认的内容。字段说明在 `flows/README.md`。
- 设计书文字里说了、流程表里没有编号的几步，我补了编号，只在流程定义里用：`F7fix`（规划校验不通过，起全新会话改工单，最多 2 轮）、`F9fix`（规划复查有阻断问题时改规划，改完重走 F7、F8、F9）、`F14fix`（F15、F16、F17 不通过时生成修复工单，回 F14）。
- 读取时校验：编号不重复；跳转目标都存在；AI 步骤和受限脚本都写了放法；不认识的字段报错。
- 回放：照 S6 的做法，再补几条：
  - 失败事件可以写明去哪（`route`），例如 T10、T12、T13 发现冲突去 T14；
  - 「最多做几次」（T6 三轮 → T7 → T8）和「最多不通过几次」（T9 打回超过 2 轮 → T8）分开计；
  - **确认过、又没被重新打开的人的确认步骤，回放时直接越过**（8.3：记录不因为文件变了而失效）；
  - T8 做完以后「停下等功能那一级处理」；
  - 重规划时 F14 以「改去 F7」结束；验收卡变了才发重新打开 F10 的事件。

## 结果（15 项测试全部通过；单元测试共 32 项）

顺利做完、修复三轮转深入诊断再转技术决策、复查打回超限、条件跳过、冲突去 T14 再回 T4、确认在被重新打开之前一直有效、被打断、放弃、流程里没有的步骤编号、花费累加、规划校验最多 2 轮、行为验收不通过生成修复工单、原型不满意重做、技术决策之后重规划（验收卡没变不用重新确认、变了要重新确认）：都符合。

## 没做的

- 回放用的必须是项目声明的那个工具包版本的流程定义（W18）：第 7 步做版本机制时接上。

## 自己出的错

- 流程定义一开始用分号把几个赋值写在一行，TOML 不允许，读的时候报错。用小脚本拆成一行一个。
- 「重规划」的测试一开始让 F14 一直挂着「开始」不结束，回放当然判成「被打断」。是测试写错了，改成 F14 以「不通过、改去 F7」结束。
