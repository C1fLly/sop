# 第二段第 4 步：检查库的通用部分、总检查

2026-11-18。代码在 `checks/`，约定写在 `checks/README.md`。

## 做了什么

照 14.1 的约定：每个检查一个目录、一个 `check.py`，只读；退出码 0 通过、1 不通过、2 无法判断（检查自己出错时是 2，不冒充通过）；一行结论加一份 JSON 报告；每个检查带「应通过」「应报错」的样例。

和技术栈档案无关的检查都写了：

| 检查 | 用在 | 要点 |
|---|---|---|
| `scope` 可改范围 | 每个 AI 步骤之后（T4 等） | 看这一步提交了的、没提交的、新文件，**加上被 Git 忽略的文件**；任何层级的 `CLAUDE*.md`、`AGENTS*.md`、`.claude/`、`.agents/`、`.codex/`、`.opencode/`、`.pi/` 新出现或被改了一律越界；被忽略的文件只看 AI 工具会自动读的那几类（构建产物本来就被忽略，不算）；路径不转义 |
| `protected` 受保护路径 | T4、F18 之前的兜底 | 改了的受保护路径，现在的内容必须是本归属最后一条放行的那一份（6.4）。比对逻辑在 `checks/protected/core.py`，GitHub 上的守门检查用同一份 |
| `guard/guard.py` 守门检查 | GitHub 的 `pull_request_target`；本机沙箱里由假的 `gh` 用同样的方式调 | 照 W21 的守门脚本改的：受保护清单从主线 `sop.json` 声明的工具包版本里取；PR 改了 `sop.json` 且有放行时，并入新声明的档案（和新的工具包版本）的清单；先自查「检出的就是主线最新的提交」（第一段结束审查的轻微 2）；出错一律按不通过算 |
| `history` 历史延续 | 每步开始前 | 现场向远程取这条分支，本地必须是它的延续 |
| `result_file` 结果文件 | T4 等 | 9.2 的格式；声称的提交存在，并且是这一步新加的；规划类、复查类步骤不该有提交 |
| `confirmed` 已确认内容 | T4、7.6 的「报告已合入」 | 规格、验收卡、摘要逐字不变；工单文件只许勾选框、状态行、评论区变；T8 之后规格只许「## 技术」那几节变 |
| `f19` GitHub 上的三项 | F19 | 全档、快档在最新的提交上、转正式之后真跑完并成功；守门在最新的提交上真跑完并成功；「跳过」不算 |
| `precheck` 特权侧用之前核对 | 特权侧每次执行 wt、Git、`gh` 之前 | `.shared/hooks` 三个文件和模板一字不差；`.git/config` 和记下的指纹一致；`.git/hooks` 里没有会被执行的钩子；没有「工作目录专用配置」；各工作目录的三个小文件内容对（6.4 第四层，v0.9） |
| `quota_scan` 额度报错 | 每个 AI 步骤之后（W29） | 扫会话日志里「insufficient balance」「余额不足」等字样 |
| `plan_check` 规格、工单、覆盖 | F5（只看规格）、F6、F7 | 规格有用户故事；工单有状态、依赖、覆盖、风险行和验收标准；依赖存在、无环；每条故事都被覆盖 |
| `cards_cover` 验收卡 | F8 | 每张工单一张卡，每条验收标准都有步骤；有大白话摘要 |
| `handoff_exists` 交接文件 | F2、F4a | 交接文件已经搬进 `.scratch/<功能>/` |

另外：
- 路径的写法（`checks/lib.py`）：`**` 任意层级；不带 `/` 的在任何层级的文件名上都算（W21 的规矩，给「检查工具认得的配置文件名」用）；以 `/` 开头的只认根目录（`/sop.json`）。
- 工具包的基础受保护清单 `checks/protected/base.txt`；各档案的清单将来放在 `profiles/<种类>/<名字>/protected.txt`。
- 规划文件的格式定在 `checks/README.md`（工具包的约定）。技能实际产出的样子对不对得上，第 2a 期核对（W25）。
- wt 的模板 `templates/wt/`：照 S9 的模板，准备脚本只链接 `.env`，删除前脚本什么都不做。
- 总检查 `checks/total_check.py`（16.1）：缺「应通过」或「应报错」样例的检查不合格；「应报错」的样例上退出码不是 1 的不合格（是 2「无法判断」也不算报对）。

## 结果

- **总检查：12 个检查，62 个样例，全部符合。**
- 另给总检查本身加了 3 项测试：一个「什么都放过」的检查、一个缺「应报错」样例的检查，都被判不合格；正常的判合格。
- 单元测试共 35 项，全部通过。

和第二段验收标准对得上的样例：
- 可改范围抓得到被 Git 忽略的 `.claude/settings.local.json`（里面写了会话开始时执行的钩子）、被忽略目录里的 `CLAUDE.local.md`、提交进子目录的 `AGENTS.md`、没提交的 `sop.json` 改动；中文路径不误报；被忽略的构建产物不误报。
- F19 三项各造一种「只有这一项没过」：全档只被跳过、快档失败、守门失败；另有全档还在跑、全档或守门不在最新提交上、只有转正式之前的记录。都拦住了。
- 特权侧用之前核对：`post-create` 被加了一行、`.git/config` 被加了 `core.sshCommand`、`.git/hooks/pre-push`、`commondir` 被指到假仓库、工作目录里指向 `.git` 的小文件被改、`config.worktree`、没有记过指纹，都拒绝。

## 没做的

- 和技术栈档案有关的检查（测试数、跳过标记、截图比对的写法、检查工具的配置、契约、界面、架构、红线、迁移、依赖、安全扫描、改动质量、变异测试、重复运行）：要有档案才写得出，第 2a 期。
- 守门检查（`guard.py`）没有自己的样例目录：它要一个 GitHub 的事件和远程，在第 6、8 步由假的 `gh` 真跑它来验（开工时用户同意的做法）。
- 可改范围检查「用一次真实的 AI 调用」那一项：第 9 步。

## 自己出的错

- 「不带 `/` 的在任何层级都算」会让 `sop.json` 连子目录里的同名文件也算受保护。加了「以 `/` 开头只认根目录」。
- 历史延续检查第一版判断祖先关系的那一句绕了两遍，改成只看 Git 的退出码。
- 在 wt 的工作目录里执行 Git 时，必须把仓库写成这个工作目录自己的登记目录（`.git/worktrees/<名字>`），写公共的 `.git` 会用错暂存区。写进约定，后面的处理函数照这个做。
