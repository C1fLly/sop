# 3-47 第 1 期的破坏演练脚本（设计书 16.3）

2026-11-22，主控窗口派的子代理做的。**没动隔离、放行事件、事件日志**：`runner/`、`kernel/`、`checks/`、`templates/` 一行没改，只加了脚本和测试；没碰 Docker、没用 sudo、没碰 GitHub（只用流程沙箱的假远程和假 gh）；**没调用 AI，0 美元**。

## 读到的设计

- 16.3：每一期结束时的两道外部把关之一。「由脚本逐项执行破坏动作（例如把一个测试的预期结果改掉并提交），小白只看结果：屏幕上应当显示检查失败。这是小白对工具包本身的行为验收。」16.3 只举了这一个例子。
- 任务清单：例如改掉一个测试的预期结果并提交、改一个受保护文件不放行、改 wt 钩子；本机跑一遍，全部拦住。脚本放 `tests/drill.py`，3-44 的 `sop self check --isolation` 按这个位置找、在开发目录里用 python3 执行、退出码 0 才算全部拦住。
- 第 19 节第三段的验收标准里没有破坏演练的条目（「破坏演练在整期结束时做」写在第 1 期分段那一段，3-49 用）。16.2 的隔离自检里写着「借专用 Docker 改 `.shared/hooks`、`.git/config`、`.git/hooks` 之后特权侧用之前核对必须发现并拒绝」，6.4 第四层列了特权侧核对的四样，演练照这几样补全了「改 wt 钩子」那一类。

### `python3 tests/drill.py [--list] [--only a,b] [--keep]`

14 项，每一项都是：**没破坏时检查通过 → 破坏 → 检查必须失败，而且失败输出里同一行写着这次破坏的标记（不是别的毛病让它失败）→ 还原 → 检查又通过**。三种结果：拦住了 / 没拦住 / 演不下去（例如要改的那一行工具包里已经没有了、没破坏时就没过、还原后没回到通过）；后两种都算没过。全部拦住退出码 0，否则 1，拒绝执行或用法不对 2。

| 项 | 破坏动作 | 应当拦住它的检查 |
|---|---|---|
| test-expect | 改掉一个单元测试的预期结果并提交（运行时目录权限 700 改成 755） | 单元测试 |
| test-skip | 把一个单元测试标成跳过并提交 | 单元测试（带 `--no-skip`，和 GitHub 上一样） |
| ci-weaken | 把 `check.yml` 里单元测试那道检查的 `--no-skip` 去掉并提交 | 单元测试（核对检查流程的 `test_ci_workflow`） |
| sample-expect | 把 `checks/scope` 的一个「应报错」样例改标成「应通过」并提交 | 总检查 |
| skill-edit | 在技能副本的一个文件末尾加一个换行并提交 | 总检查（技能副本逐字比） |
| doc-path | README 里写一个不存在的文件路径并提交 | 文档检查 |
| guard-rules | 在 PR 上改规范文件 `docs/standards/rules.md`，没有放行 | 守门检查 |
| guard-checkdef | 在 PR 上把项目检查的定义 `.github/workflows/sop-check.yml` 改成永远通过，没有放行 | 守门检查 |
| wt-hook | 改 wt 钩子 `.shared/hooks/post-create` | 特权侧用之前核对（`wt new` 一条都不执行、目录没建出来） |
| git-config | 往项目的 `.git/config` 加 `core.fsmonitor` | 同上 |
| git-hook | 在 `.git/hooks/` 放一个会被执行的 `post-checkout` | 同上 |
| worktree-config | 给一个工作目录放 `config.worktree` | 同上 |
| gitfile | 把一个工作目录里指向 `.git` 的小文件改指到别处 | 同上 |
| scope | AI 在一步里顺手改了可改范围外的文件并提交 | 可改范围检查 |

**安全**（主控点名的第一条）：

- 两层。外层（在开发目录里执行的那一份）先在 `/tmp` 下现建 `sop-drill-<随机>/`，主目录、临时目录（`TMPDIR`）、`SOP_TEST_TMP` 都指进去，去掉 `ANTHROPIC_`、`GH_`、`GITHUB_`、`DOCKER_`、`SOP_`、`GIT_`、SSH 代理一类的变量，PATH 去掉本机主目录下的目录，换进去之后**断言当前目录和主目录都在这个现场里、现场在 `/tmp` 下、和本机真的主目录不沾边**，不是就拒绝执行（退出码 2）。然后只读开发目录：`GIT_OPTIONAL_LOCKS=0 git ls-files -co --exclude-standard`（被跟踪的加没被忽略的新文件，和 `sop self check` 看的改动一致）列文件、读内容，拷到现场的 `toolkit/`，在那里 `git init` 提交成「演练起点」；wt 从它现在的位置 `git clone --no-local` 只读克隆一份到现场；最后执行**现场副本里的** `tests/drill.py --inner`。里层再断言一遍（还要求自己就是现场里那一份），之后导入的工具包代码、被破坏的文件都是副本里的。每个写文件、改名、提交的动作之前再核对目标在现场里（经链接指到外面也不行）。演完删现场（`--keep` 留着）。
- 项目那几项用流程沙箱的「世界」（`tests/sandbox/world.py`）：本机裸仓库当 GitHub、假的 gh、经 wt 接入层（`kernel/wtx.py`）用克隆出来的 wt 建的项目。守门检查是假 gh 照 GitHub 上的守门流程真跑主线 `sop.json` 声明的那个工具包版本（副本）里的 `checks/guard/guard.py`。
- 不调 AI、不碰 Docker；开发目录、`~/tools/wt`、本机主目录、真 GitHub 都不写。

**和主控说法的两处出入（自己定的，可否决）**：

1. 「脚本开头先断言当前目录和主目录在 /tmp 下」：`sop self check` 是在开发目录里执行它的，一开头当前目录必然是开发目录。所以做成：开头先建现场、换进去、立刻断言，**在拷副本和任何破坏之前**；里层开头再断言一遍。
2. 「按 Git 记录的内容拷」：拷的是 Git 记着的文件清单在工作区里的内容（含没提交的改动），不是 `git archive HEAD`。理由：`sop self check` 查的是相对起点的全部改动（含没提交的），演练要演的就是改过的那一份检查。开发目录照样只读。

**单元测试那三项只跑被改的那一个测试文件**（`run_all.py --no-skip --pattern test_basics.py unit`）：全跑一遍单元测试要 2 分半，每项跑三遍就是 7 分半；判法和全跑一样，全跑由 `sop self check` 的四个检查做。

- **隔离自检里的那些（受限侧读凭据、写工具包、借专用 Docker 改文件）**：那是隔离自检本身，`sop self check --isolation` 另跑；专用 Docker 那份会起 Docker，没在本机跑。

## 自己出的错

1. ci-weaken 第一版「没拦住」，是演练脚本的毛病：`check.yml` 第 4 行注释里也写着同一条命令，替换只换了注释那一处。改成要改的那一处必须正好一处（带上 `run:`），不是就「演不下去」。
2. doc-path 第一版想在 README 第一个换行后插一行，换行有 39 处，被上一条新规矩挡下（「演不下去」）；改成在末尾加一行。
3. test-skip 第一版用 `@unittest.skip`，可 `test_basics.py` 没导入 `unittest`，测试文件一导入就崩；演练如实报「失败了，但不是因为这次破坏」，改成在测试里第一句 `self.skipTest`。
4. 反着试「去掉技能副本检查」第一、二版的改法被别的关先拦下（见上），不是演练的毛病，改了改法。
5. 第一遍的判法只要求标记出现在输出里任何地方，太松（「不符合」和「scope/pass-」可能来自两个不同的样例）；改成同一行要同时写着全部标记。
