# 3-19 验收：两个项目同时开

2026-11-20。主控窗口派的子代理做的。没调用 AI，没花钱。用 sudo、装 Docker、起停专用 Docker、建用户级服务和计时器都只在虚拟机里做（`tests/vm/vm.sh new`，全新的 `one` 底盘；用户 2026-11-19 已答应第三段在虚拟机里做这些）。本机只跑了单元测试和全部自测：没用 sudo，没建任何 systemd 用户服务、计时器或分组，没碰 `~/tools/docker` 和它的数据，没碰 127.0.0.1:8765 那个网页服务。

**动了隔离吗**：没有。换根脚本、视野、受限环境里放什么都没改。改的只是闲了停的计时器的**名字**（见下）。

## 验出来的问题（已改）

**两个项目的登记文件会撞名。** 3-18 给闲了停的计时器和它触发的服务起名 `sop-docker-<项目名>-idle.timer`、`sop-docker-<项目名>-idle.service`。项目名里允许「-」，所以项目 `app` 的 `sop-docker-app-idle.service`（闲了停的那个一次性服务）和项目 `app-idle` 的专用 Docker 服务 `sop-docker-app-idle.service` 是**同一个名字**：装一个会把另一个的登记文件盖掉，结果可能是 `app-idle` 的专用 Docker 被换成「每分钟跑一次闲了停的小脚本」，或者 `app` 的计时器去启动 `app-idle` 的专用 Docker。是写虚拟机脚本前读代码、在本机 `render()` 两个名字比了一下发现的，没在虚拟机里真撞出来。

改法：闲了停的两份改名 `sop-idle-<项目名>.timer`、`sop-idle-<项目名>.service`。四种名字的前缀 `sop-docker-`、`sop-idle-`、`sop-`（只有分组，后缀 `.slice`）各不相同，项目名又各不相同，所以任意两个项目的八份不会有重名（`sop-idle-x` 的「-」后面跟的是项目名，不会和 `sop-docker-…` 混）。只改了 `runner/docker/service.py` 的 `idle_name()` 一行和说明。还没有真用户装过 3-18 的版本（第三段在开发），不用管旧名字的迁移。

加了一项单元测试（`test_names_never_collide_across_projects`）：12 个容易撞的项目名（`app`、`app-idle`、`idle`、`idle-app`、`docker`、`docker-app`、`my-app-idle`……）生成的登记文件名两两不同；装 `app` 再装 `app-idle`，`app` 的四份一字不变；删 `app-idle`，`app` 的四份一字不变。把名字改回旧的，这一项不过（报 `app-idle 和 app 都有 sop-docker-app-idle.service`），改了之后过。

## 做了什么

- `runner/docker/service.py`：上面的改名。
- `tests/unit/test_docker_service.py`：几处名字跟着改，加上面那一项。
- `tests/vm/twoproj.sh`、`tests/vm/twoproj-guest.sh`（新）：两个项目同时开的验收，分两段，中间重启虚拟机。**两个项目故意叫 `app` 和 `app-idle`**（就是会撞名的那一对），上限故意不同（300M、400M）。闲的时间用 120 秒（计时器每分钟看一次，和正式的一样）。
- `tests/vm/dockeridle-guest.sh`、`tests/vm/dockersvc-guest.sh`：里面写死的计时器名跟着改。
- README 的 `tests/vm/` 一行补了 `twoproj.sh`。

## 结果

### 全部自测

做之前（主控窗口跑的）单元测试 210 项、流程沙箱 24 个剧本、总检查 62 个样例全过；做之后**单元测试 211 项、流程沙箱 24 个剧本、总检查 62 个样例，全部通过**。

### 虚拟机（全新的 Ubuntu 26.04.1，内核 7.0，4 核 3.9 GB，`one` 底盘）

`tests/vm/twoproj.sh d19`，日志 `/tmp/sop-3-19/vm1.log`（本机内存盘）。**全部对**：

| 验的 | 结果 |
|---|---|
| 两个项目的 `sop` 同时分配端口（各 8 个工作目录），另有一个别的程序占着 20003（登记里没有） | 各 8 组、每组连续 10 个、没有一个端口分了两次、让开了 20003；`app` 的 w0 是 20010，`app-idle` 的是 20020 |
| 两个 `sop` 同时要用专用 Docker | 两个同时起来（2.0 秒），各自的计时器跟着起；登记文件一共 8 份、名字不撞；两个闲了停的服务各停各的；两个分组各是各的上限（300M、400M），`app-idle` 的分组没挂到 `app` 下面 |
| 两个专用 Docker 里起**同名**的容器 `web`、同名的数据卷 `data`、同名的网络 `net`，各映射自己分到的端口 | 20010 答「我是app」、20020 答「我是app-idle」；各自只看得到自己那一个 `web`，是两个不同的容器，各落在自己项目的分组里 |
| `app-idle` 想占 `app` 分到的端口 | 起不来（退出码 125），`app` 的照常 |
| 一个项目的专用 Docker 挂另一个项目的根、另一个项目的数据目录 | 都看不到（换根之后的视野里没有）；自己的照常 |
| 删一个项目的同名容器、同名数据卷 | 另一个的同名容器还在跑、同名卷还在 |
| `app` 超内存三次 | 每次被杀（分组记 3 次）；`app` 的专用 Docker 自己没事；`app-idle` 的专用 Docker 没换、`web` 还在答话 |
| `app` 用完放开、`app-idle` 还在用 | `app` 放开后 157 秒停了、计时器跟着停；`app-idle` 一直开着（主进程没换）。`app` 再要用时起来，`web` 自己起来（`unless-stopped`），还是 20010、还是自己的数据 |
| 走流程命令的那条路（两个 `Engine.docker()`），在受限环境（bubblewrap）里经各自的通道 | 各自只看到自己的 `web`，读到自己的数据卷 |
| **两个专用 Docker 都开着时重启虚拟机** | 两个都没自己起来（`inactive`），计时器也没起；8 份登记文件都在、没变；端口登记都在，同一个工作目录再要还是原来那组；这时 20010、20020 没人答话 |

| 收拾 | 两个都停了、8 份登记文件都删了 |

这和问题 1 的答案一致：**重启后不自己起来，下次 `sop` 要用时自动起来，镜像和数据都在**。

第一遍里「8 份登记文件内容没变」那一项是用 `md5sum -c` 核的，日志里有一句 `md5sum: WARNING: 1 line is improperly formatted`：分组名 `sop-app\x2didle.slice` 里有反斜杠，`md5sum` 会把这一行写成另一种格式、`-c` 时跳过它，所以那一项其实只核了 7 份。改成原样拷一份、逐字节比，再跑一遍（见下）。

## 没做的

- **真等 15 分钟**没演，用的 120 秒（和 3-18 一样）。
- 两个项目都是 `runner/selftest.make_fixture` 造的假项目（和 wt 一样的结构），不是 `sop project new` 建的（那是 3-23 之后的事）；「同时运行」是两个 `use` 进程和两个 `Engine` 并排拿着专用 Docker，不是两个完整的 `sop` 跑流程（流程沙箱的假档案没有 `[docker]` 段，真的档案是第 2a 期）。
- 容器名：设计书 5.5 定的是「Compose 项目名为 `<项目名>-<目录名小写>`，不写死容器名」。这次验的是更苛刻的情况：两个项目连容器名都一样也互不影响（每个项目一个专用 Docker，名字空间本来就是分开的）。Compose 本身没装（第 2a 期）。
- 超内存时同项目别的容器跟着停（3-55），不在这次范围；日志里 `app` 的 `web` 这次三次都没跟着停，只是碰巧。
- 两个项目分到的端口在本机所有程序之间是唯一的（登记加「试一下有没有人占」），但受限环境没隔开网络（6.5 已写）：一个项目的代码连得上另一个项目映射出来的端口。这是已知的，不在这次范围。

## 自己出的错

1. 第一遍虚拟机脚本用 `md5sum -c` 核登记文件没变，分组名里的反斜杠让它跳过了一份（见上）。看日志里那句警告才发现，改成逐字节比后重跑。
2. 写端口那一步时初稿用 `wait %2 %3` 等后台任务，写法靠不住（任务号和后台起的别的进程会混），跑之前改成记下进程号再等。
3. 第二遍同时开三台时，命令写成 `vm.sh new d19c && (twoproj …) & (dockersvc …) & (dockeridle d19c …) &`：`&&` 和它后面那一段一起被放到后台，`dockeridle.sh` 在 `d19c` 建好之前就开始了，报「没有叫 d19c 的虚拟机」退出。没跑起来、没有结论，`d19c` 建好后单独重跑了一遍。
