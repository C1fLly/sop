# 3-64 把关脚本「复查有问题」在真跑全部自测的副本上走一遍

2026-11-22，主控窗口派的子代理做的。3-44 拆出来的。**没动隔离、放行事件、事件日志**（正式代码一行没改，只改了手动跑的演示脚本）；没碰 Docker、GitHub，没用 sudo；**没调用真 AI，0 美元**（复查用的是假 claude）。

## 要验的

3-44 的演示脚本 `tests/selfcheck_demo.py` 在 /tmp 副本上真跑全部自测造了 7 种情形，「复查有问题」那种一直没验到：前几遍演示脚本自己有毛病，单元测试先没过，复查没轮到；第六遍跑完「全好」后主控叫停。另外那几遍「卡在哪」前面都多带了一个「单元测试没过」，所以要再确认卡在哪只有该有的那一样。

主控定了上限：一共最多真跑 3 份（一份七八分钟，同一时刻只跑一份）。

## 跑之前核对演示脚本

3-44 那几遍的毛病，逐条对着现在的代码看：

1. **git 设置带进自测**：`ID`（`GIT_CONFIG_GLOBAL=/dev/null`、作者名等）只给造副本的 `g()` 用。把关的环境是 `os.environ` 去掉 `ANTHROPIC_`、`CLAUDE` 开头的，再换 `HOME`、`SOP_HOME`、`SOP_RUNTIME_DIR`、`SOP_TEST_TMP`。已经修好了。
2. **中文目录名**：副本目录叫 `c<序号>`。已经修好了。
3. **路径太长**：`/tmp/sscd/c<序号>`。已经修好了。
4. **几份同时跑**：脚本本来就一份一份跑；这次三份也一份跑完再起下一份。每份开跑前用 `pgrep` 看过，本机没有别的 `tests/run_all.py` 在跑。
5. **自测里的测试和把关拿同一把锁**：`tests/unit/test_selfcheck.py` 的 `setUp` 已经把 `S.LOCK` 换成测试自己的了。已经修好了。

从 3-44 到现在，正式代码没有再改过（3-44 之后只有一个总账提交）。

**改了演示脚本一处**：原来只看最后一句里有没有那几个字（比如「复查有问题」），前面多带一个「单元测试没过」也判「对」，3-44 那几遍的毛病它看不出来。现在多核对一样：`report.json` 里没过的那几项（按顺序）必须**正好**是预期的。新加了一张表 `STUCK`，7 种情形各写了「卡在哪」应当是哪几样；「文档检查失败」应当是总检查、文档检查两样，原因见 3-44 记录。
